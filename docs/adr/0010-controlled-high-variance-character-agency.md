# 受控的高随机：角色决定行为，系统只守权威边界

Girl-Agent 将动机、态度、情绪表达、措辞、消息节奏、主动联系、沉默和能力使用定义为
Character Decision，由角色模型结合完整且有来源的当前情境自行选择。系统只提供 World
事实、记忆、关系、Affect、生活状态、可用能力及其后果，并确定性执行事实来源、隐私与
同意、安全与法律、Action 授权、effect-once、CAS、回执和重放等 Hard Invariant。选择
这一边界，是因为正则、关键词、固定话术、动机枚举、表达矩阵和随机 `act/hold` 会把
“角色的选择”悄悄变成“程序替她选择”，既降低自然度，也把局部规则错误放大成长期失声。

## Consequences

随机性用于产生机会、时机、注意力和环境变化，不直接产生行为结论。结构校验失败时，
系统把可用能力、证据和精确失败原因反馈给同一角色模型进行一次受约束重选；仍失败时
记录技术失败并走可观察、可退避的重试，不使用本地角色话术伪造成功。任何新增的软规则
都必须证明自己只是 Advisory；若它能在模型选择前决定角色该说什么、何时说或是否说，
就属于越权。

主、备供应商均不可用时，不得由本地模板伪造角色话术。部署可以显式安装一个默认关闭的
独立角色恢复模型，但它仍只能读取同一 pinned World Context，任何当前、过去或共同历史
陈述都必须走完整来源闭包，并以独立模型身份进入审计。可靠性测试期间关闭该能力，使
双路失败继续表现为可观察的技术失败；启用也不能改变 Action、CAS、回执或重放边界。

角色暂停、恢复、修改或结束计划后，旧执行头不能继续授权尚未发生的完整尝试结果。
这属于来源权限撤回，不是系统替角色选择新行动；撤回须有精确已接受计划头、原程序
与回执证明，并保留已发生事实和原始审计。独立外部事件不因角色自己的计划变化而停。

已经完成的尝试可以沿原有完成事件入口单独生成回溯结果。它必须绑定原完成事件、最后一次执行和完成之后的原请求版本；这不恢复旧活动程序继续发布未来结果的权限，也不把生命周期结束解释为成功。

技术清理不构成新的故事原因。撤回未实现尝试的权限仍须阻止原事件及其依赖，
但不把该回执解释成外部活动取消，也不为它单独重新询问命运作者。原角色选择、
实际结果和持续后果仍沿原通知游标进入故事调度；独立事件照常推进。

新角色请求把已提供的可引用来源和具体效果允许的来源分别钉入输出契约。
纠错指出原提交字段及位置，不猜测替换引用、不重选行为；Recall 与恢复沿用
原请求版本。审核可省去已精确绑定的协议身份和完整字段的重复解释，但所有
自由文本、事实主张、权限、证据及覆盖义务不变；不确定的字段仍须给出原因。

私有命运草稿不是事实授权。可执行环境文本、客观规划及其课表槽位在取得事实发布权限前，
复用原来源审核，核对既往行动的来源与最早开放时间；未来安排不证明参与、付款或已完成。
原始审核回执必须绑定精确文本、请求证据与模型身份，重启不得重复付费询问同一次未知结果。
这只限定事实与角色作者权限，不评价题材、故事质量或替角色选择行为。历史错误原样保留，
修复后仍须重新取得真实无人值守验收证据。

固定角色背景可复用既有 CompanionIdentityFrame 的精确作用域来源，供命运作者及其来源审核
共同读取；仅含名称、别名和 canonical facts，不能把风格示例、日常脚本或整段记忆提升为事实。
该来源不证明新行动或既往经历，已接受世界后果仍决定后续变化，不能用固定背景撤销真实后果。
旧付费请求保持原钉住的来源，新配置变化需重新取得未来发布权限，不改写原审计或历史。

命运作者的可用指令必须与事实发布权限一致：未经来源审核或身份来源已变的旧私有未来，
不能以“已经通过权限检查”为理由提供 keep。允许提交完整候选取得核验，合格且兼容的
未来仍可自主保留。生成端需预先知道文本最早开放时点，时长不能冒充已经经过的时间。
这是技术权限和输入契约，不强制故事改变或替角色决定行为；旧付费请求保持原输入。

角色自主修改计划后，结果生成沿原修改决策的审计与意图来源，不得误按另一个作者的提案
解析而丢失因果链。新请求显式启用相应来源版本，旧付费请求按原版本恢复。
已付费命运内容的执行不是一次新的生活创作，不能挤掉或推迟原本到期的模型考虑；私有
大纲修订失败也不能冒充角色的无事可做。独立作者仍可选择 no_op，失败仍须记录并重试。

周期活动模板的事实发布时间绑定每次实例的 starts_at；缺少单一绝对时间不等于当前已发生。
新请求须固定该符号时间契约，旧付费请求继续按原契约读取；开课时仍不能预先宣称整堂课已结束。
发送开始前若遇到无关账本 CAS 竞争，只能在同一次调用的精确未过期租约仍成立时重读并重检权限；
不得靠 owner 名相同认领其他尝试，也不能重复已开始的外部交付。

普通外部世界机会不自动继承历史角色行动的执行授权；已选行动的后果仍须从专用任务绑定原执行与原角色审计。
已登记 NPC 的身份须由原登记事件与不可变描述证明，不能把能力说明直接升级为事实。该来源只说明登记时的
身份背景，不证明当前到场、同意、动作或额外旧关系，亦不能推翻之后已接受的关系／状态变化。来源隐私仍随
每个实际发布字段约束，审核和发布复用同一细节隐私规则。技术性来源损坏不交给角色作者改剧情来修。

跨 epoch 保留的人物定义，可由当前账本已提交且可引用的 WorldStarted.continuity 中那一项精确证明；
须核对人物 ID、身份内容引用、原登记定位、事件／提交与不可变字节。旧登记定位不等于当前事件存在，
不能补造旧登记事件，也不能将未经验证的头缓存当作该证明。

结构化输出的物理载体与提示、纠错历史必须一致。JSON 文本不能伪装成原生工具调用。
旧付费请求、输出和审核保持原样；若其首次来源纠错尚未付费，新纠错可以显式声明
当前文本载体，并绑定原请求、原 schema 与拒绝原文的 hash。该声明只替换此次提交方式，
不增加事实或角色权限、不修补角色文本，仍由同一作者通过原来源审核与完整校验。
