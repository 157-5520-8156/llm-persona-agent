# 0026: Objective planning and timed external event details

Status: implemented in the candidate worktree; production qualification is separate.

A class timetable is an external arrangement, whereas attending class is a character
choice and a completed class needs actual outcome authority. Preparing a story scene
also cannot make its future prose available as current experience.

Reuse World Outlook to publish bounded `WorldPlanningDraft` documents through the
existing occurrence, settlement and content publication path (`world-consequence.3`).
Keep subjective Plans with CharacterInterior. Weekly recurrence is expanded only for
the requested window. Revisions name the exact prior publication. Exceptions preserve
the original instance identity; cancelling a moved instance retains its affected window.
Past instances cannot be moved back into the future. Nothing creates attendance.

Reuse the existing LifeDevelopment World Author and both source reviews for a private
`event_details` programme at an active activity or an Outlook scene's start. The exact
raw author result remains audited; ordinary result content contains none of the future
steps. The occurrence stores a bounded authority index, not future prose. At each due
step, verify original bytes, review binding, current source, declared dependency tokens,
privacy and any selected-outcome condition. Publish through the existing Outlook
executor. The clock does not call a model or author a protagonist response.

Pause, abandonment, changed dependencies and elapsed windows stop unopened steps.
An interrupted commit resumes the same identity. Only the owning executor activates
prepared children, so generic clock recovery cannot bypass those checks. Retain failed
attempts; retry technical failures without reauthoring. Missed content remains incomplete.
The scheduler queries running work and maps overdue backlog to the next clock; completed
history does not add one query per programme.

World Author prompts use the existing task capabilities to show only applicable guidance.
A bound event does not draw a new occasion or select an independent scene. Exact duplicate
capability mirrors may reference the complete original manifest; presentation may omit
schema annotations and unoffered branches. Canonical validation and native tool contracts
remain unchanged, and recovery retains the original stored request. Correction guidance
must expose legal alternatives without prescribing the author or character's decisions.

The authenticated weekly dashboard reads published periods/classes, actual Experiences,
subjective Plans, realized World events and private Outlook windows at one cursor.
Known arrangements do not become history just because their date passed. Reading the
calendar performs no model calls, ticks or writes. Text reads and recurrence expansion
have explicit bounds; incomplete coverage is displayed.

Fate authors continuing external situations, people, difficulties and consequences.
Actual user help may matter, but seeking help, gratitude, intimacy, silence and growth
remain character decisions. There is no required rescue plot or affection reward.

Recurrence identity and bounded instance expansion follow the distinction in
[RFC 5545](https://www.rfc-editor.org/rfc/rfc5545#section-3.8.4.4) and the
[Google Calendar recurring-event model](https://developers.google.com/workspace/calendar/api/guides/recurringevents).
These references inform representation, not evidence of this project's correctness.

Validation: focused tests cover the public producer-to-chat/calendar path, independent
claim closure, early/late visibility, selected branches, pause, interruption, retry,
expiry, privacy, original-body corruption, forged operation keys, backlog and bounded
history reads. Fixture reviewer verdicts do not establish real-model semantic quality.
