# Native fictional source and explicit compiled admission

User-approved direction: structured story source -> deterministic compilation -> character-owned
retention, with interwoven stories and sustained consequences. This decision implements the native
prehistory path; it does not disable live action/source review or the legacy reviewed archive path.

`native-story-source.1` is an operator-authorized fictional manuscript. Its author declares stable
occurrence IDs, multiple story-line memberships, full scene blocks, owner knowledge, private historical
interpretations, reported information, explicit relationships and unresolved matters. World-only
blocks are valid source and never become owner memory. The author creates semantics; code does not
infer motifs, motives, causal links or character behaviour.

Compilation is pure over a frozen source, authoring brief and archive ID. Recompiling those inputs
produces identical records and receipt. The receipt includes exact source/context JSON and hashes,
compiler version and source-authored time; it makes no claim of an independent model review or of
semantic infallibility. Native declared links can use exact endpoint references without duplicating
prose; the compiler binds their endpoint excerpts. Optional supplied quotations must remain exact.
A shared source scene may have multiple private readings, but one occurrence identity; structural
shared-scene adjacency does not infer a psychological cause.

The compiler checks owner, historical identities, participant references, occurrence/knowledge
bounds, private owners, declared graph endpoints and unchanged prior-record references. Reported
knowledge names its informant; unknown acquisition remains a conservative bounded interval and is
labelled as imprecise. It does not become an exact event or acquisition date. Later information
cannot be backdated as already known, and runtime-period events cannot be fabricated as prehistory.
Existing accepted records remain unchanged. Native records use existing rich archive/read contracts.

`character-prehistory-acceptance.2` carries a compilation receipt with no `review`; `.1` still requires
its actual review. Both use the existing archive/record event family and authoritative ledger. Native
records are emitted by `world-v2:compiled-prehistory`. Reducers and projection validation reproduce
the manifest from the source receipt and retain exact receipt/hash/time/actor closure. The ledger
basis is checked inside the existing serialized commit sequence; import is atomic and effect-once.
Old `.1` event/record serialized bytes are unchanged because new absent fields are omitted.

Memory and Recall continue to require active retention, current source proofs, actor/privacy and time
eligibility. World-only source, full compilation context and author-facing story-line labels do not
enter the reader. Native initialization calls its source compiled, not independently reviewed;
legacy initialization opportunity bytes keep their old shape. Native publication does not create
current NPCs, messages, plans or role choices.

The first production candidate is a book covering birth through the twentieth birthday, referencing
the existing accepted life without overwriting it and retaining later legacy material as a separate
bridge. Content is authored in bounded batches with exact capture recovery and budget accounting.
An independent model review is not a mandatory batch stage. Source-author corrections and explicit
editor revisions remain attributable; raw failed responses must not be rewritten as successes.

Current limits: this is fictional pre-start history and a compiler, not a guarantee that an LLM will
never write a semantically wrong scene. Source inspection and development oracles measure content
quality. Cross-actor runtime identity handoff and a rolling future-life author are separate work.
