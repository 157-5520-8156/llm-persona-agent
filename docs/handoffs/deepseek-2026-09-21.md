## 3. 不可丢失的设计边界

- CharacterInterior 是角色语义决定的作者。代码管理事实来源、主体/字段权限、外部 Action 授权、CAS、effect-once、回执和重放。
- 不用关键词、固定话术、随机 act/hold、情绪—表达矩阵替角色决定行为。
- 当前感受和联想可由本轮形成；既往/持续的感受、实际行动、已发生经历需要相应记录。主观表达里夹带的外部事实仍须有依据。
- 计划只证明意图；Started/Completed 只证明生命周期。环境里有叶堆，不证明角色站在叶堆旁、看见了它或走到那里。旧聊天只证明说过，不能自动升级成真实经历。
- 不因 `world_claims=[]` 就认为正文没有事实。不把缺少记录解释成“确定没发生”，也不靠模糊措辞补故事。
- 模型结果无效时保留已有一次同角色受约束重选；再失败应记录技术失败。不能用本地模板或技术异常伪装角色沉默/成功。
- 保持历史请求和已接受回执可按原语义验证。兼容性需要隔离，但不应为每个措辞问题继续增加平行协议。
- 开发、真实 provider 测试均使用隔离状态与 CaptureDelivery；没有新的真实 QQ 外发、生产数据库改写或部署授权。
