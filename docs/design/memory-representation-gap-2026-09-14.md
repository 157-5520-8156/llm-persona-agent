# 历史记忆压缩的未完成链（2026-09-14）

状态：待实现。此文不代表压缩功能已可用，也不替代真实长期验收。

当前 `MemoryCandidateValues` 有 `summary_ref` 和 `summary_payload_hash`；
`memory_reducers.py` 能接受绑定来源、保持隐私和 CAS 的 `compress` 修订。
但这些字段还没有对应的压缩文本读写链。`memory_retrieval.py` 对经过压缩或
替换摘要的历史候选返回 `content_unavailable`，避免回退到原始档案而恢复丢失细节。
`test_compression_cannot_restore_discarded_details_from_full_archive` 验证了此边界。
这说明状态迁移存在，而可用的压缩表示尚不存在。

后续实现须贯通以下链条，不应仅删除读取保护：

1. 为当前有效的记忆表示保存不可变内容，绑定候选修订、来源证明、原表示与
   内容哈希。原档案用于来源审计，不因候选仍有源引用就自动成为角色的可读内容。
2. 由同一 CharacterInterior 决定保留哪些内容以及如何概括。机会调度与预算属于
   系统；摘要、保留理由和是否压缩属于角色。不能用截断文本假装完成模型的压缩决定。
3. 摘要以当前可读表示为输入，保留历史时间、主体、隐私和事实/主观解读的区别。
   新增事实不能因为被写进摘要而获得权威；不合法的模型结果走既有一次受约束重选。
4. 检索、角色上下文和来源审核都读取同一个有效表示，证明同时包含该表示的
   接受事件与原来源。旧版本须能冷重放，但新游标不能通过旧索引、旧候选镜像或
   原档案恢复已丢弃的细节。再次获知某件事需要新的有效来源和保留决定。
5. 验证接受→压缩→检索→再压缩→遗忘→重启的完整链，包含并发修订、缺失/篡改
   内容、跨角色、被撤销来源、模型概括引入新经历和低预算拒绝。
   模拟角色选择只验证链条；长期自然回忆和概括质量需要后续有界真实调用。

同样检查运行后 Fact/Experience 记忆的表示生命周期，避免只在历史档案上实现遗忘。
现有 source-review 误放行仍是事实性摘要的真实验收阻断，不能把结构校验或本地测试
报告为其已解决。本轮未新增压缩调度或付费模型调用。
