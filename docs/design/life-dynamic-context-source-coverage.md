# Durable Life context in the existing focused origin review

`dynamic_life_direction` is a World Author event-impact capability. Once the
exact outcome is settled and its context adopted, its summary and tags can
become persistent Life Arc context. It does not grant the author control of
the character's motives or subjective `direction.*` namespace.

The previous focused evidence packet omitted this entire object even though
the runtime persisted it. The focused critic could neither inspect its
summary nor identify a rejection coordinate for it. General deterministic
source closure did not fill this gap.

The current focused review includes the complete object, including summary,
context tags, supersession prefixes, narrative tags, duration and privacy.
`unsupported_dynamic_life_directions` identifies exact summary or tag field
paths and verbatim fragments. The model judges origin, branch entailment and
authorship; deterministic code only validates the returned coordinates. No
text is rewritten or classified locally. Empty findings preserve the former
canonical verdict payload bytes.

This coverage was introduced with review contract `.4`, evidence packet `.5`,
and subject `.4`. The subsequent [outcome interior authority change](life-outcome-interior-authority.md)
retains it under review `.5`, packet `.6`, and subject `.5`.
New admitted Proposals explicitly record the packet contract.
Previously accepted Proposals without that marker retain packet `.4` and
subject `.3`; their hash formula and audit bytes remain unchanged. Neither
removing a new marker nor adding a new marker to an old Proposal changes what
its prior ModelResult reviewed. The reducer binds the focused audit copy to
the original validated audit state, including its subject and request hashes.

No model lane or model call is added. The existing focused critic may repair
an invalid response coordinate once. A valid unsupported verdict ends this
admission as `source_closure_rejected`; current production does not create a
new World Author rewrite call. Historical recorded rewrites retain their
existing recovery path. When no semantic critic is configured, the existing
deterministic fallback remains structural only.

The public regression uses supplied model verdicts to verify visibility,
exact rejection, current admission, old-event cold replay and downgrade
rejection. The frozen packet-4 fixture was emitted by the public runtime at
`233249ed` with local model stubs; it proves compatibility, not semantic
validity of its historical durable context. Input bytes and current review
identities change, so longitudinal baselines must be compared explicitly.

This closes an omitted input surface. It does **not** fix the separately
observed real-model errors in trial03 (existing recent manuscripts inside an
outcome) or trial05 (unseen poetry inside the premise): those strings already
reached the focused critic and were incorrectly accepted. Full visibility and
exact coordinates are not proof that a model has found every hidden premise.

## Verified defects and compatibility boundary

The first public `LifeDevelopmentRuntime.advance_once` regression failed at
the injected model boundary with `KeyError: dynamic_life_direction`: the
durable object existed in the parsed draft but was absent from the critic
packet. Supplying an exact unsupported verdict after exposing that object now
stops before CharacterInterior, Plan or Occurrence creation. Re-entering the
same wake recovers the audited verdict without another call. A malformed
finding receives only the existing single critic wire correction; a second
malformed finding remains a technical failure.

A separate cold-ledger negative exposed the missing immutable audit join.
Deleting the new packet marker and recomputing the **copied** review subject
and hash with the old formula initially let a fresh Proposal commit, even
though its original ModelResult still bound the new subject. The existing
`_validate_one_life_development_deliberation` now binds both present review
copies to their prior validated audit records. That coordinated downgrade is
rejected. Merely removing the marker or changing it to `.4` also fails.

`tests/world_v2/fixtures/life_origin_packet4_replay.json` contains ten actual
events and ten immutable sidecars emitted by the public runtime at
`233249ed2062ba5721917fe12f8b3daeda4e454f`, using local model stubs. Its
previously accepted durable field deliberately illustrates the old coverage
gap. Its original marker-free Proposal cold-replays and remains readable;
adding a `.5` marker fails. The fixture is synthetic test data, contains no
private trial prose and does not retroactively certify its semantics.

omission; it does not explain or resolve these two semantic misjudgments.
The new public notice or poetry display themselves remain legitimate novel
environment opportunities, and an accepted Plan/Started event must not be
confused with proof of every embedded outcome detail.

If paid testing is resumed, the smallest separate diagnostic is to replay
each **original critic request**, preserving its messages, JSON response
format and `max_tokens=4096`, and vary only provider-required thinking
parameters. These requests contain no tools, avoiding the earlier
forced-tool-versus-auto confound. Record the parameter diff, raw response,
verdict coordinates, latency and admitted usage. Do not recompile them through
the new review contract or treat a control result as production qualification.
No such calls were made for this change.

## Input cost and verification

The same public book-exchange fixture was compiled at `233249ed` and
`beeb909a`, using an empty pinned context and the same manifest. Compact JSON
serialization of the two `messages` values produced:

| Fixture | Previous bytes | Current bytes | Increase |
| --- | ---: | ---: | ---: |
| No durable object | 15,050 | 16,790 | 1,740 |
| One small durable object | 15,050 | 17,094 | 2,044 |

Equal old sizes are evidence of the omitted surface. These are UTF-8 message
bytes, not measured provider tokens or billing. Larger authored summaries
add their existing bounded text to the existing call; no additional model
call is installed.

The dedicated nine cases and related Life/biography suite passed (371 tests
in the broader run); Ruff and diff checks passed. The integration agent
subsequently reported that all 120 frozen scenarios at integrated commit
`e55210bb` matched the previous `.98` candidate field by field, including the
recomputed hash. The baseline was therefore not advanced. This frozen-suite
result does not override the distinct model-facing contract changes or the
unresolved real-model samples above.
