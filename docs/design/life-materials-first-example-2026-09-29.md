# 从人物生活底稿生成故事、经历与事件机会

状态：设计与人工拆分示例，未实现新的存储/读取接口，未导入World，未验证模型理解效果。依据是候选小说[《你到了跟我说》](celia-life-arc-v2-2026-09-29.md)，不是既成历史。研究与原有接口边界见[前史与NPC方案](life-history-narrative-and-npc-handoff-2026-09-29.md)。

## 先把创作材料与系统权威分开

上一轮“先构建各自生活”实际是一份写作提纲，尚不是可运行的人物档案。本轮建议把它发展为共同的创作底稿：人物身份、分时期生活状态、重要关系、正在处理的问题、既有事件及知情范围。小说和结构化记录可以交替完善；正文中新出现的实质细节必须作为增量候选回到这份底稿，不能绕过检查成为事实。

共同底稿在创作阶段也没有生产写入权。通过前史审核/接受后，系统的权威仍是已接受记录；小说保留为可追溯原文与阅读视图。运行期事件则继续由现有事件、行动和接受链产生。不能为了恢复小说顺序，伪造尚不存在的运行期Action、当年消息回执或模型调用。

每一项材料应带来源、有效时段、本人是否已知、允许谁读取、是否仍待确认。目标和愿望须有形成时间与状态，不能用来证明相应行动已经完成。若某项只有作者的概括而没有角色记录，先留在创作资料中，由后续角色初始化形成自己的理解。

## 一件事如何保留多个层次

照片这一段不能只存“知栀和嘉禾吵过架”，也不能把整段小说原封不动给两人。

| 记录层次 | 照片事件的例子 | 后续用途 |
| --- | --- | --- |
| 原始场景 | 约好拍照，现场忙碌、折盒子、提前离开、发出六张照片、只收到简短回复；后来发生争执 | 保留必要原文和场景关联，让回忆有前因与经过 |
| 行为/结果候选 | 知栀拍照并发给嘉禾；嘉禾回复收到；嘉禾后来表示自己用了照片且有客人询问 | 区分发出、确认收到、使用，以及后来告知。最后一项首先是嘉禾的陈述，不能凭抽取器自行补出实际使用时间、渠道或客户身份 |
| 知栀的历史解释 | 她觉得自己忙了半天没有得到感谢，又觉得为此计较不好意思 | 保存本人当时的理解，不把它写成“嘉禾不在乎她”这一外部事实 |
| 嘉禾的历史解释 | 她在争执中说以为两人够熟，不需要特意招待；她当时持续面对工作 | 对方说过的解释与她未说出口的内心分开。知栀不能读取嘉禾整个私人生活 |
| 后来的新信息 | 搬东西后，嘉禾才向知栀提到照片被使用 | 一条后续告知记录，与旧场景关联；不重写成知栀当时就知道 |
| 当前解读 | 收到新信息后，知栀如何看待旧事 | 由CharacterInterior结合当下处境形成。允许仍介意、改观或不想再谈，不规定结论 |

这里有一处需要回到作者底稿核实：正文没有精确说明嘉禾何时、在哪里使用照片；知栀后来又看过操作间动态，原文也没明确这些照片是谁拍的。若实验需要设定“告知之前知栀不知道照片被使用”，应将其作为待确认的知情安排写入创作底稿，而不能声称仅凭小说已经证明。角色侧没有可读来源，也不等于全知作者已经证明她从未通过其他途径知道。

## 多条故事如何共同成立

每个创作任务读取同一版本的人物与历史底稿，只提出新增场景及其影响。被共同讲述的一件事共用事件身份，人物的回忆与评价分别指向它。故事标题、人物姓名和文本相似度都不能替代事件身份。

冲突处理至少分四类：

- **硬冲突：** 已固定出生日期不同；同一个明确连续时段内，人物被写成处于两个已知互斥地点；同一事件既被断言发生又被断言没有发生。定位具体记录并退回候选，不覆盖已接受事实。
- **不一定冲突：** 两件事都写“2025年春”，或“住杭州”与“去上海看展”。前者时间范围可能兼容，后者分别是住处与出行；不能因区间重叠就判错。
- **视角不同：** 知栀认为没人顾她，嘉禾认为熟人不用招待。两种个人解释可以同时保存。
- **知识不足：** 只知道“后来使用过照片”，不知道在哪一天。保留时间范围/先后关系，补充提案另审，不让检索器或摘要器发明精确时间。

例如，家庭线可以解释知栀当周为什么回嘉兴；嘉禾职业线解释操作间当时的客观忙碌；友情线呈现她们当天怎样相处。这三条线引用同一次回乡与帮忙事件，不各造一次日期和结局。时间冲突涉及多个候选时，先合并修订，再接受统一版本。

## 人物材料怎样成为事件机素材

事件机需要的是当前可用处境和因果条件。嘉禾正在考虑换工作，可提供岗位消息、排班、通勤和既有约定等相关材料；由她决定是否申请、询问、推迟或放弃。知栀正在处理自己的课程与社交安排，两个人的时间安排可能产生实际交集，也可能一段时间没有交集。

小说创作中的“这一段让友情发生转折”不进入运行接口。输入应说明人物目前有什么、知道什么、想过什么、哪些事尚未确定，而不写“安排嘉禾失约，使知栀生气”。前者提供生活条件，后者替人物做了选择。随机性可以产生机会，但不能生成已经完成的行为或规定人物反应。

少量稳定个人资料按版本缓存，动态处境只更新变化部分；历史片段通过角色有权使用的记忆按需读取。不需要让NPC每次从头阅读小说，也不需要每个人每tick都调用模型。

## 怎样检验角色能否理解

角色无需知道作者想表达的主题。需要检验的是：她能否根据自己所知理解当时在意什么，区分事实与自己的推测，在新处境中合理使用或重新看待旧事。

后续最小实验应使用相同内容的两种表示：A为角色有权阅读的场景原文，B为同一场景的事件、本人历史解释和必要原文段。两者来源、细节与上下文预算可比，避免让A读全知小说、B读缩水摘要。另设只保留客观事实的消融组，单独考察删除个人视角的损失。

用照片事件的告知前后两个时点检验知识边界，再用一次新的帮忙邀请检验实际内心选择。观察实际输入、Recall与接受的内心结果，不只问模型“你懂了吗”；也不要求她固定答应、拒绝或生气。若A可理解而B丢失关键含义，修转写/检索；若两者都表现不稳，再查角色提示和生成。此前工程联动验证没有覆盖这个语义验收，本轮也未执行该实验。

当前主要工程缺口仍是：跨故事的统一候选底稿及版本接受、逐角色知情来源与时间、历史身份到运行NPC绑定、NPC私有前史读取。应围绕现有前史、Memory、NPC状态和事件机补齐，不能仅靠新写一份人物JSON宣布系统已经接通。
