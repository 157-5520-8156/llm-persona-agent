# 人生前史的叙事生成与 NPC 接续

状态：研究后的设计提案与内容试写，未实施新的运行机制，未导入人物或记忆。配套样稿：[《你到了跟我说》](celia-life-arc-v2-2026-09-29.md)。

## 研究中可用的方法

下列是本次核对的一手资料。研究指标来自各自实验，不是 Girl-Agent 的效果证明；写作课程是创作经验，不是心理学定律。

| 来源 | 原工作提供的方法 | 本项目采用范围 |
| --- | --- | --- |
| [Re3，EMNLP 2022](https://arxiv.org/abs/2210.06774) | 先生成总体计划，写各段时带入计划和当前故事状态，再处理连贯性与事实一致性 | 前史离线创作保存人物、已有事件、未解决问题，分场景续写；不把全文每次重发给聊天模型 |
| [DOC，ACL 2023](https://arxiv.org/abs/2212.10077) | 分层细纲与生成控制；论文在人评中同时考察连贯、纲要相关性和趣味性 | 把不同人物的选择与后果先接起来，再写场景。纲要是创作工具，不能作为运行后强制剧情 |
| [Writing Excuses：Character Relationships](https://writingexcuses.com/13-26-character-relationships/) | 关系可同时在幽默、金钱、价值观、相处方式、双方对关系的定义等方面契合或摩擦；区分位置权力与个人影响力 | 让人物既有维系关系的理由，又有真实分歧。只供创作检查，不建立“分歧数值→吵架”的代码矩阵 |
| [Writing Excuses：Why Should My Characters Fail Spectacularly?](https://writingexcuses.com/writing-excuses-10-29-why-should-my-characters-fail-spectacularly/) | 尝试的结果可以带来新代价，结果推动下一次尝试；课程也明确反对机械凑固定次数 | 用“选择改变了后面的条件”检查转折；不要求每件小事失败，也不安排人人都在同一章和解 |
| [ConStory-Bench 作者项目页](https://picrew.github.io/constory-bench.github.io/)，[原论文](https://arxiv.org/abs/2603.05890) | 从时间因果、人物知识、世界设定、细节及叙述一致性等角度找有文本证据的矛盾 | 单独验收年代、知情边界和因果。没有矛盾不等于故事有趣，也不能仅靠模型打分宣布文学质量合格 |

我们之前的问题是：按时间目录分别填短片段，接着为“深刻”补一个道德冲突。目录的年份很多，关系却只有一根因果线，配角只在主角需要成长时出现。增加场景长度也没有修复这个结构。

## 本次采用的创作过程

先确定每个人各自追求的东西及现实限制，再写他们的交集。知栀既想保有老友的位置，又想进入新的大学生活；嘉禾想被当作能独立做事的人，也需要收入和可持续的工作；陈曼参与合作有租金、订单与休息安排方面的考虑。人物的目标可以同时合理而不能同时满足。

随后交织三条线：老友的亲近方式变化、嘉禾的职业尝试与迁居、知栀在新环境里的关系和自我评价。青岛计划、第一次帮忙、照片有没有被使用等内容在不同阶段改变意义；保留玩闹、无聊和没有情节用途的日常。关键对话用具体场面呈现，其余年份可以略写，不安排每段结尾总结性格。

最后分开进行两种检查：内容上检查配角是否只有服务主角的功能、冲突有没有实际利益、角色是否有自己承担的过错、关系是否仍有维系理由；工程上检查时间、身份、原始记录、知情与隐私范围。前者需要真正阅读作品，不能用结构校验代替。发现问题局部改写，不能让一致性审核把全部创作退化成无关痛痒的小事。

v2仍有局限：陈曼的独立生活展开有限；本稿只补一条重要关系及相关生活，不构成二十年的完整人生；地点与时段还需统一审阅。本文没有把“我觉得更好”记作质量验收通过。

## 给记忆系统的不是一份全知小说

全知作者底稿、世界已接受事实、每个人知道的事、每个人当时的理解、每个人现在的判断，应当分开。写作阶段可以构思嘉禾不曾说出口的感受；这不赋予知栀读取它们的资格。

样稿可先拆为下列候选事件簇。编号仅用于设计讨论，不是已接受的事件ID。

| 候选簇 | 可接受后作为共享事实的部分 | 必须保留的视角差异 |
| --- | --- | --- |
| H01，早年相识与反复来往 | 剪坏裤子、一起等吃饭、买文具、写旅行本子的具体交集 | 不能把“常一起玩”推成两人所有童年经历相同 |
| H02，家长询问与发言失误 | 具体谈话、台上的停顿、发出的短视频 | 知栀觉得前排人在笑她，不等于有人确实嘲笑；嘉禾截视频的未表达动机不自动共享 |
| H03，嘉禾学艺与收入 | 她向知栀展示过的成品、工作消息与买鞋互动 | 嘉禾全部收入、工作压力和其他同事的想法不因朋友关系而公开 |
| H04，旅行与烘焙展 | 商量过旅行、未订票、展会照片与消息 | “有时间陪别人却不陪我”是知栀的解释；去展会的工作安排可属于嘉禾另一条经历 |
| H05，稿件落选与文案 | 知栀的落选事实、后来告诉嘉禾、接单文案被替换 | 在知栀说出来之前，嘉禾和陈曼不能知道她刚经历了落选；陈曼未参与私聊 |
| H06，操作间与争执 | 约定拍照、临时帮忙、提前离开、随后互相发的话 | 各自期待、当时不满及对“帮忙”的定义单独保存。嘉禾使用照片的情况在她告知前对知栀不可见 |
| H07，退租、搬迁与道歉 | 谁参与合作结束，谁见证搬东西，具体道歉内容 | 母亲转述须保留为转述；知栀不是租金协商的在场者，不能获得全部内部细节 |
| H08，异地生活与未定去向 | 后来实际旅行、收到的工作消息和查过的路线 | 嘉禾新的私人生活不自动进入知栀记忆；考虑上海工作不是已辞职、已录用或已搬家 |

详情记录可以有长短差异，每条保留时期、参与者、先后关联和出处。公开可观察行为与历史主观解释分别提供给各自读者；检索摘要可以省略，不能把解释升级成他人的真实动机。原文只在相关时提供，不能把这些场景全塞进系统提示词。

## NPC 联动的接口要求

本节是拟议接口，不代表当前代码已有对应事件或字段。实际接线审计另见 [NPC审计](../audits/prehistory-npc-linkage-2026-09-29.md)。当前已存在NPC独立状态/目标/关系写回与虚构活动生产链，但没有历史人物到运行NPC的显式映射，也没有把这些前史接进NPC私有长期记忆的链路。已有共同经历摘要只有有限窗口，不应把它描述成完整NPC自传体RAG。

NPC目前能提出虚构计划和生活事件；现有 `user_channel_completion=none` 不允许它凭叙述完成QQ发信。样稿中的历史私聊属于待审前史事实；面对面谈话可以成为被接受的共同生活事件内容；但如果要表现NPC收件箱、送达、未读、回复与未回应，仍需显式的收发对象、通信记录和传递状态，不能拿一段环境正文冒充这些回执。该缺口不应通过接入用户真实QQ来替代。

1. **历史身份显式绑定。** 使用World、档案版本、`history:person:*`与运行NPC身份组成经验证的绑定记录。不能靠同名、相似人格或检索相似度自动合并。只有历史身份的陈曼可以继续留在前史中，无需立即变成持续运行NPC。
2. **各自初始化。** 嘉禾的个人背景、当前处境、她知道的共同事件和她自己的记忆进入她的actor域；知栀只接收自己的版本。双方对亲密程度、亏欠与旧事的解读可以不同；不能把它们压成两人共享的一份关系说明。
3. **交接未定问题。** 2026年7月嘉禾在考虑上海的工作，这是曾有的意向。到World启动时，让NPC在自身状态中决定继续、改变或放下。前史作者没有权限预定她后来入职、找知栀见面或搬去上海。
4. **行动产生新来源。** NPC选择联系、履行约定或参与事件后，经现有授权和结果链产生可见记录。知栀通过自己的CharacterInterior感知、解释和选择回应；后续聊天引用这些新来源。模型决定不联系也是可能结果；技术失败须另记。
5. **NPC缺席也有生活。** 嘉禾不出现时的状态变化应来自属于她的真实世界事件或被接受的行动，不由“为了让故事有转折”直接改掉她的工作、好感或记忆。不能把她设为等待主角互动的剧情按钮。

这条交接允许一个人过去有故事，也允许运行后的故事脱离作者预想。离线前史可以有完整叙事安排；实时运行只继承成立的历史、当前处境和未定事项，不继承“本章必须和好”的指令。

## 最小接线验收与成本

先只绑定一个NPC，验证“历史来源→双方不同的可读记忆→一次NPC自主选择→主角感知与选择→新记忆/回执→冷回放”。以下项目全部通过前，不宣称联动完成：

- 相同名字的另一个NPC不能收到这段历史；重复初始化不重复导入或付费。
- 嘉禾可以想起自己经历过的事，但不能读知栀未告诉她的落选感受或聊天；陈曼没有参加的私聊不会成为她的知识。
- 用同一历史事件的不同主观记忆作小组对照，检查模型输入、实际注意和被接受的选择；不强求指定情绪或行为出现，也不凭一句“想起了”判通过。
- 使用合成时间推进真实触发已有机制；把未定意向、已执行行为、未送达、角色不回应和技术失败分别记录。重启后来源和状态不变。
- 计量每条链的物理调用数、输入输出、一次性初始化费用和持续费用；本轮未跑项目模型API，因此没有这条新链的实测费用。

成本控制优先复用已接受的个人资料和事件摘要，用来源修订号缓存身份及记忆读取，只在有相关事件或已有定时机会时让NPC判断；避免为每个NPC每个tick额外调用。调度提供机会，不替NPC决定态度。可以分批离线生成与审阅前史，局部修改只审受影响部分；不要把高成本的小说反复改稿流程放到每条聊天的关键路径。

## 从故事转写为经历：保留意义与知情顺序

以下仍是待实现的表示与实验方案。当前`PrehistoryRecord`已有时间范围、历史人物、相关记录和正文，但没有完整的逐角色知情时间/视角结构；NPC上下文也没有该前史读取链。

创作稿保留全文。入库转换以完整场景为单位提议事实与视角记录，不逐句切碎，也不只压成“拍照→争吵→和好”。场景短摘要、必要原文段、事件关联、人物与知情范围一起保存。检索可先提供短摘要，相关时补足同一场景的前因、过程与后果；较晚发生的告知必须保留为较晚的记录。

以照片为例：

| 对象 | 内容 | 知情范围 |
| --- | --- | --- |
| 事情发生 | 嘉禾使用了照片，收到客人询问 | 嘉禾当时知道；不能因此让知栀也知道 |
| 知栀当时的经历 | 忙完发出照片，只收到简短回复，觉得自己的付出没被看见 | 知栀自己的感受；不证明嘉禾没用照片、不重视她 |
| 后来告知 | 搬东西后，嘉禾发消息说照片已使用 | 从告知时起，知栀才拥有这条信息及其来源 |
| 再理解 | 知栀可能修正先前判断，也可能仍介意没有及时得到感谢 | 由角色在当下形成；不是转换程序必须产出的结论 |

因此，事件发生时间与某个人获知时间要分开。回忆2025年的自己时，她可以记得当时的误解，同时知道后来发生的说明；查询过去视角时不能用后来的知识替换当时所知。文学叙述中的他人内心若属于作者设想，只进入相应角色的候选私有材料，不直接进入主角的记忆。

前史经专用来源接受与保留，不生成假的运行期Action、聊天送达回执或当时并不存在的模型调用记录。可以复用Memory和内心解读机制，但要补齐相应来源读取，不另建一套脱离事件账本的“小说脑”。

## 多条故事共享一份世界历史

各故事线创作前读取同一版人物身份、时间范围、职业/住处变迁、已发生交集和未定事项。新故事只提交增量候选；通过检查后更新共同底稿，再供后续故事读取。不要让不同生成任务各写一整份人生，最后靠名字和相似文本拼接。

需要拒绝或修订的是同一人在同一时间不可能兼容的行程、未交接的身份改变、同一事件相反的客观结果等。两个人对同一件事评价不同、一个人后来改变理解，本来就可以同时存在。重复叙述应指向同一事件身份及不同视角；不能覆盖成一个双方都同意的“正确感受”。重要冲突需定位原段落和既有记录，修订提案而非偷偷覆盖已接受历史。

小说适合作为离线创作表达，人物/时间/事件底稿提供跨线约束；运行后由已接受事件与各角色选择产生后续生活。可以根据记录再写叙事展示，不能把作者安排的未来剧情当成运行事实。

## “角色理解了”需要怎样验证

读者的理解与角色的理解可以不同。读者能从全知视角看见双方的委屈，角色只掌握部分信息，也可能不愿承认自己的嫉妒。验收目标是有来源、符合所知且能延续的个人理解，不是让角色复述作者的主题说明。

先选上述同一事件的两个时点，以及双方不同视角。比较A（角色有权知道的叙事原文）与B（完全相同可见内容的场景记录、解读及必要原文），保持来源标识与预算可比；C仅给客观事实，作为有意删去个人理解的对照，不将C当作公平的格式对比。当前模型、处境和测试问题保持一致。

验收四件事：能否区分“照片未被使用”与“当时不知道被使用”；会不会越权知道对方未透露的事；面对新的帮忙邀请，相关记忆是否实际进入并被用于内心判断；收到新信息后，能否在不重写旧事实的情况下形成新的解释。不给规定的情绪、固定答句或唯一动作。它可以答应、拒绝、问清楚或暂不决定，也不必把旧事讲给用户听。

检查实际模型输入、Recall记录和被接受的内心/选择结果，不能仅凭模型自述“我理解了”计通过。同一问题做少量重复和改述，记录不稳定性；反事实前史放在彼此隔离的副本中。只有内容转写与视角边界先验证可用，再扩展更多相互交织的故事和NPC。
