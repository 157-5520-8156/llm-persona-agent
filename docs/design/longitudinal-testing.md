# 加速长期旅程测试

本文是 `girl-agent-design-intent.md` §12.11 的验证工具说明，不增加角色行为规则。
目标是缩短发现长期连续性问题的反馈周期；模型是否像人仍需基于连续经历评审。

## 方法与实际覆盖

在全新的 SQLite World 中运行真正的 `build_qq_c2c_host`。测试者只提供用户消息及其发生时间，
World Author 和 CharacterInterior 继续使用原来的机会、上下文、决策、权限、结算与记忆路径。
QQ 发送接到本地捕获器，`get_message` 只确认确实捕获过的消息。不会接触真实 QQ 或生产数据库。

虚拟日历逐次到达下一条输入、已登记的 due、重启点或有界 heartbeat。每次先调度和结算同刻环境，
再让新输入读取上下文；结算后重新读取生产宿主的 due 快照。未来租约、未到期 Action 可以继续等待，
不能把反复 drain 当作时间已流逝。后台计时器只能等待日历推进，展示等待使用独立时钟。
HTTP 超时、实验运行期限和 API 账期仍按实际时间计算，不缩短供应商调用、不重置每日费用。

默认旅程七天，11 条用户输入、两次重启，包含日常交流、未回复间隔、用户安排的更正和跨日回忆线索。
没有角色的标准台词、指定心情、要求必须主动联系的次数，也不要求每次输入都有输出。
真实角色生活由原机制产生；没有产生活事件时，丰富度评估应记录缺证据并检查原因。

| 要观察的问题 | 纵向证据与判断 | 不成立的替代指标 |
| --- | --- | --- |
| 人格大体稳定 | 在不同处境中的价值、偏好和边界；变化是否有此前经历支持 | 每轮使用同一种语气、人格永不改变 |
| 记忆像人 | 信息来源、时间、更正、再次出现的语境；能否承认不确定 | 把所有旧消息逐字背出来 |
| 一周重复 | 多次提起的是同一事情吗；有无新进展、情境触发或用户邀请 | 相同词语出现即失败；话题黑名单 |
| 经历带来变化 | 事件被接纳、进入角色材料、后续判断或选择变化的连续证据 | 事件存在就声称模型看过；要求遇到挫折必生气 |
| 生活事件丰富 | 不同活动、人物、处境、结果与持续后果；生活是否只围着用户转 | 随机换地点名称、每天强制一个戏剧事件 |
| 行为多样但连贯 | 相近/不同处境中是否存在多种有依据的选择 | 提高温度、随机决定发言或沉默 |

## 三层迭代

1. **每次改动的短旅程**：先用零费用夹具验证真实宿主能推进、重启、回放和导出；再对有问题的短区间
   做小额真实模型试跑。固定夹具的重复回应是已知负对照，不是产品质量样本。
2. **阶段性的虚拟周**：运行真实模型，连贯阅读整周记录，并针对上表标注证据与不确定性。
   至少比较多条独立旅程，不能用一条顺利的七天记录证明稳定可靠。相同输入也不保证模型结果可复现。
3. **少量真实时间观察**：保留实际用户的自然输入、真实 QQ 回执、并发/网络/重启与疲劳式长期体验验证。
   虚拟周无法替代这些；它先筛掉大量逻辑断链与明显行为问题。

后续可在同一个保存点复制两个隔离世界，只改变一项用户/环境输入，比较后续变化；这能减少重复付费
生成前史，也便于定位因果。当前会在重启点保存静止 SQLite checkpoint 及 hash，**尚无自动分叉续跑
或配对统计入口**。不能把两次独立生成、经历不同的周记录当成严格配对实验。

## 使用

```bash
# 默认是无网络夹具；output 必须不存在。无需 .env 或模型凭据。
PYTHONPATH=src python scripts/run_world_v2_longitudinal_audit.py \
  --output output/longitudinal/fixture-week-01

# 真模型试跑：环境中配置 DEEPSEEK_DEBUG_API_KEY；开关明确表示会调用供应商。
# 0.5 元是实验共享预算，不是跑完七天的价格承诺。到额度不足时保存部分结果。
PYTHONPATH=src python scripts/run_world_v2_longitudinal_audit.py \
  --output output/longitudinal/model-week-01 \
  --model-mode real-provider --allow-real-provider --max-cost-cny 0.5
```

`--scenario` 可指定同格式 JSON。调整 `duration_minutes`、输入和重启点可做数小时的短旅程。
仓库提供 `fixtures/world_v2/longitudinal_two_days.json`，包含六条输入和一次重启点；其两天是请求范围，
不是默认预算可完成的承诺。CLI 不读取 `.env`，也不验证 debug key 与生产 key 是否不同；隔离数据库
不等于隔离供应商账户。若使用同一账户，实验费用必须计入该实例总账。
`--heartbeat-seconds` 默认 300，最大 900；粗粒度 heartbeat 不是生产几秒一次 scheduler 的逐次重放。
`--max-wall-seconds` 默认 1800，是停止实验新工作及等待调用的期限；已经发出的持久任务关闭时需收尾。
越限、回放不符、后台无法推进、预算拒绝或目标区间仍有应处理的 due，均不得标为完整旅程。
若最后一个事件之后没有到期机会，Logical Time 可以早于模拟窗口终点；报告保留两种时间和 quiet tail，
不为了让数字一致而制造空事件。

为了隔离成本和网络，当前实验 profile 关闭图片、外界实时源、语义 embedding 和文本端点评估。
因此还不能声称这些生产能力已经被整周覆盖。真实模型模式保留所配置的角色和世界模型，不用固定话术
替换角色。虚拟未来的日期不会被配上今天抓来的新闻，制造假的未来世界证据。
当前 Life general source closure 使用确定性检查；novel-origin 在未配置 reviewer 时使用确定性
focused-origin 检查，配置 reviewer 后才使用该模型路径。缺少 reviewer 不等于关闭生活事件接纳。
实验报告分别记录这两条路径；self-review 只复用显式配置，不为跑通评测自动开启。

## 输出与评审

- `report.md`：连续对话、技术问题、重启、时间跨度、费用及各维度的待评审提示。
- `timeline.jsonl`：每个输入/调度步骤、捕获消息、状态与对应账本闭区间。
- `evidence.jsonl`：新世界真实事件的增量导出；`manifest.json` 绑定文件 hash、回放检查、运行范围与限制。
- `review.json`：保留顺序的评审包，去除已知运行版本/供应商管理标签；六维默认 `insufficient`。
- `model-inputs.jsonl`：真实模型模式在客户端 transport 边界捕获完整 JSON 请求字节及 SHA-256；
  包含 messages、tools、schema 与输出参数，不记录鉴权头、请求地址或响应正文。文件权限为 0600。
- `checkpoint-*.sqlite`：关闭并等待后台收尾后的保存点。供本地进一步取证，不包含真实用户生产数据。

`validate_review_annotations` 要求六维完整、理由和有效证据引用；`assessed` 表示有依据地做过判断，
不表示质量通过。工具不主动请求额外 LLM judge。可先由实现者寻找反例，再让独立评审者阅读隐去版本
标签的材料；评审分歧保留，不把模型评审当作客观人格检测器。

没有可见消息不等于沉默。报告保留实际 `TriggerProcessCompleted.runtime_outcome_ref`，角色的
`model-silent`、Action 授权、供应商接受、技术失败及未知各自保留。捕获器的确认只是模拟回执，不能
称真实 QQ 送达证明。当前重启 hash 验证状态连续性，异步恢复是否重发仍单列未验证。
模型输出合法之后仍可能发生提交失败；报告将 Life ecology 的 `failed_safe` 和技术失败终态单独显示，
不把这些调度步骤折叠成安静时段，也不把它们解释成角色选择沉默。

捕获成功标为 `captured_client_requests`；写入失败、不可读取的请求或部分覆盖会保留不完整状态，不能
伪报成功。捕获器不缓冲响应流，记录故障不阻断模型调用；必须联合 usage 和 capture health 核对覆盖。
捕获区间不证明请求属于同一 pinned turn；发送字节不证明供应商接受、模型关注或后续变化的因果关系。
导出的模型原文可能包含身份和供应商名称，管理字段隐藏不等于严格盲评。这些私人产物不进入版本控制。

## 费用与时间

加速去掉的是空等，不是模型计算。真实一周需要多长、花多少钱，取决于该周触发多少次模型调用与实际
供应商延迟；不能预先保证几分钟或几毛钱跑完。预算不足时必须保留 partial 证据，不能降低世界活跃度
再把结果当作原 profile 的完整一周。

每实例约 ¥100/月的目标包含测试调用。设计总纲给真实资格化/对聊 canary 的初始信封是 ¥6/月，
因此不应每改一行就重复付费跑完整周。先做短回归、复用保存点、只对有信息价值的问题扩大真实样本。
当前预算门在本实验 SQLite 内共享，跨实验目录与生产实例的总费用仍需汇总，不能各开目录重新获得额度。
HTTP 发出前按完整请求（包括工具 schema）与实际输出上限保守预约；按供应商 usage 结算，未知价格
不发请求。因此可能在已结算费用低于预算时拒绝下一次调用，拒绝金额不能当作实际花费。
虚拟周压缩在同一个真实账期内，不能把 production health 的“每真实日花费”直接当成模拟日均成本预测。
