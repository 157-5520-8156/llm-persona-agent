# 保留原句范围的聊天来源审核

## 已确认的问题

v16 真实读取器保留了“你要真让我什么都不想 我大概三秒就破功”的条件，
但来源阶段只接收“角色大概三秒就破功”的实际状态命题。它没有原句，既无法核对
命题是否忠实，也无法发现两位读取器共同遗漏的事实。这个接口缺陷已确认；它不是
上一轮所有交付失败的唯一原因，无依据习惯和未交付草稿被误认成已回复仍是独立问题。

## v17 的职责

保留两个不读证据的独立读取器。将完整原句、两份完整读法（含条件、问题和预设）、
带身份的全部命题及同一 pinned 来源一起送至 `visible_contextual_source_review`。
模型逐项判断原句是否确实承担该事实承诺。`not_asserted` 是可审计的范围判断，不是
事实获得了支持，必须无来源选择且 `source_support=false`。实际断言仍按原来的
主体、mode、时间和字段权限核验，不能改读为说过或打算过来迁就证据。

审核还必须覆盖每条原句，并列出未被实际断言命题覆盖的事实/前提；即使两个读取器都
没有提取事实，也不能跳过此检查。遗漏触发同角色一次纠正；范围不明、覆盖未完成或
无法读清来源是技术不确定，不当作编造，也不当作角色沉默。条件里的历史、习惯或其他
实际前提不会因外层条件而自动免审。模型仍可能判断错误，需要真实反例验证。

代码只守身份、覆盖、来源权限、结果结构和重放绑定。原句范围与语义真实性由审核
模型判断；措辞、情绪、意图、行动及纠正后的表达仍由同一角色决定。没有增加角色脚本。

## 接线、成本与验收边界

显式 `--visible-source-review-version 17`；旧版编译/回执及部署默认值不变。
实际事实候选仍为两次读取加一次来源审核；之前判为全无事实的候选也增加一次整句
审核，因此不能宣称降低成本。保留原调用超时和纠正次数。未来减少重复读取需要独立
的等效完整性证据，不用空事实数组换取快速通过。

需要同时验证：纯假设/当下感受可表达；条件内的过去经历、隐含习惯、未交付草稿
不能冒充记录；证据权限不变；缺项和不确定不能通过；完整聊天及冷恢复正确。
本地测试只证明执行边界，真实提供方与完整聊天结论另写入发布证据。
