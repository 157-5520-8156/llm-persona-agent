# 启动前人生档案与统一记忆：讨论草案

状态：用户已确认纳入当前Goal。已实现启动前档案的权威导入层及显式应用配置，仍需接通角色保留、统一检索与表达来源审核；没有改写生产角色数据，不构成完整功能或发布承诺。

## 问题与当前证据

用户提出：角色的年龄远大于程序实际运行时间。启动前缺少自传式经历，会使日常聊天缺乏可回忆的人生，不能单靠要求模型停止编造来解决。希望为每个角色建立与当前记忆互通的人生档案，并用于遗忘、压缩、提取和长期一致性测试。

当前候选代码的相关入口：

- `configs/character.yaml` 的 background 包含“高中做过校刊”等过去设定，但 `companion_identity_source_material` 明确排除 background；较小的 canonical_facts 另外提供稳定事实。设定文本和可引用事实目前并不等价。
- `BiographicalTimelineConfigured` 保存审核过的时间线，主要支撑年龄、学业与住处；不能由这些坐标推导任意历史事件。
- `Committed Experience` 绑定结算后的活动或确认的共同事件；启动前人物背景不属于此来源。
- `MemoryRetrievalCompiler` 当前读取 fact/experience 来源；`RecallCorpusCompiler` 和 `WorldRecallIndex` 已能区分事件、语义事实与主观解释，并保持原始来源。
- 记忆已有保留、强化、遗忘、压缩来源覆盖等约束。这里不把这些代码约束当作长期行为已经验证的证据。

因此需要扩展合法历史来源及其读写链，不能简单将更多背景文本塞进提示词，或把导入数据冒充运行后亲历事件。

## 建议的概念边界

“启动前人生档案”记录在角色世界中成立、发生于本World开始运行之前的历史。允许由模型创作并经一致性审核接受；来源是世界初始化的创作授权，真实性范围是虚构角色世界。

“运行后经历”继续来自角色选择、活动推进及世界结算。人生档案导入不能补写启动后的失踪活动，也不能将计划升级为完成。

两类来源进入同一记忆处理与检索系统，但保留各自来源类型。不能仅凭回忆文字或检索结果形成新的事实权限。

另外区分三件事：

1. 历史事实：发生了什么，约在何时，有哪些参与者。
2. 记忆表征：角色记得哪些内容、细节有多清晰、有哪些关联与当时解释。
3. 当前理解：此刻如何看待这段过去、是否愿意讲述，由角色决定。

忘记某事不代表历史被删除。新的理解不覆盖旧事件。档案也不能变成角色每次检索都能读取全部精确原文的后门。权限性删除和隐私撤回另走既有删除边界，不能用“历史不可变”拒绝合法删除。

## 最小落地范围

先离线建立一份可检查的人生档案：家庭、求学、住处、重要人物与关系的时间骨架，加上有联系的日常片段、反复经历和少量转折。不要求逐日模拟二十年，也不把所有经历都写成戏剧性大事。

过去人物、地点、物件必须有稳定身份；历史关系不自动授予当前NPC行动或在场权限。近期记忆和很久以前的记忆可有不同初始可访问性，记录初始化方法与版本。这是产品建模假设，不宣称心理学真实性。

每条记录至少保留角色/World、记录身份、发生时间或区间及精度、系统接受时间、事实内容、来源版本、参与对象、隐私范围与关联记录。主观解释单独记录并保留角色作者身份。系统接受时间不能伪装成过去的写入时间。

启动截止点取该World原始启动边界，不能在后续导入时移动到今天。已有角色先核对配置与已确认的历史；角色以前说过的话只证明曾说过，不能自动成为所述经历的证据。不得生成涉及真实用户的未确认共同历史；已有人工设定需要保留其设定来源与适用范围。

模型可在离线创作阶段参与构建过去，但需检查时间、人物、地点、已接受事实与既有设定冲突。确定性代码检查身份、时间与权限，语义一致性需要模型审核及代表性人工抽查；哈希正确不等于语义一致。

首个实现只导入受审档案，并贯通来源读取→角色保留选择→统一检索→可见表达来源审核→重启重放。保留当前角色对情绪、解释和披露的决定权，不建立“某经历必然导致某性格”的规则。

后续可以另行设计受约束的历史补全能力，但聊天回答不能凭自己的草稿制造支持草稿的证据。补全必须有独立授权、冲突检查和接受记录；旧的固定上下文不能事后被新历史悄悄改写。这项能力不放入最小首发范围。

## 遗忘、压缩与表达

允许存储层保持完整档案，而角色只能访问经记忆状态筛选后的内容。事实审核可校验已选内容是否有依据，但不能把其本应无法回想的细节偷偷灌回角色纠错输入。

压缩结果可以保留梗概、情感关联和时间模糊度，必须能追溯到原始记录，不得增加地点、人物、动作和确定性。仅换用“好像”“记不清了”等词不构成新事件的事实来源。

允许角色表达不确定性以及对过去不同的理解；是否需要进一步模拟错误记忆，应作为单独设计问题。第一版不主动制造错误事件来表现真人感。

## 加速验证

使用同一份已冻结的档案建立参考事实集和未发生事项集；保留独立题集，避免仅以生成记忆时的措辞提问。离线推进逻辑时间并通过现有记忆读写入口执行保留、遗忘、压缩、检索与强化；不能只把数据库日期改成多年前就宣称测过长期记忆。

固定档案导入能测试大规模检索、来源核验与初始化后的表现。要测试数周内的形成和演化，还需另一类逐步加入事件与用户互动的时间推进试验；两类结论分别报告。

检查直接和间接线索、相似人名/事件干扰、未知事件诱导、压缩后的事实丢失与新增、过去与当前状态混淆、跨日重复、来源隔离、隐私、重启与冷重放。检查角色能否适度回忆、遗漏时是否承认不确定、理解能否变化但不重写事实，不以每次背出原文作为成功标准。

保留、忘却、复习等语义决策采用角色模型；逻辑时间、预算、数据完整性和不可越权的来源范围由代码约束。对照未压缩/压缩、不同检索预算与相同输入轨迹，测量行为差异及费用。

档案创作与导入列为一次性初始化成本；在线只检索相关小片段，逐项记录后台维护、检索、审核与纠错成本。未经真实样本测量不承诺具体月费。合成人生档案的测试不能替代真实陪伴期间的长期用户评价。

## 与当前发布阻断的关系

此机制能补上启动前人生来源缺口，属于用户原本期待的完整生活与记忆的一部分。它不证明运行后无依据的午睡、散步等陈述变成合法，也不自动修复审核误判或纠错超时。接入之前仍不得宣称这些发布阻断已解决。


## 已落地的导入接口与剩余接线

`PrehistoryArchiveRuntime.import_reviewed` 接受独立审核记录所绑定的档案。应用通过显式
`WorldV2TurnApplicationConfig.reviewed_prehistory` 安装，默认不导入。审核记录是可信运维输入，
包含审核者、审核产物引用/哈希及实际审核时间；档案不能仅凭自己声明“已审核”进入聊天能力。
这里的哈希只检查审核是否覆盖同一份内容，不代表代码已经检查了文字语义或生平一致性。
生成与独立审核工具、首批正式人物数据仍待完成。

档案 manifest 固定历史身份与逐条内容哈希；每个片段独立写入事件，使后续记忆合并仍能逐项
追溯来源。接受时间使用当前逻辑时间，发生区间严格早于原始 `WorldStarted`；时间精度保留
显式时区，账本统一时间表示不会把本地月份改成另一个月份。历史人物/地点使用独立命名空间，
不生成当前 NPC、在场权限、活动或 Experience。重复导入、重启和部分失败重试不会重复接受。

导入默认不创建 MemoryCandidate。当前普通聊天也不会读取完整档案；面板只新增档案数与片段数，
不暴露历史正文、身份引用或审核材料。新字段为空时不进入旧序列化与语义哈希，现有世界不被自动
补写历史。后续必须通过现有记忆候选接受与检索流程开放角色的回忆能力，保留来源类型、角色作者
及撤回/遗忘规则，不能把直接读取档案当作这条接线的替代方案。

导入层验证见 `docs/audits/release-prehistory-import-validation-2026-09-13.json`。这些验证不证明
角色已经能回忆启动前人生，也不证明真实语义一致性审核、压缩、遗忘、跨周自然度或月成本已通过。
