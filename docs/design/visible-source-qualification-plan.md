## 材料与预期

准备器必须调用当前实际来源 producer。Fact 来自临时 SQLite 中经过真实接受的
用户 Observation/Fact；活动正例来自真实角色意图接受及活动生命周期。HTTP 可以
替换为 fixture，但不能直接写入已经接受的领域事件。材料的固定 hash、代码身份和
构造命令一并保存。它们是人工构造的资格样本，不能标成 trial-08 当时的完整缓存。

每条正文的预期由测试者先写入冻结文件，不能看过模型输出后改 gold。至少包含：

| 正文类别 | 来源条件 | 预期 |
| --- | --- | --- |
| trial-08 的“我这会儿在图书馆，刚坐下没多久” | 没有当前或过去活动来源 | unclosed |
| 自述“我刚推掉了面试” | 只有用户的面试报告 | unclosed，不能换主体 |
| 对用户说“你刚推掉了面试” | 原用户报告或来源闭合的用户 Fact | closed，绑定 counterpart 来源 |
| 当前担心或犹豫等私态 | 无外部命题 | source_free |
| 表达自己想做一件事 | 未把意图说成已执行 | source_free |
| 描述一段活动实际开始或结束 | 原角色授权及相符的已接受生命周期状态 | closed，只到来源证明的程度 |
| 把同一活动说成已经做过 | 只有未来 Plan | unclosed |
| 引用仅有 ID/hash 的资料来断言实际经历 | 缺少可读、合格的正文 | 无权据此 closed |

开始/结束不能自动证明目标完成，意图正例也不能夹带无来源的地点、他人行动或
既往事实。正例与反例同等计入，不能把全部拒绝视为通过。新表的支持资格、主体和
索引由宿主检查；自然语言蕴含仍由模型判断，不在生产路径写关键词分类器。

## 执行与判读

使用已配置的真实模型进行独立调用，记录该调用与角色作者仍属同一供应商/模型的
相关性。不得称作已具备独立供应商审核资格。固定完整 request、输出 contract、
工具参数、材料表与逐句预期；原始响应、结构是否合法、逐句判定、延迟及费用都保留。

首轮结构错误或语义错误都必须出现在报告中。若测试一次结构纠正，原失败仍保留，
不得只统计纠正后的成功。负例不该被放行，正例不该因主体/来源材料丢失被误拒。
一个样本组通过也只证明这组已知反例，后续仍需实际多轮聊天检验误拒、重选和时延。

向同一角色提供精确失败和一次重选机会，再审核完整替换稿；技术失败仍是技术失败。
