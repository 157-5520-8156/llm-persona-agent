# 三条交织生活线：首版执行示例

这是隔离机制测试的虚构输入，不是已经写入角色生活的历史，也不是已证明真实模型能够长期维持的故事。

| 长期事项 | 近期外部变化 | 与其他事项的交织 |
| --- | --- | --- |
| 社区旧书交换 | 发布活动公告，之后开放学习资料专区 | 同一场活动同时关联物件整理、学习资料与熟人见面 |
| 学习与时间安排 | 图书馆自习区周六检修，傍晚才开放 | 造成可选择的时间变化，不替主角决定去哪里 |
| 熟人的生活变化 | 林提出周六整理旧书的邀请 | 与旧书交换共享节点，不再制造一场重复活动 |

中央作者一次输出事项、共享节点、窗口与执行包。环境正文如“图书馆通知：周六自习区检修，开放时间改为傍晚六点以后”；NPC包如“周六我打算整理旧书，你有空的话可以来看看”。执行时将NPC原话连同说话者归属保存，只证明其说法，不证明他说的一切已成事实。

主角随后可以参加、拒绝、改期，或提出中央作者没有想到的新方案。只有她实际提交的计划和真实状态变化可供条件使用。例如资料整理机会可依赖一个既有计划completed，abandoned使其失效；改期可以使绑定旧版本的节点失效。另一条没有依赖该计划的生活线继续保持可用。这里没有把“拒绝邀请”等自然语言用关键词映射成状态。

验证分为三部分：同批三个环境事件只需一次fixture作者调用；真实注册NPC的发言投放不调用NPC或事件作者；真实应用构造器开启中央模式、连续wake与SQLite重开后不重复投放。另覆盖取消、过期、中断恢复及失败记账。它们证明执行机制，不证明主角真实对话质量或三周叙事质量。

复现入口：tests/world_v2/test_world_outlook.py。执行命令：

```sh
python -m pytest -q tests/world_v2/test_world_outlook.py
```
