# 来源拒绝后的原文反馈

实际聊天中，来源审核已能支持角色过去的疲惫和被采访感受，却拒绝了混入同一气泡的
“刚答完，下一个问题又来了”。纠正请求只有独立读取者归纳的命题，缺少被拒原话，
失败名称仍是格式错误；反馈中要求参考“原气泡”却没有提供它。

`visible_rejection_context`集中定义完整原文的纠正载体。审核准备对象提供原始气泡顺序、
完整文本、候选hash和来源表hash；16条、每条4096字符的边界与现有文本审核边界一致。
原文不挤入4096字符的失败描述，避免截断后重写失去上下文。

只有明确的来源语义拒绝生成这个载体，通过既有异常接口传到CharacterInterior。
入站和主动表达共用该类型，纠正失败码为`role_result_source_invalid`。
载体只放在纠正栏目，并明确标识`rejected_candidate_not_world_evidence`；
不进入世界材料、不创建经历、不授予来源权限。缺省字段不序列化，旧请求身份保留。

这不是一个行为规则。角色仍决定如何理解失败、重写、调用能力或沉默；
同一固定世界请求最多一次角色重选，技术故障不因此获得新的语义重试。
新候选仍必须通过完整来源审核，不能把原文回传本身当作事实依据。

验证需要分别证明传输完整性和真实重写效果。应用测试覆盖首次拒绝到第二次作者调用、
原文与审核请求逐字相等、纠正栏与世界材料隔离、最终凭据及冷重放；
真实聊天另行核对原始供应商输入和最终交付，不能用前者宣称后者已可靠。
