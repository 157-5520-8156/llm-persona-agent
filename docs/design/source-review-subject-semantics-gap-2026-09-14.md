## 后续实验结论（2026-09-14）

新增的 `visible_source_subject_authority` 将来源持有者与陈述主体分开；原环境正例可以使用非个人主体，旧自述不能按 external_fact 支持经历，意图与生命周期仍不等于执行结果。证据说明实验增加了相对字段、合格来源枚举，以及拒绝分支无需补填支持性摘录的协议。

`visible_source_reading_experiment` 进一步让模型直接选择有权限的原文字段编号。主机保留完整原始来源和证明，精确还原编号、字段与正文；仅相同原文材料、持有者及完整权限集合的别名可以归并。全部语义材料仍展示，未按候选词筛选或删正文。v1保持原有用途，v2增加报告自然承接用途及按用途约束的来源选择，v3用显式空数组表示无证据选择。v1/v2冻结返回的12次重读结果与原先完全一致。

报告自然承接与客观事实确有区别：真实误拒理由明确要求为用户报告的出发经历提供独立客观证明。新增 `report_uptake` 消除了接口术语的混同，但**不能保证模型没有改换报告主体**。新协议下Flash、Pro均曾放行“你送我出发”，其说明却只复述来源中的用户家人送用户出发。另有落座反例被改标成 utterance_record；说明承认证据只能证明说过，仍把实际经历句判为通过。

这不是可通过再放宽来源权限解决的问题。当前输出主要解释“来源能证明什么”，却允许模型把候选句改读成较弱命题；自报用途标签无法证明候选句确实只表达该用途。下一步需要独立呈现并核对**候选实际命题、问句前提、角色指代与来源命题**，再作语义判决。代码仍只校验精确覆盖、身份、权限与引用，不能靠本地句式规则裁决语义。这个方向尚未实现，不应包装成已修复。

实验始终 `receipt_authority=false`。59项本地检查只验证结构与权限；本阶段27次真实调用保留全部失败。Pro对当前协议的6次调用仍失败，耗时4.3–10.8秒，不能用“更强模型”代替聊天验收。第一版条目请求压缩的大小数字仅适用于该冻结请求，不能推广到后续不同schema或月成本。

条目传输还复用了原证据说明消费者的1024字符摘录上限：遇到更长的合格字段直接报不支持，不截断或静默忽略。未专门建模的来源家族仍沿用实验的旧标量读取与主体约束。正式接线之前还需覆盖全部生产reader及协议/请求摘要身份，不能将这个有界原型直接当作v9审核替换器。

## 本轮证据

隔离聊天进行了三次自适应用户输入，交付八条消息。第一轮作者确实收到录取材料历史阅读，但角色选择暂不讲；不能再把该次不讲归因于未召回。第二轮校刊草稿添加无依据细节，被审核拒绝，同角色纠错超时。调度重试随后把用户自己的家人送用户出发，写成用户送角色出发，问句被 v8 判为 source_free 并交付。用户指出主语错误后，角色承认并纠正。

1. 原句：`你先说说你送我出发那会儿，家里什么样`。信息请求是当时家中情况；隐含前提是用户曾送角色出发。来源只支持用户家人送用户出发。Flash 和 Pro 的原 v8 请求均错误放行该前提。
2. 正例：`那你别光笑啊，你家里人送你出发那会儿什么样`。当前用户报告明确支持家人送用户出发；未知的家中情况只是问题请求的答案，不应要求已存在答案证据。强调前提检查的两版实验提示均拒绝此正例，因此不能直接上线。正例可以是具有合法来源的 closed，也可以在合适的问句表达分类下是 source_free；判为 unclosed 不合格。第一版实验有与失败样本相近的家庭例子，不是独立泛化验证。
3. 环境正例：灯修好、梯子车移走。Pro 能拒绝没有依据的角色落座，但把环境正例主体标成 none，现有消费者以主体不匹配拒绝整轮。这是可复现的协议/消费者冲突，不是一个可交付成功。
4. 证据说明实验的两层数字坐标导致实际返回选来源55却填材料15。可选相对字段路径传输消除了第二次材料选择；随后仍遇到环境 external_fact 与 environment 分类重叠，实验未合格。
5. 开启推理需使用供应商支持的 auto 工具选择；原 forced 请求获400，正确传输又超过11秒试验截止。不能据此延长普通交互截止或宣称推理模式可用。

## 已确认的代码边界与尚未证实的归因

`visible_life_source.settled_life_source_support` 返回 occurrence 的参与者作为第一项；环境正文并不因此断言该参与者实施了正文中的全部行为。
`visible_source_closure_protocol.compact_source_reference_table` 把该第一项写入 support_subject_role；解析器要求全部所选来源的此字段与整条 Beat 的 subject_role 一致，并拒绝 none。这个链条没有区分来源参与者和所描述命题的主体。

当前用户报告同样以 message.actor 作为支持主体。它有助于约束第一人称解释，但报告者可以讲述家人或第三方的行为。后续设计不能把报告者身份等同于全部嵌入命题的行为者。环境正例的硬拒绝已复现；暂不声称这一点单独解释了正例问句的模型误拒绝，后者仍需要独立对照。

## 下一实现必须满足的条件

- 独立表达来源持有者/报告者、原文中代词的解释基准、被检查命题的主体，以及来源的事件权限。模型判断语义对应关系；代码校验引用、字段、披露权限、事件身份和已声明绑定。
- 用户报告允许自然承接原报告，但不能改变行为者、对象、时间、肯否或事件状态；角色旧自述仍只证明说过，不能证明自述中的事件。
- 环境材料不能证明角色在场、执行或完成活动；绑定尝试结果只能证明该次执行中被记录的结果。
- 对问句分别检查请求的未知信息与已经预设的事实。不能默认问句无事实，也不能要求问题的答案预先存在。
- 不能通过允许所有来源匹配 general/none、删审核、修改旧返回或本地句式规则解决冲突。
- 新生产语义需要新的请求/协议身份，保留 v1–v8 冻结请求及历史回执的读取。当前实验结果不授予生产回执或 Action 权限。
- 验证必须成对覆盖：错误共享历史/有来源的用户历史、环境事实/角色在场、报告者/第三方、纯问题/带前提问题；随后再跑真实角色纠错和交付链，记录延迟及费用。
