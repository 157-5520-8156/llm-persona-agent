# P2：可恢复的增量故事导入

本轮基线ffdde4c6。用户已授权自行推进；沿用导入、审核、记忆读取公共接口测试。

先交付两条交织故事的闭环：.2修订/捕获恢复；在同一入口接受带既有历史版本的.3增量；
显式审核共享事件身份与跨故事关系；重复导入不写旧史、不重选记忆。工程代码不做相似度归并或剧情判断。

## 增量契约

新.3档案在manifest中保存import_context：既有同actor档案manifest pins、World原始启动坐标、
传记配置事件pins、确切的既有记录快照，以及作者提出的事件同一性和跨故事类型关系。
共享事件指向某个已接受记录中的明确event_ref；宿主沿既有已审映射生成稳定canonical_event_ref。
同名或时间接近不会自动成为同一事件。新旧个人回忆可对同一事件有不同、注明时点的理解。

审核输出必须逐项覆盖新记录、源稿内部边、共享事件判断与跨故事边，并明确跨记录阻断项。
新的审批绑定包含这些内容的完整manifest。首次导入在锁内核对历史与传记版本；变化则拒绝过期审批。
已完整导入的同一包重试仍幂等，即使世界后来继续发展。回放也核对接受时的版本和外部记录内容。

新关系可以从旧记录指向新记录，不改写旧记录。边由新档案的已审manifest授权，读取时仍检查两端
是否属于当前actor且可读；旧记忆已忘记时不借新边恢复旧正文。典型交集是同一事件后来被告知更多信息，
或后来对旧事形成新的解释；这不是重新发生了一次旧事件。

## 修订与恢复

已批准的记录除待重新审核的关联外保持内容、事件/知情时间、块及出处不变。
.2修订保留格式；旧typed关联要提供其实际捕获artifact以重建旧候选。
运行目录绑定完整请求，恢复不能换掉上一份审核。完成产物必须匹配捕获hash；已有响应不再次调用模型。
请求是否已计费不明确时停在可审计状态，不通过重试伪造成功。

## 验收

两条交织线分别导入；共享发生身份一致但知情时点和主观解释各自保留。
反例包括：第二份审批过期、源快照被改、错误actor、未审事件归并、漏审跨故事边、改写旧事件、遗忘/隐私穿透。
固定稿件与gold事件/知情/关系后独立抽取多次，另作语义比较；不把恢复同一捕获当作独立重现。

分章/覆盖计划必须保留原稿hash与确切字符范围，不能默默漏掉章节。首个实现继续尊重现有有界审核包，
超出整体证据预算明确失败；不声称已经解决任意长篇的分层全局审核。NPC和实时命运仍为下一阶段。

## 后续语义稳定性与成本约束（用户确认，2026-10-07）

用户接受事件/知情底稿方向，并强调大量记忆导入的成本必须可控。下面是后续实现和验收要求，
不代表当前入口已经具备人民币预算闸门、合并调用或批量角色保留。

### 实现顺序

1. 先冻结小规模语义gold与完整费用账本。按每万原稿字符、每百个经审核事实分别计费，
   同时报告片段数、接受/遗漏/拒绝情况。不能通过合并片段或删除难例使单位价格看起来更低。
   多次独立抽取和交叉审核用于开发及抽样资格验证，不作为每条日常导入的固定步骤。
2. 原子陈述是校验粒度，不是模型调用粒度。以证据预算内的完整场景/相关场景组批量处理。
   比较现有四阶段与“批量提取底稿和提出关系 + 一次独立逐项审核”两次正常调用候选方案；
   必须同时检验语义质量、总输入/输出token、缓存命中和尾部纠正费用，减少调用数不自动等于降费。
3. 已审底稿采用稳定引用，以本地编译生成记忆切片。修订只失效受影响的事实、权限、时间与关系
   的依赖闭包；原稿、历史基础、规则版本或证据变化时，不得沿用过期审批。批内局部修复仍需
   检查受影响的跨记录关系；不能只删掉一个拒绝项就假定余下的全局结论不变。
4. 避免每次向每个阶段重复发送全部旧历史。候选优化是固定身份/时间约束索引加高召回的相关
   原证据读取，再核对全局身份约束。摘要不能代替证据；检索覆盖无法确认时保持待审或补读，
   不把“没有检索到冲突”写成“证明没有冲突”。在扩到大量故事前独立验证该优化。
5. 初始保留选择单独做小批量CharacterInterior方案，与现有逐条路径比较。每条仍有明确的来源、
   自主决定、结果与恢复状态；不得由宿主自动全保留、全跳过，或固定删掉低分记忆省钱。
   这是新版本语义契约，旧初始化事件及其opportunity字节保持不变。
6. 增加单批与整次任务的可配置费用上限。发送前按固定价表、输入量和允许的输出上限做保守预留，
   将纠正纳入同一预算；未知计费不能释放为零。余额不足时保存进度并停止新增付费请求，
   已经完整捕获且可验证的结果仍能免费恢复。预算停止不是审核通过或角色沉默。

### 准入条件

固定测试集中的事实虚构、越权知情、错误事件合并和时间倒灌必须单列；关键错误不因便宜放行。
通过对照验证后才切换更便宜的正常路径，争议项允许一次有界复核，不能重试到碰巧获批。
当前小样本不能支撑千条/万条价格承诺；先报告实测端到端成本与规模增长曲线，再定长期预算。
