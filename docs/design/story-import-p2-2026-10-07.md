# P2：可恢复的增量故事导入

本轮基线ffdde4c6。用户已授权自行推进；沿用导入、审核、记忆读取公共接口测试。

先交付两条交织故事的闭环：.2修订/捕获恢复；在同一入口接受带既有历史版本的.3增量；
显式审核共享事件身份与跨故事关系；重复导入不写旧史、不重选记忆。工程代码不做相似度归并或剧情判断。

## 增量契约

新.3档案在manifest中保存import_context：既有同actor档案manifest pins、World原始启动坐标、
传记配置事件pins、确切的既有记录快照，以及作者提出的事件同一性和跨故事类型关系。
共享事件指向某个已接受记录中的明确event_ref；宿主沿既有已审映射生成稳定canonical_event_ref。
同名或时间接近不会自动成为同一事件。新旧个人回忆可对同一事件有不同、注明时点的理解。

审核输出必须逐项覆盖新记录、源稿内部边、共享事件判断与跨故事边，并明确跨记录阻断项。
新的审批绑定包含这些内容的完整manifest。首次导入在锁内核对历史与传记版本；变化则拒绝过期审批。
已完整导入的同一包重试仍幂等，即使世界后来继续发展。回放也核对接受时的版本和外部记录内容。

新关系可以从旧记录指向新记录，不改写旧记录。边由新档案的已审manifest授权，读取时仍检查两端
是否属于当前actor且可读；旧记忆已忘记时不借新边恢复旧正文。典型交集是同一事件后来被告知更多信息，
或后来对旧事形成新的解释；这不是重新发生了一次旧事件。

## 修订与恢复

已批准的记录除待重新审核的关联外保持内容、事件/知情时间、块及出处不变。
.2修订保留格式；旧typed关联要提供其实际捕获artifact以重建旧候选。
运行目录绑定完整请求，恢复不能换掉上一份审核。完成产物必须匹配捕获hash；已有响应不再次调用模型。
请求是否已计费不明确时停在可审计状态，不通过重试伪造成功。

## 验收

两条交织线分别导入；共享发生身份一致但知情时点和主观解释各自保留。
反例包括：第二份审批过期、源快照被改、错误actor、未审事件归并、漏审跨故事边、改写旧事件、遗忘/隐私穿透。
固定稿件与gold事件/知情/关系后独立抽取多次，另作语义比较；不把恢复同一捕获当作独立重现。

分章/覆盖计划必须保留原稿hash与确切字符范围，不能默默漏掉章节。首个实现继续尊重现有有界审核包，
超出整体证据预算明确失败；不声称已经解决任意长篇的分层全局审核。NPC和实时命运仍为下一阶段。
