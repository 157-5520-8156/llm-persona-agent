# 自传体记忆与生活联动：研究依据和实现提案

状态：讨论与设计提案，未实现、未生成完整人生、未修改生产。2026-09-29。
用户希望：有详略、情感色彩和人格影响的前二十年记忆，并让后续生活、选择、聊天持续
经过同一条链路。普通中文概括、省略和简短否认不按形式逻辑苛责；禁止凭空新增具体剧情。

## 判断

方向值得推进，但目标应是“一个人走到今天留下的记忆结构”，而非二十年的完整日志。
事件和记忆过薄确实会留下回答缺口；它不是全部编造的已证根因。此前生产副本已经出现
“找到正确记录仍扩写”及“复述自己编过的故事”。因此资料质量、检索、生成忠实性需分别验收。
新增12条前史已证明接入和保留链路可用，不能当成高质量人生记忆系统的完成形态。

“与人设契合”应解释为核心身份、年代和总体倾向一致，允许反例、矛盾、成长和不同关系中的
不同面貌。不能把所有童年经历都写成解释同一个爱好，也不能为每个性格特征安排一个伤害事件。

## 研究依据：发现不等于软件定律

| 一手资料 | 研究或理论支持的结论 | 本项目可以借鉴什么 |
|---|---|---|
| [Conway & Pleydell-Pearce, 2000](https://pubmed.ncbi.nlm.nih.gov/10789197/)，[论文全文](https://www.researchgate.net/profile/Martin-Conway-2/publication/12528554_The_Construction_of_Autobiographical_Memories_in_the_Self-Memory_System/links/0deec51babda329123000000/The-Construction-of-Autobiographical-Memories-in-the-Self-Memory-System.pdf) | Self-Memory System模型区分人生时期、一般事件、事件细节，并讨论当前目标与记忆建构的相互关系 | 使用层级和关联，而非孤立故事列表；这是经典理论模型，不是人脑数据库的完整实现图 |
| [Blagov & Singer, 2004](https://pubmed.ncbi.nlm.nih.gov/15102036/) | 自我定义记忆可从具体性、意义、内容和情感等维度研究 | “记得清楚”“对我重要”“影响现在”不要合成一个分数；重要记忆不一定所有细节都清楚 |
| [Talarico & Rubin, 2003](https://sites.lafayette.edu/talaricj/files/2009/09/TalaricoRubin2003.pdf) | 闪光灯记忆的鲜明度和确信感不等于更高的一致性 | 区分鲜明度、确信感、来源可靠性；不能用“刻骨铭心”给新编细节授权 |
| [Kensinger等, 2005](https://pubmed.ncbi.nlm.nih.gov/16029088/) | 在被测视觉任务中，情绪性中心信息和外围细节的记忆表现可不同 | 有选择地保存细节；不把每个重要事件都写成五感齐全的电影。不能将任务结果推广为所有情绪记忆的固定规则 |
| [Bauer, 2015](https://pmc.ncbi.nlm.nih.gov/articles/PMC4669902/) | 自传体记忆发展与遗忘有关，成人早年记忆稀少；幼年记忆不是按成年方式完整保存 | 早期多为模糊片段和家人转述，转述与亲历分开；不设所有角色通用的硬年龄阈值 |
| [Bluck等, 2005](https://scholars.duke.edu/publication/663788) | 研究自传体记忆的自我、社会和指导性用途 | 验收不只测回答往事，还要测当前自我理解、关系和选择；不要求每次把往事说出口 |
| [Schacter, Addis & Buckner, 2007](https://pubmed.ncbi.nlm.nih.gov/17700624/) | 讨论记忆与想象、预测未来之间的联系 | 旧经验可以成为当前预期的材料；不是“同一线索必然触发同一行为”的证明 |
| [Anderson & Schooler, 1991](https://journals.sagepub.com/doi/abs/10.1111/j.1467-9280.1991.tb00174.x) | 讨论记忆可及性与经历频率、近期性及分布的关系 | 可及性应动态变化，不只按年龄统一删记忆；不直接套用一个遗忘公式作完整人格模型 |

## 与当前代码的对应

- `world_consequence_contract.py:WorldConsequenceV2`已有环境正文和有执行绑定的个人结果，
  正文上限12000字符。问题并非数据库只能存一句话，而是生成内容、角色注意、保留和读取没有
  围绕可记忆事件共同设计。环境事实仍不等于角色看到、参加、做出反应。
- `character_life_response_contract.py:CharacterLifeResponsePayload`已有角色反应，允许null、
  正文上限4000字符；`Experience .2`已有外部结果与角色反应的组合读取。不能由World作者填她的感受。
- `character_prehistory.py:PrehistoryRecord`主要是时间、人物关联和一段至多1600字符的statement。
  它能承载正文，但尚无明确的人生时期、反复经历、主观意义变化、感官细节可及性等结构。
- `MemorySalienceVector`已有自传相关性、情绪余波、关系、复现、新奇性等维度，
  `MemoryCandidateValues`已有来源、提取强度和复核。不能据这些字段存在宣称联动已验收。
- `recall_attention.py`会把当前消息、感受、解读、关系和处境放进有界检索查询；
  `CharacterInterior`已有Recall与Appraisal/Affect能力，不需要另造一套平行大脑。
- `memory_retrieval.py`默认摘录480字符；已改善的生活Recall使用独立候选材料和窗口。
  `_prehistory_excerpt`目前直接取statement的前`max_excerpt_characters`，并标记truncated。
  不能把一千字重要记忆写入后，再固定截前480字而丢掉关键变化与结局。后续完整索引也必须
  只读取角色仍有权提取的记忆，不能为了修复截断而绕过遗忘/隐私去索引全部档案。
- `memory_consolidation_runtime.py`目前主要是到期保留/遗忘复核，不是成熟的分层语义压缩。
- `prehistory_memory_runtime.py`显式一次初始化一条；大规模档案直接沿用逐条完整上下文调用，
  会增加调用和重放成本。批处理应是后续优化，不能把本方案的低价当作该路径已经实现的价格。

## 目标表示：事实底稿、记忆与当下解读分开

### 人生的组织层次

以下数量是首版工程容量建议，不是心理学测得的人均数量。

- 5—8个人生时期：家庭环境、学校/居住变化、那个阶段的重要关系与关注点。
- 15—30组反复经历：一些相似的周末、相处方式、做事习惯和曾经持续一段时间的困扰。
- 40—80个具体片段：有长有短，有些只有一句，有些记得两三个细节。包含普通、愉快、不快、
  好笑、无聊、尴尬、能力增长、未解决的问题，不强迫正负各半。
- 其中8—12个重点记忆：是前一类中的子集，不额外重复计数；有足够的情境、转折、结果、
  人物关系和角色视角，另存完整材料，按需读取。

不是每年同样多，不是每个生日都必须发生大事，更不为了“有深度”强制安排创伤。
自我认识可以来自重复的小事；有些重要经历也长期没有漂亮总结。

### 一段经历至少区分三个对象

1. **发生了什么。** 角色/时间/场景、事件顺序、实际行动和结果、可感知细节及来源。
   NPC行为、角色行为、尚未执行的计划须分别授权；保留目前effect-once/CAS/回执。
2. **她记住了什么。** 她注意到的细节、主要印象、清晰和模糊的部分、当时自己的感受与理解。
   “我当时觉得自己不重要”不能升级成“别人就是故意不重视我”。
3. **她现在怎样理解。** 后来的反例、和解、重新评价、尚未放下的部分。这是可更新的角色解读，
   不修改原事件，也不强制继承过去的情绪到现在。

建议用少量稳定元数据加有来源的内容块扩展现有Memory模块，而非把几十个新必填字段塞进聊天协议。
至少需要期段/事件簇链接、原事件引用、历史主观视角、可回忆细节引用、关联线索、后续重新理解。
事实、角色解读和家人转述的读取用途要明确。旧发言只能证明说过，不自动成为人生事实。

记忆重构首先实现为选择、压缩、概括、侧重和不完全想起。当前减少编造的目标下，不主动加入
“随机记错事件/颜色/人物”机制。自然语言宽松与世界历史凭空变化是两个不同问题。

## 一个联动设计例：不是给当前生产角色新增的事实

假设某角色的一次生日约会中，朋友迟到，她在店里等了很久；后来两人见到了面。
事实材料保留谁来、何时来、已发生的行动。她可能记得纸盒上黏住的糖霜，却忘了店名。
当时她把等待理解为自己不被重视，这只是她的读法；另一些后来被认真对待的经历可成为反例。

若现在有人含糊地说“到时再看”，检索可以把这段记忆及反例带入候选。角色自己判断是否相关、
现在是否担心、要不要确认时间、继续信任、保持沉默或换个安排。表现可能只是一句希望确定时间
的话，不必每次复述生日或输出心理分析。

代码不能写成“生日关键词 -> 唤醒伤痛 -> 焦虑80 -> 追问”。检索可以提供机会和材料；
动机、意义、情绪、措辞、是否行动仍归CharacterInterior。

## 可复现的生成过程

输入包：角色核心资料、正式年代/地域/身份约束、当前世界启动边界、语言、人生风格要求、
随机种子、生成器/提示/schema版本和总token预算。核心资料是约束，不是要求每个故事都验证同一性格。

阶段：
1. 生成时期骨架、少量历史人物和持续关系；只进行结构、年代和身份校验。
2. 生成关联的事件簇：包括能塑造某个倾向的经历及反例，不把每个特质写成单一原因。
3. 为候选片段选择记录深度；扩写少量重点，其余保持短，允许无结论、无意义和未完成。
4. 独立核对跨时期一致性、关系身份、事件先后、世界边界、角色行动权限及整体生活感。
   发现问题只重做相关分支，不反复重写整个人生。
5. 同一角色模型形成/保留自己的记忆和当前理解；导入事实不等于全部保持鲜活，不能自动激活全部负面情绪。
6. 生成检索索引和摘要，保存原文可追溯引用；用问题和选择场景验收完整链路。

保存每阶段的规范化输入、原始输出、模型实际身份、版本、参数、种子、关系图、哈希、审阅与接受结果。
“完全重现同一人生”靠保存并重放这些产物；仅凭相同seed/temperature=0不能保证远端LLM逐字相同。
不同角色使用相同生成流程、不同输入和独立World/actor命名空间，不复用上一个角色的记忆实例。

已认可的当前12条v1前史是既有历史，不静默覆写成新故事。新版本先在隔离世界验收，保留旧格式读取。

## 后续生活如何保持同样质量

World作者提供足够的外部情境和已授权行动结果；CharacterInterior决定看见/在意什么，以及是否保留。
普通事件可以短而具体，重要事件需要能解释变化的前因后果，不把重要等同长篇景物描写。
优先丰富现有World作者和角色反应调用的内容，避免每个小事件再新增两三个模型步骤。

原始事件库可以完整，工作记忆和给模型的材料必须有界：
- 首先提供短的相关记忆概括及精确来源；需要时读同一条的细节。
- 对重点记忆按照内容块选择，不机械截断开头，不把“没展示”当成“没有发生”。
- 角色选择的理解、保留和后续评价写回已有Memory/Appraisal/Affect等通道。
- 回忆时的当前反应可以影响计划、关系判断、联系/沉默和话语；回忆不必外显复述。
- 历史人物只有档案身份时，不自动变成可以发消息的当前NPC。

## 成本与开销

[DeepSeek官方价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)于本次查询显示：
当前deepseek-flash为V4.1；高峰每百万token非缓存输入2元、输出8元，缓存输入0.04元。
按不依赖缓存的保守单价，**累计100万输入+10万输出=2.8元**；同样用量发生三遍是8.4元。
这是用量假设下的算术，不是已经生成高质量人生的实测报价，不含embedding、人工审阅、工程成本。

因此“一次性做一份有限、分层的人生档案”不必昂贵；应先把生成、独立复核和初始化的总量封顶测量，
再给每角色报价。不能把二十年逐小时调用模型，也不能每条初始化都重发完整人生上下文。

持续运行的成本风险更大：每轮把全部记忆塞给模型、反复重写同一记忆、为微小事件多加模型调用。
采用稳定前缀缓存、分批初始化、仅对变化部分复核、相关摘要与细节按需读取；保持生活机会和回复质量，
不靠减少互动频率或预算拒绝来宣称省钱。一次性初始化费用和每日运行费用分别统计，未知账单不当零。

## 首个可验收切片

不先生产几百条故事。先做一个角色的3个人生时期、12条普通片段、其中3条重点记忆和若干反例关联，
覆盖正向、不快、平常关系以及同一经历后来被重新理解。数字只是试验大小。

必须测四类东西：
1. **同事实、不同表示。** 原始内容相同，比较扁平叙述与分层读取，避免把新增答案当作降低编造。
2. **历史作用。** 同一当下选择在不同、分别成立的前史副本中对照；保持模型和当前处境相同。
   检查记忆是否被提供/注意/采用、是否形成当前Appraisal、是否影响实际选择；不要求每次焦虑或拒绝。
3. **长期与修正。** 加速跨日验证遗忘、概括、反例、关系变化和旧错误自述污染；重启后回放一致。
4. **有用与自然。** 事实召回、无新剧情、合理中文表达、没有每次讲往事、人格总体一致但有情境差异，
   以及真实首条交付、调用次数、一次性/每日成本分别记录。

若完整链路没有显示记忆影响选择，或细节仍在读取时丢失，就先修命中的接口，停止扩大生成规模。
这份提案不证明生成幻觉率已经下降，也不作为当前版本的发布资格结论。
