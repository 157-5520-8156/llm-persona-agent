# closed 裁决必须携带模型选择的来源

[第 16 批](../audits/launch-visible-source-trial16-2026-09-09.md)真实 reviewer 判 closed，
却给了空来源数组。原用户报告已在请求里。问题是 provider 返回结构允许表达一个
宿主不会接受的组合，不是缺少新的角色行为规则。

独立显式 reviewer v3 为 `decisions` 的每一项提供三个完整结构分支：

| 模型选择 | 来源字段 | 归一化 |
| --- | --- | --- |
| closed | 必填整数 `first_source_ref_index` 和数组 `additional_source_ref_indexes` | 按模型给定顺序合并为原 `source_ref_indexes`，至少一条、至多八条 |
| source_free | 没有来源字段 | 空数组 |
| unclosed | 没有来源字段 | 空数组，仍须 v2 原有拒绝诊断 |

模型拥有语义判断与来源选择权。宿主只转换已选择的结构，并继续执行原完整 Beat
覆盖、引用范围、重复、actor、材料可读性、事实时态/状态与权限校验。不凭给出了一个
整数就认为陈述为真，不修补遗漏的来源，不把其他主体材料变成角色经历。

工具使用既有 strict subset 的嵌套 `anyOf` 和完整 object；不依赖不支持的数组
`minItems` 或 `prefixItems` 来声称供应商能保证非空。新的数组分支仍需实际供应商
资格。v1/v2 的 schema、prompt、请求、回执和冷验证字节保持；新工具、请求准备和
回执分别为 `.3`，旧归一裁决和反馈数据不变。原 full-review policy/来源表/能力
及 ModelResultAudit 不扩权。

producer 与 consumer 均需覆盖入站、主动、原角色一次纠正、完整重审、冷恢复及
跨版本伪造反例。版本显式选择，默认 v1 保持；reviewer 1/2/3 独立于作者 1/2/3。
不添加审核重试、第三次作者请求或更长 deadline，实际 schema 字节照常计入费用预留。

## 已验证范围

协议与诊断的 root 联测 108 项通过；receipt、真实形状的入站、纠正和配置接线联测
93 项通过，主动表达和冷恢复 16 项通过，完整重新编译的跨版本伪造 7 项通过。
这些组有重叠，不相加作为唯一测试数。模拟第 16 批候选时，合法返回可被接受；缺少
首个来源、旧空数组及主体错误均不能产生 Action，已完成的两次物理调用仍各自计费。

独立冻结验证保留 v1 原请求、工具、准备与回执字节；v2 另冻结 21 份材料和两条冷恢复链，
28 个 v1/v2 解析正反例保持原结果。独立 21 个 v3 反例验证来源与主体边界。
Schema 保证 closed 必须提供首个整数，但来源上限、去重、范围及资格仍由原 parser
检查，不能声称供应商 schema 已保证这些性质。

目前都是无网络调用替身及冻结原件的离线证据。真实供应商是否支持该数组分支、
实际来源选择质量、完整多轮交付和月度费用仍待资格，生产默认保持 v1。
