# 来源审核中的记录依赖

状态：显式 v21 实验合同；`manual_only / qualification_incomplete`。

六例真实 v20 对照有一项元话语误拒。两份读取均保留了完整原句；来源模型明确解释
该句是当前发言的说明、无需外部记录，也将其列入 `non_record_expressions`。但逐命题
接口要求 `assertion_status=asserted`，宿主随即把 `source_support=false` 解释成拒绝。
“正在作一个断言”与“必须用既有记录证明”在这里发生了混淆。

## 接口

显式 v21 保留两个独立的 v16 读取器、完整原句、全部固定命题坐标与来源权限。
仅来源合同升级为 `visible-contextual-source-review.5`，用逐命题 `record_dependency`
替换 `assertion_status`：

- `record_bound`：语境实际承担的记录依赖命题。继续核验正文支持、角色、时间、
  字段权限和接受 Fact 的精确值；没有来源不能通过。
- `not_record_bound`：无需先前记录的当前表达、元话语或未作实际断言的内容。
  必须 `source_support=false`，两种引用列表均为空；不产生新的 World 事实权限。
- `uncertain`：记录依赖仍不确定。没有明确拒绝时是技术失败；与明确拒绝并存时，
  可以把拒绝理由交给同一角色一次纠正，随后完整重审。

分类由读取完整语境的模型决定。宿主不分析角色用词、审核解释或匹配文本列表来替换
模型的结构化结果。当前表达中的独立过去经历、已交付言语、习惯和外部事实仍需来源；
引用某句话不会证明它为真或以前说过。逐气泡的遗漏检查继续执行，包括两个读取器都
没有列出任何事实的情况。

## 兼容与验证

v1—v20 原请求、回执与原始拒绝结果保持原编译。新版本具有独立协议和回执身份，
同一候选、来源、读法、实际调用哈希继续精确绑定。编译缓存只复用不可变请求 JSON，
新合同和编译器身份进入缓存键；审核判定、回执验权和完整正文检查不缓存。

本地测试验证接口边界、错误主体/值、遗漏、冲突读法、不确定、冷回执与旧编译字节。
这些测试不证明模型语义可靠。真实复测应保留六例实际读取结果，仅重新调用来源阶段，
再以新候选运行完整角色对话；来源阶段对照与完整聊天分别报告。
