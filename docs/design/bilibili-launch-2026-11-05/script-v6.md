### 全片硬规则

1. **聊天必须用真实原文**。只允许做两种处理：删节，用「（中间略）」分隔条标出；按画面需要换行。保留她不加标点、用空格断句的原始风格。时间戳以 QQ 实际显示为准（见第 5 节 T-1）。
2. **每段都要说清结论**。旁白直接讲「这说明什么」，不让观众自己猜。留白只放在三处：S3 末「她的晚饭不等」后、S5 骰子冷笑话后、S7 全段。
3. **主张卡是发布会的骨架**，样式统一（2.3 节），每张都要读得完。
4. **画面元素准入**：只放旁白正在讲的东西、聊天原文、真实 Dashboard 截图、她二十年前史的原文。不放装饰性英文、编号或哈希值。
5. **零黑话**：不出现「事件」「账本」「词元」「溯源」「occurrence」等词。唯一保留的术语是「视锥剔除」，用画面直接演出来。
6. **措辞边界（AGENTS.md）**：不说「规则让她这样说」，也不说「前史导致了这句话」。只说世界给了她什么环境和经历，怎么说由她自己决定。命运线不能说成「掷骰子」：结果既有随机，也受她自己的行为影响。

## 2. 画面工艺标准（v5 的失败点，必须逐条满足）

### 2.1 镜头

1. **镜头之间直接切**，不再用 6400px 长桌一镜到底。切换用 8–12 帧的「纸滑入」：新卡片从画外滑入，压住旧卡片。镜头**禁止**横穿空桌面。
2. **每个镜头最多一个运镜动作**：推、拉、侧摇、翻面里选一个。
3. **透视常驻**：桌面始终保持 rx 16°–30° 的俯角；只有主张卡和 S0/S7 的暗场字幕可以正对镜头。
4. **构图**：主体落在画面中央 70% 的安全区内；主体之外，画面里的空白纸面不超过 30%。前景（虚化的上一张卡）、中景（主体）、背景（桌面纹理与淡色网格）三层同时在画面里。
5. **镜头运动只在停留关键帧之间插值**，每段运镜时长不超过 1.2s，用 `Easing.bezier(0.33, 1, 0.68, 1)`。

### 2.2 字号（1080p 实际像素，计入镜头缩放后）

| 元素 | 最小字号 |
|---|---|
| 聊天正文 | 30px |
| 时间戳 / 小标签 | 20px |
| 底部旁白字幕 | 36px，暖白字 + 深色半透明底 |
| 主张卡 | 88–104px 宋体 |

### 2.3 主张卡

- 满屏暖纸底 `#F2EEE6`，宋体墨色大字居中，单行（最多两行）。
- 入场：字从 Z −80 落到 0（12 帧，轻回弹），随后一条橙色细线从左往右画在字下（18 帧）。
- 停留不少于 2.5s。配一声低沉的纸张落下音，**不配旁白**（字自己说话）。
- 出场：整张卡向上翻走，露出下一段。

### 2.4 Dashboard 截图

- **不能直接贴深色截图**：外面套一张浅色衬纸卡片（12px 白边加纸阴影），截图本身亮度提升 15%。
- 截图出现 0.6s 后，镜头推近到要讲的那一块，并用橙框圈出；全图只停 0.6s，大部分时间看局部。
- 截图上方一行小字：「实际运行界面」。

### 2.5 聊天卡

- 统一一个简洁样式：她在左（暖白底，带头像 `avatar_zhizhi.png`），我在右（墨蓝 `#2B4C7E` 底白字）。
- 卡片顶部是日期时间（「11/4 周三 11:45」），删节处用「（中间略）」细分隔条。
- 一张卡最多 6 条气泡，超过就拆成两张。

### 2.6 验收（每段都做，不过就不进入下一段）

1. 每段渲染后**每秒抽一帧**拼成总览图，逐张检查：主体是否在安全区内、有没有切边、空白纸面是否超过 30%、字号是否达标。
2. 运镜区间额外每 5 帧抽一帧检查。
3. 主张卡和读气泡的时长：用秒表实际读一遍，读不完就加时长。
4. 全片拼接后再整体看一遍节奏，记录每段实际时长回填第 0 节。
