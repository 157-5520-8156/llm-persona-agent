# 时间密集的阶段故事：内容、形成和导入

状态：用户提出的下一方向；本文件是基于现有代码的实施设计，尚未导入新历史或实现新协议。
基线：`44d8b889`；承接 `long-horizon-story-system-2026-10-07.md` 和 `scene-recall-qualification-2026-10-08.md`。

## 当前缺口

“前二十年完整”目前指从出生至二十岁都有分期源稿，不代表每个生活阶段已经具有足够连续的经历。当前仍偏重跨年的节点、物件回声与关系变化。

实际源稿 `configs/prehistory/native-first-twenty-years-20261008/source.json` 有59个新场景、122块。57个场景的发生范围宽度在7—31天，另2个不足2天；这些通常表示日期精度，**不表示该事件连续发生了一个月**。28条显式跨场景关系中，仅一条两端日期范围的最小间隔不超过31天，其余间隔更长。该统计仅覆盖新源稿显式边，不包含旧72条记录、自动同场景连接或未显式编码的语义联系。

旧档案也有局部密集过程。例如 `celia-expanded-growing-g07` 已写到：合作准备几天、改动提案、落选、推责任、几天后归还东西和下一次组队；`g10` 有问话、争执、几天减少交流和截止前核对材料。问题不全是内容不存在，还有多次发生压缩进一条记录、缺少独立过程坐标。

许桥线有关系张力，但已检查的人设与源稿没有确立恋爱、表白、分手或前任身份。不能据亲近、吃醋式表现或沉默直接认定双方恋爱。新的感情故事可以创作，但身份、双方知情与实际关系变化必须明确作为新来源，不把解释冒充旧事实。

## 应增加的中间尺度

采用“人生阶段—阶段故事—具体发生”的多尺度组织：

- 人生阶段：高中、升学、大学等，提供背景和时间范围。
- 阶段故事：持续几天、几周或数月的共同处境，可以有反复、停顿、重新开始和暂未解决的后果。
- 具体发生：一次交谈、一次修改、一晚等待、一项完成/取消、一次后来获知。日期可不精确；已知先后顺序和日期精度分别保留。

时间密集不等于每天记录，也不等于每天制造冲突。只有改变事情走向或体现生活质地的具体发生需要展开，普通相处、重复、空白和自然搁置也有位置。两次平常事件的共同处境可以成立，不强求每一节点构成因果链。

## 复用与新增

现有 `NativeStoryScene`、角色知情区间、同场景/后续/披露/回调关系、纯编译与导入回执可复用。`.16` 能补齐场景和多入口，但没有完整的阶段故事读取协议；6条返回预算不能自动承担一段20场景故事的所有细节。

下一层应集中在一个阶段故事模块，以小接口承担以下行为，避免把新规则散入作者、导入器、检索器和各角色提示：

1. **源稿中的阶段容器与成员引用。** 持久标识、版本、覆盖区间、已有/新增事件成员、来源；一件事只发生一次，可以同时属于校刊、友情和家庭线。关系变化与未结事项引用已有事实/承诺/结算来源，不在容器中另造一套权威状态。
2. **过程顺序与知情分开。** 同一天上午、午后、晚上可以有不同发生；只知道“之后几天”的保留相对顺序，不伪造时刻。预期、实际结果、当时理解和后来获知分别记录，不能把后来的答案倒灌给先前的角色。
3. **增量细化。** 现有发生只引用，不重新生成另一个身份。补充未写的前后过程，需绑定最新已接受历史并留下增量来源。当前native编译器会拒绝重复声明已接受event_ref；不能简单给原事件换ID绕过去。将旧复合记录拆成过程视图时，优先从原文定位子片段，保留原记录及其依据，不重复制造一段经历。
4. **分层读取。** 先给该角色当前可读的阶段概览、主要进展和未决事项，再按问题进入某一天/某件事的原文；概览是可重建的来源视图，不是独立事实。未读的后续保留为未知。索引、标题、成员数和摘要均不得暴露私有支线；遗忘和历史视角同样适用。

不立即设计第二个事实库或独立命运调度器。既有长期线设计中的权威、版本和来源要求继续适用。

## 形成与导入

历史创作流程：固定既有世界与创作区间 → 按同一阶段连续编写结构化场景 → 确定性编译为事件/知情/关系增量 → 角色自主保留 → 构建有来源的阶段读取视图。

连续写作时携带“截至这一刻已经发生和已经知道什么”的来源清单、角色可访问状态与未决事项，减少各场景独立生成后再强行拼接。清单只提供环境，不指定角色必须采取的动作、情绪或和解结局。模型负责语义和创作，代码检查身份、引用、确切时序冲突、权限、预算和effect-once；不增加每批必需的独立模型审核。

未来生活流程：既有World产生并结算事件 → 角色形成记忆和私人理解 → 更新受影响的阶段视图。未发生的故事设想仍是候选；实际拒绝、延期和不参与可以改变后续，不能把预写剧本提前导入成事实。

## 成本先行

当前 `PrehistoryMemoryRuntime.advance_once()` 按单条源记录调用角色：上一轮118条可读记录用了118次保留调用。源稿加密后若保持这一方式，开销与片段数一起增长，因此大规模补写前应验证有界批量保留。

拟议批量方式：一次提供一个可完整读取的小场景组，让同一角色对每条来源分别决定保留/略过；保存逐项决定、源绑定和独立效果。不能把整组强制保留，也不能把模型漏答项当作略过。恢复仅处理未完成项，完整响应恢复不再付费；缺失用量继续占用预算。

用总输入/输出token、实际费用、失败、保留选择差异和读取质量比较批量与逐条方式；减少调用次数不自动等于减少费用或保持质量。对既有记忆只做必要增量，摘要只更新受影响部分，不把更密的记录全塞进每轮聊天。

## 第一份可验证交付

优先选择高中阶段已经成立的 **2024年1月校刊改稿** 作为锚点（`p6-01-a/b/c`），构造约2—3周、约12—18个具体场景的有界试稿。范围和数量是开发样例规模，不是生产生活配额。实际日期和与旧档案的重合须在编写前固定；现有事实不改写。

让同一次交稿期与备考/普通课堂生活、许桥的相处、家庭书店生活自然交织；允许有些场景与交稿无关。成果首先证明一段生活有过程和后续影响。感情线随后可以采用相同机制，但不要求固定“相识—相恋—分手”套路，也不把现有许桥线擅自改成恋爱。

最小验收：

- 从事件或人物两个入口读同一段生活，能定位问题所需的具体经过与后续依据。
- 按某一天回看时，不知道后来的结果；日期不明确时不伪造精度。
- 一次共同事件不因属于不同故事而重复；补写不覆盖旧承诺、结果或原文。
- 来源缺失、遗忘、私有线、漏答和技术失败不会被摘要掩盖。
- 正确材料与自动检索材料的复述分别测；数量、当前状态、说话人和未知后续仍沿用已有失败对照。
- 同包重放不重复付费或写入；单场景修订只重算受影响部分，实际成本完整入账。

这是内容和机制共同推进的一份试稿，不是将整段高中或全部恋爱经历一次补齐。生成忠实性问题保持独立验收，不能用增加故事量宣布解决。
