# 增量上下文材料与共享检索计算

基线b69d120e。只实现已授权的前两项：当前Context的检索资料增量准备、同一pinned snapshot下本地/语义检索共用基础计算。不改变模型输入范围、记忆覆盖、排序和预算、生活频率、时限、审核策略、来源/权限/角色语义；不进行提交合并或提前发送。

- 所有当前来源检查仍执行。纯文档材料以完整输入身份复用，任何内容、来源、隐私、时间、故事依赖变化均重新物化；可变或不支持的值不缓存。缓存有限并可丢弃，不是事实/权限来源。
- SQLite派生索引以专属变更代次识别文档/索引头变化，普通账本追加不会导致全索引重读。外部索引写入、删除、更新及失败事务必须反映到代次。只序列化并写入变化的文档，原canonical集合hash保持。读快照和代次须一致；写入前重验并处理竞争，旧pinned对象不被新代次修改。冷路径和超容量必须保留全量正确回退。
- 本地和语义检索只共享相同文档、策略和完整query依赖下的资格/故事处理/词法计算。向量、语义注意力、最终评分、选择和trace各自不变。共享计算不等待向量网络，不删除本地兜底。并发构建、不同主体/隐私/时钟/窗口、变更文档必须隔离。
- 先红绿回归，再完整库同源Context/corpus与两种检索逐结果/来源/trace等价，最后无profile的原生入站请求待发及回复回放。阻断网络，复用现成向量；不把旧响应回放当成新模型语义通过。最终代码复核、冻结、全量一次、核对SHA并提交。

参考与未采用方案见docs/research/local-latency-primary-patterns-2026-10-12.md。若只减少部分材料的重复计算而尚未形成整个Context的依赖图，应在最终证据中明确范围，不声称所有准备已变为O(变更量)。
