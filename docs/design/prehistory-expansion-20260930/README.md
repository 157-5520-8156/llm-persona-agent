## 几条值得先看的经历

- **F09：2018年的生日。** 蛋糕有一边奶油粘在盒壁，她先想拍好看；父母唱乱生日歌，她边纠正边笑，笑灭一根蜡烛。最后照片留下漂亮半边，录像却没重拍。愿望内容已模糊，录像现在是否仍有文件也未设定。
- **F01→F07→F19：会响、进水、卡死的计时器。** 从小时候嫌响、弄坏后父亲修理，到多年后厨房改用手机。最后一次看见它在窗边，不替父亲写“舍不得”，也不杜撰它后来的去处。
- **G10→G16→G19→G20：没有撒谎，却选择少说一句。** 她知道许桥提前说过要走，却赌气不替同学补充；后来没有当场说清，毕业后慢慢少联系。重见时提起以前的过错，对方没有给她一个现成的圆满结局。
- **U10→U11→U13→U14→U15→U20：共同做事并不代表理解彼此。** 确认参与者拖到最后一晚、临时改图、各自觉得付出没被看见。两人也继续吃饭、分享零食，后来愿意再做，最终暂时收摊；未来是否重开没有定。

这些经历是处境与历史，不是“以后遇到X就必须生气/沉默/拒绝”的程序规则。

## 产物如何使用

- `stories.md`：只含按故事顺序排列的原文、场景ID和时间，不混入两份重复记忆。供阅读以及后续现有抽取器使用。
- `family.json` / `growing.json` / `university.json`：本轮编辑源文件，包含原文、候选回忆、本人理解、未知信息、关联建议。
- `bundle.json`：合并后的60条、源文件路径与SHA-256。格式为 `creative-prehistory-bundle.1`，**不是可直接配置到生产的 ReviewedPrehistoryArchive**。
- `related_ids` / `existing_links`：作者给出的阅读和审核导航，不是已获批准的因果边、NPC权限或知情授权。后续正式转换仍须按原文重新建立合规关联。
- `validation.json`：本地结构检查结果，不能替代内容批准。三份 `review-*.md` 保留交叉审阅时的发现，[修订与验证记录](review-resolution.md)说明哪些已改、哪些未采纳。

创作时原文已通过现有 `source_segments()` 输入边界检查。导入时另按三条故事各自冻结原文和操作者整理的材料，绑定真实生产brief，由独立模型逐条审核后导入60条。不是重新调用模型从裸小说自动抽取；本批导入证据不替代通用抽取器的规模验证。

## 重建

在仓库根目录运行：

```sh
python docs/design/prehistory-expansion-20260930/build_bundle.py
```

脚本只读取这三份编辑JSON，检查60个唯一ID、必要字段、出生/入学/截止日期、关联可解析、无完全相同的正文，再重建阅读视图和合并包。它不会调用模型、连接数据库、导入记忆或发送QQ。原文和JSON并存，修订JSON后须重建，避免阅读稿与候选分叉。
