# 录制清单与素材验收

## 1. 素材优先级

先取得 B、C、D 三条连续案例，再补 E、F、G。没有连续案例时，先做项目阶段展示，不用多个孤立的成功句子宣称长期陪伴已经成立。

| ID | 要拍什么 | 最小完整证据 | 当前状态 | 不满足时 |
|---|---|---|---|---|
| A | 6–8 秒开场 | 一条真实收到的自然消息或语音，加上下文 | 待选真实片段 | 用生活画面和问题开场 |
| B | 生活先发生、聊天后提及 | 一个计划/事件、已结算结果、角色经历、稍后普通聊天 | 账本有早餐/课程等候选；聊天闭环待取材 | 只展示生活记录，不冒充 QQ 对话 |
| C | 跨日记忆 | 早先原始互动、之后间接提问、实际回答、来源核对 | 检索实现与历史试验存在；本片案例待录 | 改讲机制，删去成功演示口吻 |
| D | 关系/态度影响后续互动 | 前因、后续表达、同轮状态、真实发送时间 | 机制和状态存在；待筛连续样本 | 不用单条撒娇充当证明 |
| E | 双向语音 | 角色可用转写、QQ 收到语音、手机或客户端能播放 | 有 4 份本地合成文件，未做本轮 QQ 播放验收 | 用已有授权普通语音并明确历史节选 |
| F | 与生活相关的照片 | 生活来源、媒体选择、生成文件、对应分享回执、收图界面 | 主世界有 6 条分享记录；待逐条选图核验 | 不展示“口头承诺了但没发”的片段 |
| G | B 站见闻与分享 | 实际读取范围、角色感知、真实聊天分享 | 有 142 条感知投影，分享样本待匹配 | 只展示“她注意到什么” |
| H | 生活线路与未来可能 | 当前真实快照，明确已发生/候选；展示一个现有来源链接 | 当前源码可渲染；线上读取待确认 | 用标注日期的历史快照 |
| I | 简单机制图 | 四步概念图，与实际代码职责一致 | 可直接按脚本制作 | 不扩成技术讲座 |
| J | 结尾状态卡 | 当前项目阶段、用户决定的开放方式 | 公开方式未定 | 只写持续开发，不许诺下载 |

不进入主片的现阶段素材：寄送交互的“自主送礼”演示、未经对账的成本表、未经实机验收的安装过程、合成测试夹具中的成功对话。

## 2. 三条主线怎样录

### B：生活连续性

1. 从已发生的普通生活事件中选一件；先记录来源时间、状态与结果，避免先写好理想答案。
2. 保留这件事发生前后对应的完整记录。不能把 `planned` 或未来候选拍成完成记录。
3. 稍后在正常聊天中自然询问近况，记录她实际怎样表达。问题不要包含事件的正确答案。
4. 核对时间、对象、动作与结果；未提起该事也是一种结果。可以选其他真实片段，但保留本次尝试，不把选片数量说成成功率。
5. 最终画面只保留观众需要的信息：事件简述、两处时间、几条聊天。来源 ID 存在内部素材卡，不堆到主片。

候选已有记录：11 月 3 日早饭由肉包售罄转为糖包、古代汉语课、午饭与晚间宿舍通知。选择最普通、最容易核对的一件即可；不需要人为制造戏剧冲突。

### C：跨日记忆

1. 选一段无敏感个人信息的早先互动，确保确实存入可用记忆。
2. 经过其他话题和真实时间后，以间接线索问起，不在提问里泄露答案。
3. 保留整个回答，而不是只剪准确的半句。核对是否添了源材料没有的细节。
4. 若系统使用预置前史，字幕写“角色前史回忆”；只有来源是运行期间共同互动，才写“共同经历”。
5. 若使用固定问题反复录制，内部素材卡记录尝试次数；成片不标榜一遍成功。

### D：关系与主动性

1. 从已有日常交流选取一个有前后文的片段，不为了视频要求角色必须爱、嫉妒、生气或撒娇。
2. 保留角色表达前可用的生活状态、最近对话与同轮输出，核对实际送达。
3. 如声称主动联系，确认前面没有用户的新消息、人工催发或直接强制 dispatch；追踪触发类别，排除仅是故障重试。
4. 如果没有回复，只有明确的角色决定才能称为沉默；claimed、超时、发送失败均不可包装成个性。
5. 情绪和关系数字最多辅助出现一次，主要让观众从语言与前后变化感受差别。

## 3. 每条素材的内部卡片

每个片段记录以下字段即可，使用 Markdown 或剪辑备注，不必把整份生产数据库复制到素材目录。

```text
素材 ID：B-01
取材日期 / 时间 / 时区：
素材性质：实际运行 / 历史运行节选 / 离线回放 / 测试夹具 / 机制示意
代码提交与本地修改快照：
可识别的模型与配置版本：
世界游标、事件 / 回合 / Action / 回执定位：
角色读到了什么、哪些材料没提供：
用户的输入：
角色完整输出及实际交付结果：
成功之处与错误 / 失败 / 不确定之处：
是否存在重试、挑选多次、人工干预：
原始录屏文件与使用的入点 / 出点：
公开前脱敏范围：
配套旁白需要成立的那一句话：
```

素材入选原则：配套旁白所说的内容，能够被这一个片段直接支持。不要让“视频里能看到一个数值”承担“数值真的影响了行为”的证明。

## 4. 录屏与画面安排

建议工作规格：1920×1080、30 fps、16:9；这是制作起点，不是平台强制参数。先录 30 秒样片，缩到手机尺寸检查字幕、聊天和鼠标动作，再批量录制。

- QQ 实际接收界面用于证明表达与交付；Dashboard 用于解释生活和记忆，二者承担不同用途。
- 每个段落先一眼看全，再裁切到一条消息或一个状态。多数观众无需看见全部导航和调试字段。
- 聊天气泡别小到需要暂停才能读完；旁白与读字发生冲突时，宁可少讲一句。
- 原生语音播放时保留播放按钮和时长，关闭旁白。音量以正常说话舒服可听为准，避免靠强压缩制造“贴耳”噱头。
- 视频里的项目时间与录制时间分开。Dashboard 使用世界北京时间；真实录制时间写清时区，避免跨天画面被误读。
- 可以使用页面“暂停画面”以便讲解，但字幕注明冻结快照；该按钮不暂停角色后台运行。
- “演示模式”不等于匿名化。心声区、头像、昵称、聊天、路径和侧栏都要逐画面检查。
- 本轮本地夹具预览仅用于判断构图，不是最终视频素材。它的“同步正常”等状态都是测试数据。

## 5. 发布前只核对具体承诺

当前制作范围不包含发布到 B 站。投稿前需完成：

1. 按成片实际内容填平台生成内容声明；此处未取得完整平台规则，不能把本清单当成合规结论。
2. 标注虚构 AI 角色、AI 语音/图像、历史节选或机制示意。重排聊天与原始 QQ 截图分开称呼。
3. 从公开录屏中去除账号、联系方式、用户私人经历、密钥、后台路径及无关窗口；第三方消息和素材仅使用有权公开的部分。
4. 片中成本、延迟、成功率只保留有测量口径的数字；暂不填任何“月成本 100 元”“秒回”“永不遗忘”。
5. 开源、下载、招募、收费与更新时间由用户定案。现阶段脚本没有预设这些承诺。

## 6. 下一轮制作顺序

1. 确认可用的录制服务与 Dashboard 状态；当前健康读取超时尚未诊断。
2. 从已有记录确定 B/C/D 三个案例，先取材，再把脚本中的现场指代改成准确事实。
3. 完成 45–60 秒开场样片：真实片段、问题、项目名、第一次生活证据。
4. 按同一视觉规格录完其余章节，旁白试读计时，删去重复解释。
5. 对照素材卡完成粗剪、字幕、声音与事实检查，形成可供用户审看的成片。

本轮没有为取材发送消息或调用付费模型。未来如需新跑真实案例，应先具体列明使用哪个隔离或生产环境、接收对象与试验预算，再执行已经明确授权的范围。
