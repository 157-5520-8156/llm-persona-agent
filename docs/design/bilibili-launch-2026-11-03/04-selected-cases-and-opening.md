# 已选连续案例与一分钟样片

更新：2026-11-03。这里区分“真实系统运行记录”与“现实世界中真的发生”；角色的校园生活仍是虚构世界内容。

## 主案例：凌晨讨语音 → 早晨的生活与分享

全部时间为北京时间，均为 2026 年 11 月 3 日。

| 时间 | 实际记录 | 入片方式 |
|---|---|---|
| 00:47:12 | 用户：“睡之前可以可以给我发条语音吗” | 原文重排，保留重复字 |
| 00:49:12–13 | 角色：“大半夜跟我讨这个”“行吧行吧” | 原文重排，省略实际等待 |
| 00:50:40 | 一条真实发送的语音，正文为“行，说完了，我要睡了——你也赶紧躺平” | 从取回的原始音频中节选 0.94–5.10 秒 |
| 08:45:03 | 早餐结果结算：肉包售罄，买到糖包和豆浆 | 世界记录摘录卡，明确它是虚构生活记录 |
| 09:02:42 | “肉包卖完了，就剩最后一个糖包，配豆浆凑合吃了” | QQ 平台原文核对后重排 |
| 09:02:43 | “我收拾收拾去上古代汉语了，你要还睡着就接着睡吧” | QQ 平台原文核对后重排，后半句作为收束 |

为什么选它：同一个角色在两个时段里既有自己的事，也有面向用户的表达。可感知的细节是糖包、豆浆和那句让对方继续睡的话，不需要先解释复杂架构。

### 已核对的连接

1. 文字 payload 的 SHA-256 与已保存描述一致，并找到对应 QQ delivered 终态回执。
2. 对两条早餐消息重新调用只读 `get_msg`，平台返回文本与账本文字一致。
3. 对深夜四条语音重新读取平台消息，均返回 record 类型；通过 `get_record` 取回原始 WAV。没有使用重新生成的角色配音替代。
4. 早餐经历引用的世界结果、内容引用和 SHA-256 相互对应；结算事件序号为 87682，时间为 08:45:03。
5. 早餐表达提案记录为 model / engage_now，入口为 expired_expectation；因此准确地说，这是已有调度机会上的角色跟进，不能描述为完全无调度条件的自发行为。
6. 该轮角色状态摘要明确提到了早餐、早上的报到和夜里的语音请求。它支持检查材料连续性，但不是“真实心智”或严格因果实验的证据。

### 它不能证明什么

不是跨日长期记忆测试；不是全部消息都自然且事实无误的证明；不是完全无人干预系统的普遍成功率。视频中的等待被压缩，不能据此承诺秒回。

## 备选案例：健身时的一小段互怼

11 月 2 日 15:47–15:55，原始交流中有：

- 用户说自己在健身。
- 角色接“健身还回得这么勤”“你这是练嘴呢”。
- 用户回“拜托，吱吱大人的消息怎么敢不回呢”。
- 角色回“行吧”“这话听着舒服”“那你练你的 我继续窝着”。

这些角色文字都有已交付回执，适合后续正片展示语气、来回交流与亲近感。用户的健身近况来自同轮消息，不应包装成长期记忆召回。

本轮没有把整段午后生活作为事实一致性案例：更晚的聊天出现了“今天没课”和“下午两节课都上完”的不一致。可以展示这段范围内的语气，但不能用它证明全天生活状态一致。

## 为什么没有直接用本地语音目录

之前发现的四个 `output/voice-delivered` 文件，其文本没有匹配上这次导出的已交付消息时间线。仅凭目录名不足以证明它们是当时发送的原声。此次改用回执对应的平台 record，从源头取回音频。

本地自动转写同时发现数条旧语音把括号提示念出来。样片选用可用正文片段，完整失败表现保存在内部取材记录，避免用重新合成的声音掩盖旧版本问题。
