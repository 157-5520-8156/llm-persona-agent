# 项目分析与发布会证据边界

## 1. 结论

Girl-Agent 当前最有价值的展示方向，是**运行在持续虚构生活中的角色陪伴**：同一角色结合生活、记忆、关系与当下情境表达，用户通过 QQ 与她相处，Dashboard 展示部分过程与记录。

这比单独罗列“聊天、记忆、生图、语音”更能说明项目的设计重点，但尚不足以证明它比所有“大肥鱼”实现更好。需要以连续体验证明差异，而不能以代码规模、状态字段数量或单次漂亮回答替代。

“仿真真实性”在这里至少包含四件事：

1. **经历连续**：先前发生的事能影响后来，不为当前一句话临时补造过去。
2. **处境一致**：计划、实际做过的事、当前所在情境和聊天内容能对上。
3. **关系连续**：同一段互动留下可持续的印象与变化，下一轮不全部清零。
4. **表达自然**：语言、语音、照片与互动时机使观众感到在同一个角色身上，而不是在看功能拼接。

前三项的机制在代码中有实质实现；第四项以及长期稳定表现，需要真实录屏与连续样本检验。模型生成的情绪和内心摘要不证明主观感受或意识。

## 3. 从用户体验反推真实架构

```text
QQ 文本 / 图片 / 语音
        ↓ 归一化、身份、消息片段与话轮协调
QQC2CHost → WorldV2TurnApplication → WorldRuntime
        ↓ 同一轮固定世界版本、来源和权限
ContextCapsule / InnerLifeSnapshot ← 生活、记忆、关系、情绪、外部感知
        ↓
CharacterInterior：角色理解处境、选择行动或表达，也可检索 / 延后 / 沉默
        ↓ 提案接纳、版本检查、来源与权限边界
表达计划 / 生活计划 / 情绪与关系变化 / Action
        ↓ 执行与回执
QQ 可见内容 + 新世界事件 → 后续判断的材料

后台：时钟、世界作者、NPC、生活结果、记忆整理、再次考虑机会
展示：Dashboard / 房间呈现读取已有状态，不为角色创造经历
```

这是一张概念链路图，不能用来声称每轮都调用所有模块、按图的顺序串行执行，或所有事实都经过语义审核。

### 3.2 角色自主与统一内在状态

`CharacterInterior` 绑定角色、触发原因、快照、世界游标、能力、检索与纠错谱系。同一角色可以参与入站聊天、生活反应、主动联系、记忆留存等不同目的。统一的是角色状态和决策边界，不意味着所有目的由同一个供应商、同一个模型实例完成。

当前入站 prompt / slim 输出同时承载：对消息的理解、当下自我状态、消息、延后、期待、回访、持续情绪、关系变化、生活意图和媒体选择。它并非只输出一段聊天文本。一次无效结果允许同角色受约束重选，技术失败与角色选择沉默分开处理。

演示价值：同一回合的消息与角色状态摘要可以并排解释“为什么这里采用这种表达”。但界面的“心里”属于角色模型写出的结构化状态，不是读取到真实人心，也不是模型完整推理过程。

源码定位：`world_v2/character_interior/core.py`、`contracts.py`、`production.py`、`inbound_prompt.py`、`structured_role.py`、`world_v2/private_turn_state.py`。

### 3.3 生活、世界作者与长期故事

世界作者提供外部机会、安排与客观后果；角色形成自己的计划与反应。Outlook 实现了线程、阶段、机会窗口、依赖、来源条件、修订和执行；生活模块负责计划的开始、暂停、结束与后果。

重要区别是：课表不证明出勤，计划不证明完成，活动结束不证明达成愿望。已实现的来源与状态边界比“每天随机生成一篇日记”的描述更准确。

NPC 有独立的演员身份与可见材料。当前账本存在人物登记、活动、经历与世界事件，但登记了多少人物并不等于这些人物全都在独立、高质量地持续生活。

历史长期故事验收文档明确记录过尚未跑完、故事质量不足和付费调用失败。本轮未重做完整多日验收，因此只能展示具体已有片段，不能把未来线路图当成已经兑现的长篇故事。

源码定位：`world_v2/world_outlook.py:39`、`world_outlook_runtime.py`、`world_outlook_execution.py`、`life_ecology_runtime.py`、`world_planning.py`、`npc_ecology.py`。历史边界：`docs/audits/real-story-quality-and-contracts-2026-10-13.md`。

### 3.4 记忆

记忆分为前史、世界事实、亲身经历、对话、主观印象等来源；回忆索引是可重建检索材料，不取代账本。检索结合词面、语义、结构线索、时间等信号，并保留来源、隐私与当前世界版本。还存在自动预取、角色主动检索、场景读取、留存、整理与遗忘路径。

演示应选“换个说法仍能提起旧事”的连续片段。把同一事实重复粘贴进最近消息后让她复述，不能证明长期记忆。记忆候选数量也不是回忆准确率。

历史真实复述实验同时发现过检索遗漏和读到正确资料后的生成错误。当前代码改进与测试不能自动抹去这个质量边界；需要为片中所用案例逐条核对。

源码定位：`world_v2/context_capsule.py:940`、`recall_index.py`、`recall_runtime.py`、`recall_attention.py`、`scene_recall.py`、`memory_retrieval.py`、`character_interior/life_memory.py`。历史边界：`docs/audits/scene-recall-and-retelling-2026-10-08.md`。

### 3.5 情绪、关系与主动联系

系统既保存当下理解，也保存持续情绪、关系轴、私人印象、未完成话题、回应期待与重访意图。情绪有确定性的衰减计算，角色模型决定相应表达与主观更新。这些状态不是现实心理量表，不能把 42% 暖意解释成科学测量的爱意。

主动联系不是只有定时推送。现有机制会把生活变化、挂念、沉默后的机会等交给角色考虑。但调度仍含固定限制：`SocialInitiativePolicy` 默认对部分共享主动通道设每日 2 次、至少 3 小时间隔，连续沉默后增加冷却；不同通道并不全部共享这个限制。因此不能误写成“每天最多发两条”，也不能宣称“所有时机完全由角色决定”。

生产 Host 使用该策略默认值，并额外设置热聊续接候选窗口。这与项目文档反对机械社交限流的目标存在需要继续讨论的张力。本轮记录问题，没有擅自改变机制。

源码定位：`world_v2/social_initiative.py:190`、`:674`、`:2595`、`qq_c2c_host.py:3703`、`affect_math.py`、`relationship_acceptance_runtime.py`。

### 3.6 语音、照片与外部见闻

- 语音：`qq_voice.py` 处理入站转写/语气材料与出站合成；`onebot_adapter.py` 将角色选择的语音表达发为 OneBot record。当前代码还存在语音失败后回退文字的路径。因此合成文件、QQ 接口接受、手机播放成功须分别核验。
- 照片：有媒体候选、规划、生成、检查、批准、发送及分享回执。不能把模型“我给你拍一张”的承诺算作发图完成，也不能把生成的照片说成现实相机拍摄。
- B 站：公开源适配器可读卡片、字幕、弹幕/评论，必要时获取分镜供视觉理解；Hub、角色注意和最终接受分层。不同条目的实际阅读深度不同，“看过一个视频”应按该条记录说明，不能宣称总是完整观看。
- 房间 / Godot：有读取公开 DTO 的展示桥接，不是控制真实身体或真实环境。当前发布会不以“具身智能”为定位。

源码定位：`world_v2/qq_voice.py`、`onebot_adapter.py:204`、`world_v2/media_delivery_runtime.py`、`media_execution_runtime.py`、`external_world_perception/hub.py`、`external_world_perception/bilibili.py`、`godot/scripts/room_state_bridge.gd`。

### 3.7 账本、审计与成本

SQLite 账本、不可变内容、游标比较、Action 与回执，负责状态一致、权限、防重复执行和恢复。它们使“哪些事情确实被系统接受和交付”可追踪，但结构合法与来源存在不等于自由文本的全部语义正确。

生产策略文件中看到 `grounded_review_v25`、普通文本 `sampled`、表达 episode `off`、Life `structural`、Life candidate reviewer 关闭。`ordinary_text_observation.py` 明确将合格普通文本记录为 `semantic_review: not_performed`；结构 Life reviewer 也不做语义蕴含判断。因此不能对外说“每句话都经过完整事实审核，绝不幻觉”。这些是读取到的部署文件，未从本次成功的 live health 响应确认进程已加载全部最新内容。

`.env` 加默认配置中预算停用项为 true，月成本字段 100 元是目标值。成本页面还有估算费率与不同账源。没有做账单对账、采样日标准化和成功交付统计，不能宣传月费、单次成本或性价比数字。

## 7. 发布会口径

| 可用表达 | 需要附带的证据或边界 |
|---|---|
| 基于大语言模型的角色陪伴系统 | 明确角色与世界为虚构，照片/语音为生成内容 |
| 她有持续运行的虚构生活 | 指向实际运行片段；需要服务运行，不能等同断网、关机仍生活 |
| 角色会结合记忆、关系和处境作决定 | 用至少一条连续案例，不把字段存在当作自然体验 |
| 支持语音、图片、B 站内容感知 | 标注实际演示的输入、生成与交付结果 |
| 选择与结果会进入后续记录 | 区分想做、正在做、已完成；未来候选与已发生记录分开 |
| 持续开发中的个人项目 | 开源、下载、测试资格、发布日期仅在用户定案后填入 |

暂不支持：真正有意识/有真实情感、绝对不失忆/不编造、完全无规则、绝对实时/秒回、已验证完整一生、固定低成本、成熟商业化、多人服务已就绪、现实寄送功能。

## 8. 当前最值得优先补齐的制作证据

1. 一次真实的“生活先发生→随后普通聊天自然提起”，核对时间与原始结果。
2. 一次跨日回忆，使用间接线索，确认没有把答案重新塞进最近聊天。
3. 一次有上下文的主动联系或后续补充，排除技术重试与人为催促。
4. 一条 QQ 实际接收并能播放的语音，一张与同一生活情境吻合的普通照片。
5. 能稳定打开并准确显示当前数据的 Dashboard 录制环境。

这些是为发布会取材而设的最小连续案例，不是完整科研评测；得到一条成功片段也不能推出稳定成功率。
