# Life 全候选写入前核验

## 边界与接线

`compose_production_character_interior(life_source_reviewer=...)` 显式安装实验核验器；
默认未安装，发布资格继续为 `manual_only / qualification_incomplete`。
角色先生成完整 Life 候选，独立模型判断其中事实是否有来源，不能代写角色的感受、
行为或纠正稿。当前感受与未来意图无需外部事实许可，但它们包含的既往经历仍需核验。

`life-source-review.2` 使用角色实际收到的快照与 `life-source-readings.3` 字段权限，
逐一覆盖 summary、生活反应、Appraisal、理由及其它嵌套字符串。每个字段须恰好出现一次；
支持项须引用实际展示的来源及其许可。Fact 还须选择与已接受观察值哈希匹配的原文。
这些确定性检查只证明结构和权限，语义覆盖与蕴含仍是可出错的模型判断。

明确拒绝交回 Core 既有的一次同角色纠正，携带原始完整输出及具体字段失败原因。
纠正稿重新核验；再次拒绝记录技术失败，不写入 Experience/Appraisal。
超时、缺失字段、越权来源、无法判定均为技术失败，不伪装成角色拒绝或沉默。
Recall 是控制转移，不是可写候选，须先召回再生成终稿。修复原校验同时要求 Recall
提供终稿 proposal 的矛盾；wire 校验仍禁止 Recall 携带 proposal。

## 持久化、恢复与调用

原始核验准备在调用前写入显式提供的不可变 sidecar；原始响应和调用元数据先归档，
再检查语义结果。失败也留存，不把诊断档案登记成 World 事实。
接受凭据绑定作者原稿哈希、实际输入、完整候选、来源视图、核验请求及响应。
Core 首次接受、纠正接受、持久化与冷恢复都重验；已配置核验的 runtime 不接受旧的
无核验 prepared turn。凭据本身不是新事件权限，也不消除历史误接受。

一次核验最多 22 秒；没有内部重试。首次候选和一次纠正各可能增加一次核验调用。
通过 metered model 与原有 usage observer 计费，核验用途单独标记。
这增加成本及延迟；约每月 100 元的产品目标尚未合格，不从局部成功推断月成本。
冻结后改变来源读法或协议请求字节须有版本迁移，不能静默重释旧凭据。

## 验证范围

本地测试替换作者和审核的 HTTP 返回，其余为实际 SQLite app、Core、持久化和接受链。
验证拒绝后同角色纠正、二次拒绝、不可用/不完整审核、权限借用、凭据替换、冷恢复以及 Recall。
角色/来源/生活反应组合检查 207 passed，2 strict xfailed；两个预期失败仍描述未配置
核验器的旧写入缺口，不能视为发布通过。真实供应商语义可靠性需另行试验。

首轮三次真实 Flash 调用在两个编造反例上拒绝正确，合法候选则因模型将权限代码写成
自然语言而技术失败。v2 据此把 reading_id、claim_scope、subject_role 的 schema 限为
当前目录可用词表，没有 Fact 时 subject_ref/quoted_value 必须为空；组合权限仍由代码核对。
保留 v1 请求编译与凭据解释，三份历史脚本凭据冷核验通过。v2 相关检查 21 项通过，
供应商复测单列，不把结构修复计为语义通过。
