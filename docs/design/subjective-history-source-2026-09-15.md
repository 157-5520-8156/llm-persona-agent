# Read accepted subjective history without promoting beliefs into facts

The phase-qualified real chats exposed an asymmetry: the role author could see
accepted Appraisal/Affect history, but the whole-candidate source table omitted
those selected lanes. A retrospective feeling was interpreted as an ordinary
external fact, with neither its own source nor an appropriate permission.
This does not make all prior rejections false: some candidates also invented
availability, a reason for failed delivery, or physical actions.

Explicit review version 12 pins independent protocol `.4`, meaning `.10`, and
receipt `.12` before the author runs. The new meaning category
`past_subjective_state` retains past feelings, interpretations and communication
preferences as claims requiring evidence. They are not current source-free
expression, accepted future plans, actual actions or another person's mind.
If a sentence separately states an action or result, that proposition remains
in the ordinary factual category. Interpretation and entailment remain model
decisions; code does not classify prose or prescribe emotional behavior.

`visible_subjective_source` validates the selected complete projection value,
its hash, original acceptance binding, privacy, active selection and pinned
time. It supplies one narrow `subjective_history` permission. The trusted
Capsule supplies the companion owner; Appraisal.subject_ref is the interpreted
subject and must not be mistaken for the owner. Full hypotheses, alternative
weights, confidence, dates, status and Affect component data remain visible;
selectors identify exact meaning/dimension fields without discarding context.
An earlier intensity or cause cannot be invented from a current affect value.

The source composer includes these selected lanes only for version 12. Source
table `.6` avoids the existing recalled-prehistory `.5` identity. Old source
compilation and request bytes keep their defaults. Shared-string presentation,
independent readers, one same-reader structural reselection, bounded validation
phases and the one same-character semantic correction remain unchanged.

Ordinary event, dialogue and plan sources do not acquire subjective-history
permission. Conversely, a private-history card cannot support actual sending,
physical behavior, a belief's external content, or the counterpart's real
emotion. A structurally valid model selection crossing these permissions is
rejected. No new Appraisal, Affect, memory or World event is fabricated by this
reader; accepted source coverage and real semantic performance require their
own runtime evidence.

## Real-provider qualification and remaining ownership seam

The first real version-12 journey exposed a second, concrete asymmetry: the
source table contains one selected appraisal, while the author's living-state
installer presents 21. The new permission is implemented, but that does not
establish source completeness. Its two delivered turns avoided the disputed
past subjective claim. Do not mark the historical-reading feature qualified.

The next change must give both consumers a shared, pinned inventory of accepted
records, with exact record access and privacy/time/provenance checks owned by
that boundary. The reviewer must not gain authority by copying author prose;
compaction must not silently remove the only proof of a presented recollection.
This should be an explicit context-source interface, not ledger access scattered
through the semantic reviewers. Current-past Affect updates need their exact
recorded revision rather than inferring history from an opening event.

[Anthropic's context engineering discussion](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
supports keeping sufficient focused context and retrieving additional material
when needed. It does not prescribe this project's authority model; shared pinned
source identities and replayable acceptance are requirements from our own code
and the observed mismatch. Increasing both prompt budgets is not a substitute.
