# P2 增量故事导入实测（2026-10-07）

本轮基线 `ffdde4c6`，实现 `dbc0db32`，审查修复 `6366b9e1`、`e95caa09`。
设计见 `docs/design/story-import-p2-2026-10-07.md`，契约见 ADR0023。
所有资料来自虚构固定稿件与隔离 SQLite；没有更改生产历史、配置、进程或真实 QQ。

## 已交付的闭环

- 源稿与 brief 固定，结构化抽取、稿内关系、跨故事事件身份/关系、独立审核、受约束修订、捕获恢复串成单一准备入口。
- `.3` 包携带既有档案、传记配置、World 启动与外部记录的精确版本；首次导入在事务锁内核对，拒绝过期审批或替换旧史。
- 审批覆盖每条记录、稿内边、共享发生和跨故事边；另有明确的漏连关系报告。宿主检查完整性，不能代替模型决定语义同一性。
- 旧 `.2` 与新 `.3` 记录可呈现同一 canonical 发生编号。新关系通过已审核的新档案授权投影到两端，旧记录字节不变。
- 当前 owner、隐私、保留/遗忘、来源证明及历史知情筛选继续生效。旧片段可发现后续，长窗口和实际来源引用保留新增档案证明。
- 初始化 opportunity 保留旧读取形状，避免新增 Recall 元数据破坏已提交的记忆初始化事件回放。
- 原稿分段保存完整文本、字符范围和 hash，可无损重建。它尚不执行任意长篇的跨章节全局合并/审核。

准备入口不接受世界历史、不替角色保留记忆、不控制角色行为。实际接受仍走 `PrehistoryArchiveRuntime`。

## 试验与失败账本

固定源稿为 `fixtures/world_v2/interwoven_stories/story-a.md` 与 `story-b.md`。
冻结世界来自上一轮的早期 12 条历史快照，**不是当前生产 72 条历史**。
主角 `agent:companion`；两条故事关联蓝本子/写作/摄影与工具盒/夹子/后来告知。

| 阶段 | 实际结果 | 结论 |
| --- | --- | --- |
| 首轮 A+B | 各 7 条可导入记录；0 共享发生、0 跨故事边 | 结构通过，但交织覆盖失败；不能记作成功 |
| 新知情契约 A | 14 条；稿内关系首答越过记录范围，被拒后一次纠正成功，随后批准并隔离导入 | 具体义卖知情收窄到 2025-04-19；后续理解到 2025-06 |
| 新知情契约 B | 7 条、6 条跨故事边；两次普通 JSON 审核均漏必填维度 | 技术拒绝，未以局部 approve 冒充整体成功 |
| B strict 审核恢复 | 只重做 1 次审核；批准 7 条/6 边 | 提取和关联捕获复用；仍没有共享发生映射 |
| 全事件身份计划 | 识别交夹子为同一发生，但混入一条新稿内部边；纠正请求 ReadTimeout | 该阶段失败，保留 1 次未知计费；不是审核超时 |
| 误标的 review-retry 目录 | 在复制过来的不确定计划请求处停止，未新发请求 | 名称不能作为执行证据；新增请求为 0 |
| 定位后的独立恢复 | 新请求携带原方案和确切错误端点；1 次计划+1 次独立审核 | 7 条 B 记录、1 个共享发生、9 条跨故事边批准并导入 |
| 同协议独立重复 A | 与前次相同请求体 hash；抽取成 12 块/6 条记录 | 分组与原 14 块/14 条不同，记录数本身不代表质量 |
| 重复 A 独立审核 | 5 条批准，糖纸记录拒绝 | 他人内心/共同态度与宽泛知情范围仍有语义问题；未导入 |

最终共享发生隔离分支为原 12 + A14 + B7 = 33 条记录。两次交夹子叙述具有明确映射；
2026-01 的告知、反思、提出归还仍为新的事件，未被归并成 2025-04 的发生。
旧记录不变，重复接受不写事件，恢复完成计划/审核无新模型调用。
这证明一个受审核的两线样本可以贯通，**不证明整个生成/审核体系已具稳定语义质量**。

首轮宽泛 `known_until` 并非纯粹模型自发错误：旧提取提示明确要求“持续可用至启动”可以填启动时间，
而 P1 读取将该字段解释为知情获得上界。本轮以新版本消除这项生产者/消费者冲突，保留旧捕获不重标。
未注明时间的背景仍存在宽区间，不能声称所有知情问题都已解决。

## 独立重复的准确边界

两次 A 的完整 `ingestion-request.json` 相同，实际供应商请求体 SHA-256 均为：
`280c8937e9a6d50fa83f050b1e42db9516b1cf7c96938d7bb419c478ad0d29fa`。
模型、原稿、brief、ID、温度及请求协议相同；第二次不是恢复第一次捕获。
两份保留了主要事件线，但分组、ID、部分认知表达与审核结论不同。
第二位独立审核拒绝了叙述中的双方共同态度；此前批准包也含相近表达，说明审核存在分歧，
不能以一次批准声称读者视角绝无泄漏。重复样本只做抽取与内容诊断，未重跑整套关联或导入。

“同一捕获可恢复”和“独立转换质量稳定”是两个不同验收项。前者已验证；后者未通过全面验收。
下一轮应冻结事件/知情/权限 gold 与逐项覆盖计分，再检验独立抽取和审核一致性。
不能继续只用导入成功率、片段数或整体 approve 衡量小说转换质量。

## 测试与审查

- 边界覆盖：过期档案基础、旧快照/共享编号/传记/启动 hash 篡改、缺失审核维度、漏连拒绝、原记录不改写、当前 actor、遗忘、历史知情与来源闭包。
- `.2/.3 × 短/长旧片段` 经公共 Memory/Recall/实际 claim 绑定验证；移除新增档案证明会抑制相关读包。
- 已捕获的错误工具名称进入一次纠正；中断后复用完整响应，不确定请求不自动重发。修订与实际 typed 关联继承分别测试。
- Standards：首次发现 1 项 P2（完整错误工具响应无法纠正）；修复后又发现长窗口旧基数，均已关闭。
- Spec：首次发现 2 项 P2（旧 `.2` 编号、旧→新续读）；修复检查发现初始化旧字节 P1、长窗口 P2、普通 Context 引用 P2，均已关闭。两轴复核无遗留可操作发现。
- 旧初始化 golden 从 `dbc0db32` 的真实旧函数生成，不以当前实现反写预期。评审者重放原失败样例，opportunity 与语义 hash 已一致。
