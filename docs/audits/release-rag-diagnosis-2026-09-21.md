## World 工具与输出容量

原工具是 `world-consequence-author-tool.1`，其业务结果合同已经是
`world-consequence.2`；这两个版本不是同一编号。旧真实候选的 4 个 outcome 均为
普通隐私、带地点、`visual_evidence=null`：工具 schema 接受，现有业务 parser 拒绝。

新工具 `.2` 将已有条件前移到模型可见 schema：地点和 location capability 成对；
带地点的普通隐私结果必须含视觉材料；withhold 不得含视觉材料；无地点材料不得声称
视觉地点。角色仍选择 no_op、地点、隐私和候选结果。来源审核、动作权限与业务 parser
未放宽。旧 `.1` 的 forced／auto wire hash 保持完全相同，旧请求按其记录版本恢复。

新工具通过现有 union-safe `$def` 压缩：完整工具 16400 B（旧版 10646 B），
schema 压缩 16131 B，展开 32052 B。压缩减少重复定义，但没有抵消全部新增结构。

两次新真实检查，每次最多 1 次调用、35 秒、无重试：

| 配置 | 供应商结果 | 本地判断 |
| --- | --- | --- |
| 新工具，4096 输出上限 | HTTP 200；用满 4096，`finish_reason=length` | 工具参数 JSON 被截断，不能进入业务解析 |
| 同材料／模型／工具，仅上限 8192 | `finish_reason=tool_calls`；实际 4083 tokens，14.562 秒 | schema、原业务 parser、offered binding 校验均通过；4 个候选各含视觉材料和授权尝试结果 |

[DeepSeek 官方说明](https://api-docs.deepseek.com/api/create-chat-completion/)指出
`finish_reason=length` 可能表示输出被截断。本次精确用满已设上限，与此一致。
第二次实际输出略低于旧上限；输出有随机变化，不能把单次成功全部归因于提高上限。
基于已观察到的截断，为自动构造的后台 World provider 与试验 world_support 提供
8192 的输出余量；交互作者和外部注入 provider 的上限保持原值。仍按完整上限预留，
按实际用量结算，不靠省略字段或压缩角色选择来过关。

World 工具及邻近 103 个不同测试通过；provider 构造、CLI、输出预算组 119 项通过。
Ruff／diff 检查通过。这些属于定向验证，上个冻结版本 b560a3d2 的完整回归不能冒充
本轮修改后的完整回归。真实候选只用于诊断，未写回旧机会或作为已发生经历。
