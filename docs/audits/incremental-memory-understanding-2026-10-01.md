# 后台增量理解、去重与后续读取验证

2026-10-01。用户要求将此前尚未实现的 Hindsight 借鉴部分完成。
基线 868804dd；在现有发布候选工作树修改。生产只做一致性只读备份，
所有时间推进、付费试验和复查接受均发生在隔离副本，没有 QQ 发送或生产切换。

## 实现

- 新记忆触发合并机会；复查在一次角色调用内同时选择保留与理解更新。
- 原文、精确故事关联与既有理解共同提供证据。生产复用已有 BGE-M3 缓存端口排序相关理解。
- 同一角色选择新建/修订/合并/搁下/不更新；没有关键词人格分类、情绪矩阵或程序代替角色选择。
- 成功回执和实际保留效果共同绑定模型输出。未接受的付费草稿不进入记忆。
- 冷恢复、当前视图、历史检索、转送内心上下文已接通；原文不被摘要覆盖。
- 修订继承来源依赖。源记忆被遗忘或不可读时，子摘要也不能继续暴露其内容。
- 记录的理解是私有、可推翻的读法；不获得外部事实或行动授权。

实现及权限边界见 [ADR-0021](../adr/0021-sourced-incremental-memory-understandings.md)。

## 自动化验证

434 项针对检索、记忆、角色协议、生产投影、后台上下文和生活感受的检查通过。
专门的纵向测试覆盖：同源不同方面分别保留、角色合并、旧版本显式回想、来源撤回、
跨 actor 拒绝、sidecar 篡改、付费后中断恢复且不重复调用，以及八条后台阅读全部进入真实 Core。
最后一个测试源于真实副本中“普通六条上限截掉后台所需八条”导致的 invalid_projection。
FeatureHash 只用于确定性边界测试，不作为真实语义质量成绩。

本轮没有完成全套发布门禁，不宣称生产已验收。

## 真实角色与真实来源

使用当前 API 的 deepseek-flash、thinking disabled，沿公共 CharacterInterior 路径运行。
四个已接受后台批次产生 **11 个版本、8 条当前理解、3 条可读历史理解**。
第四批次由角色主动 revise 三条既有理解；当前数保持八条，未把旧版本删除。
冷读取能够恢复同样的账本，无来源抑制错误。

例如，角色将许桥借相机的旧事与周祺的小交换联成“不替两个人承诺的边界”；
随后读到小交换中拒绝耳机、事后迟疑的另一段经历，又主动修订该理解。
她还将父亲松手让她独自骑车的童年记忆与离校时没问出口的话联系起来。
这些是角色自己的概括，不能将“同一路数”的判断升级为客观心理定律。

同一冻结原文批次的理解 on/off 诊断均返回 decided。
它证明整理结果能进入后续角色判断，输出关注的方面发生变化；
没有盲评或重复采样，不能单凭这一对断言人格/行为因果效果已量化。
诊断输出未被接受为新 World 状态。

## 实际失败与修复

- 最初角色用 m/u 令牌点名关注，而协议只识别另一套引用。增加精确令牌恢复与完整来源绑定。
- nullable 更新字段与“必须明确数组”的检查矛盾。新能力工具改为必需、非空值类型的数组；无更新用 []。
- 两套重复的来源选择与“一源一引文”条件使合法多段引文失败。
  新工具只在 evidence_quotes 选择一次来源，允许同源多段，不再重复 source_tokens。
- 后台提供八条理解，投影却沿用聊天六条上限。现在显式提供的能力来源全部接入，聊天预算仍为六条。
- 起初整理器还在重述旧方面。明确增量账本任务后，真实第四批次执行三次 revise。

失败原始请求、费用与修复前后结果均保留，不将它们改写为成功率成绩。
