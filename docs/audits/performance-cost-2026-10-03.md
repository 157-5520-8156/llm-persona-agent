# 性能与费用优化：局部收益，整体目标未通过

基线 `6a4878b6`。使用一致备份的生产副本和 CaptureDelivery；没有发送 QQ 测试消息或切换生产。模型、生活机会频率与读取预算不变。

## 修改

- 世界 YAML 采用 CSafeLoader（不可用时回退 SafeLoader），按完整文本缓存，返回独立副本。调用者仍读取当前文件并校验，不缓存文件是否有效。
- BGE-M3 SQLite 向量缓存仍查询当前 World/version 的行，仅缓存 JSON 原文与维度对应的纯解码。改动、损坏或删除的行不能复用旧读取结果。逐索引对象的缓存试验没有保留：语义搜索创建临时索引，该层不能消除实际重复解码。
- 已安装 reference wire 的后台请求在引用编号前把稳定角色与环境放前面，时刻和能力绑定放后面；所有值、数组顺序与来源保留。旧非 reference wire 顺序保留。
- 两个不同的已提供句柄若精确指向同一主张来源，展开时只留一个来源，避免展开制造非法重复。原样重复句柄和未知来源仍走原验证；文字与来源权限不变。

参考 [DeepSeek 官方缓存说明](https://api-docs.deepseek.com/guides/kv_cache/)及 [PyYAML 官方文档](https://pyyaml.org/wiki/PyYAMLDocumentation)。供应商缓存是尽力而为，前缀长度不能直接当作节省金额。

- 实际 world_seed：原解析 57–62 ms；新解析首次 9.5 ms、热缓存约 0.77 ms，结果完全相同。
- 生产副本 415 个 1024 维向量：原解码 107–135 ms；新解码首次 112 ms、热缓存约 0.082 ms，逐向量完全相同。这不是整轮回忆耗时。
- 四次同 pinned Context 的 model_content_json 字节一致。这组带 cProfile，不能与无 profiler 的聊天算总提速。

## 实际模型对照

同一冻结世界，依次问日常、生日回忆、许桥的影响。角色输出及后续世界状态会变化。

| 条件 | 首条捕获秒 | 云作者调用 | 三轮聊天费用估算 |
|---|---|---:|---:|
| 基线 | 6.29 / 8.60 / 6.35 | 4 | CNY 0.0845 |
| 中间候选 | 7.55 / 未发出 / 5.98 | 5 | CNY 0.0850 |
| 最终候选 | 6.26 / 6.28 / 5.81 | 3 | CNY 0.0448 |

中间生日轮的引用展开重复触发重选，重选又超过 beat 上限；保留失败样本。最终三轮捕获成功，但生日轮转说厨房计时器，许桥轮只说“许桥啊……”。费用下降同时伴随额外 Recall 消失和回答差异，**不能归因成代码省钱近一半，不能宣称保持质量的降本成功**。没有稳定 <5 秒、QQ 或 P95 资格。

三批真实后台记忆整理：基线四次调用（含纠错）CNY 0.0502；第一次候选三次 CNY 0.0441；最终候选三次 CNY 0.0463。正常调用费用未明显改善。工具 schema 中的可用 token 枚举也随批次变化，仍会影响前缀缓存。结算与记忆理解由同一角色模型生成，未用规则替代。
