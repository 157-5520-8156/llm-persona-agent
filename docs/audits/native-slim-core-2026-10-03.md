## 根因与实现

原 slim strict 工具只要求 result_kind 与 payload_json 字符串，不能约束字符串内的 meaning_of_this/my_state。缺字段会触发整轮重选。参考 [DeepSeek 官方 strict/anyOf 文档](https://api-docs.deepseek.com/guides/tool_calls/)，新增默认关闭的 WORLD_V2_NATIVE_SLIM_CORE：

- decision 分支原生要求 messages、meaning_of_this、my_state、world_claims；消息、感受、理解、事实引用仍全部由角色写。
- 其余可选能力保留 extras_json。没有选可选能力的完整核心沿用原 slim 的省略语义；不能用 extras 覆盖核心字段。
- recall 保留独立 payload_json 与当前能力边界，final 工具不提供再次 Recall。
- 原生核心解码回原规范草稿，不改变 Appraisal/Affect、来源、隐私、Action、CAS、effect-once、回执和回放。旧 slim 格式默认保留。
- prompt.7-slim-core 与工具 _core 名、schema hash/contract hash 区别新传输；不是恢复旧约 27k 字符全 nullable schema。此次工具约 1.7k 字符。

真实供应商仍出现把完整字段放在 result 外面的格式错误。现在只把明确存在、没有重叠冲突的字段重新包装；缺感受、理解、消息或引用仍失败。原始响应字节仍绑定审计。裸完整核心省略可选容器不意味着代码替角色选择感受或能力。

引用 codec 现在同样展开原生 extras_json 和 Recall 的嵌套字符串。旧实现只处理根级 payload_json；不修这个会让新的 Affect/能力引用别名无法返回实际坐标。未知别名及重复键继续拒绝。final 工具提示使用当前工具名称。
