## 冻结复现与已知问题

`/tmp/trial15-frozen-visible-probe.py` 在禁止 HTTP、凭证和 SQLite 的条件下读取原始
请求/响应并核对哈希。两个 v3 响应通过各自实际 Schema，外加未选分支 null 的反例
仍被拒；首审核响应通过正式 parser，确实产生整气泡 unclosed，而非本地解析错报。

审核契约只返回气泡索引、判定、语义/主体分类及来源索引，没有争议片段或简短原因。
host 的 locator 是整气泡，不是模型定位的失败部分。原始证据不能判断 reviewer 把
“正准备去”理解为当下意图，还是已经进行的准备行动，不能据此断言语义误拒。

另一个确定的问题是 `_role_result_correction_instruction` 把这次来源拒绝冠以
“结构校验失败”“只说明投递形状不合法”，与合法 v3 及实际失败类型不一致。应保留
精确 failure_code/detail，避免宿主杜撰失败类别；后续诊断可帮助角色自己重选，不能
成为关键词放行、替换话术、自动分段交付或新增事实授权。

反证还发现单气泡同时绑定两种主体来源的表达能力有限，但不能认定它导致本次拒绝：
若后半句是当前意图，只需为前半句绑定用户当前报告，既有 parser 可以闭合。
是否需要新的多主体契约需另有生产者和消费链证据，不在这次修复中扩张。
