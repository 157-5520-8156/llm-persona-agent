# 当前投影地址查找：保留的本地优化

本轮属于原 goal 的性能/费用续修；未改变角色语义决定、来源/隐私/CAS/effect-once/回放要求，未部署或发送真实 QQ 消息。

## 改动与边界

新增 `projection_lookup.lookup_first`，在同一不可变投影集合被至少 8 次按同一字段查找后，建立保持 first-match 的地址索引。按集合对象身份和字段隔离，强引用原 tuple 防止对象 id 重用，最多 8 个索引、每集合最多 100000 行。单次提交/新集合、可变行/集合、动态属性、非标量 key 继续原遍历；不缓存不存在结果、权限通过或验证结论。

应用于已定位的事件编号、提案编号、模型结果编号、结算编号和修订坐标查找。返回原始行后，原函数继续完整检查 hash、revision、参与者、actor/world、原始角色审计、结算、撤回/隐私、内容体和回执。额外谓词每次执行，重复编号下仍找第一个满足谓词的行；缓存锁不覆盖外部谓词或可变行扫描。

这不是记忆筛选器，不改变条数、事实、记忆可见性、数组顺序、候选排序、Role 工具或提示。不再为一次 schema 解析的微小波动加缓存。

- 首次基线 0.774 秒和后续索引 0.302 秒包含原有数据库/解析缓存冷暖差异，不作公平提速比例。该固定 Context 编译不包含真实 BGE 自动 attention 等全部聊天准备步骤，不能据此宣布全链 <5 秒。

## 真实角色链条

无 cProfile，独立副本、真实 V4.1 Flash/BGE-M3、协议25、CaptureDelivery。固定三条输入：近况、暂时去忙、最难忘的生日。角色可自由 Recall、延后或沉默；未禁止 Recall，未改频率或输出质量标准。

首条捕获 5.368/5.145/4.235 秒，三轮均 ActionAuthorized、捕获文本可见。三次付费角色调用约 0.0351 元、无记账错误；还执行三次本机 Qwen3-1.7B 输入端点估计，不能将它们说成额外付费 DeepSeek 调用。后台工作设为0，此费用没有生活、记忆整理、交互事实等完整日负载，不能外推为1.5元/天。本机同时执行了小范围回归测试，该组是链条诊断，不是严格无负载速度A/B或QQ验收。

第三轮只回复“最难忘的啊……”“我想想”，没有回答问题。真实请求 recall_available=true，原生工具允许 decision/recall；输出没有选择Recall，later与waiting_for均null。其中later在此协议是发消息延迟，不是继续思考的任务，不能通过调later误称已接好未来思考。当前不能把这轮计为合格的回忆回答，不能因较快/较便宜而宣称保质。现有数据只能定位“角色没有选择检索且回答未完成”，不能擅自宣布是RAG不存在记忆、检索漏了或必须强迫她检索。

近况轮还输出了具体生活描述、world_claims=[]；空声明不证明正文没有事实，应结合可见来源核对。这组尚未证明事实质量或长期人设表现。
