## 已实现的输入修正

当前故事上下文选择有独立 policy18 身份，旧17及更早保持原实现。最多6条读物及原两项字节预算不变。在至少两个种子预算时，先保留主上下文与当前问题最强直接字面命中，再补场景和图关联。所有候选仍先通过当前 actor/privacy/status/time 过滤。对当前话题入口保留一个已认证的关联起点或后续，跨阶段回顾不因日期较晚而硬删。

复核发现并修复两种去重遗漏：同场景不同记录的直接命中不再被场景去重吞掉；同一长记录的开头和末尾窗口竞争时，以当前问题命中窗口作为该记录代表，仍一记录一窗口。只改变已合法材料的可达性，不用本地规则决定角色说什么。

当前入站3/slim在 shared-string 编码前，把派生 conversation 呈现为 dialogue-report-view.1，标明 recorded_utterance_only；原句、顺序和时间不变，原 recent_dialogue 和 canonical snapshot 不改。编码前转换还覆盖不启用 reference codec 的 slim。model-context-reading.2明确旧话、当下理解与执行结果的权限差别。V1/V2保留原 list 和八个冻结请求 hash；纠正 trailer 仍最后。LifeSourceView固定目录和 World Author 原合同不变，其余生活输入不据此宣称已资格通过。

两项呈现孤立增量：读取说明365 UTF-8字节，旧话载体159字节（未编码的同内容JSON对照）。实际 token 与费用不能由字节增量代替。没有扩大整库读取或把全部前史塞入每次输入。

## 人工来源对照：仍未通过

第一轮初始输入确实带新旧话报告载体和空 personal_action_evidence.results，模型仍说“我排的班次照跑”。相关排班/核表材料来自较早自己的话、习惯或原计划，不能单独证明最近实际执行。来源标记改善了输入权限表达，尚未证明模型能稳定遵守。

第二轮自动预取已含高中原事件 g07 和大学重逢后续 g20，回忆后也真实提供它们。最终表达却先称“校刊那会儿”，随后讲活动方案未入选，存在跨事件混叙风险；“后来也没正经道过歉，就那样过去了”也可能混淆高中阶段与2026重逢发展。不能仅因结构化 world_claims 的两条引用有效就判整段自由表达正确；也不把这句有时间歧义的话夸大成已证明“永远没道歉”。

因此继续区分检索遗漏与生成失真：本轮工程修复解决可复现的预取/编码遗漏，云端语义仍有失败。不能以多轮付费提示词试验、补写历史或恢复同步审核凑合格。下一阶段应在上游原生生活/行为来源中明确执行结果与旧报告的可读边界，同时保持角色表达自主权；需新的最小对照证明方案有效。
