# ¥1.5/日成本目标：同负载对照与修复

状态：尚未证明稳定达到完整标准。最新完整24小时＋6条聊天已知费用 ¥1.328，工作日等效 ¥1.555419，另有1笔计费未知。6轮最终均有模拟交付，其中1轮首次延后；本文不得作为上线资格。

## 验收口径

相同角色模型、相同生活机会输入、相同聊天负载，不靠预算拒绝、减少唤醒、缩短输出上限或放宽事实来源校验降价。所有真实 API 调用使用调试账号；真实 QQ、媒体、外部资讯及语义 embedding 均未启用，与历史成本样本的排除范围一致。

原始 ¥3.047 样本来自旧的加速驱动。复查发现：其事件汇总一度使用了错误 World 身份，且回执墙钟与虚拟日历混用。因此这里只保留该费用作为历史参考，不拿它与后续费用作严格因果百分比比较。

新脚本 `scripts/benchmark_daily_cost.py` 从同一独立源账本复制，校验 World 身份，记录源序列、代码副本和哈希、原生请求/响应与逐次费用。固定24个原始时钟输入；加强负载额外加入6条预先写好的聊天。不会因为某轮角色选择了更多 no_op 就自动判质量合格。完成事件数量是工作量观察，不是预设的角色行为比例。

## 找到并修改的机制

1. **延迟回执导致生活回应无法结算。** 旧代码把最后一个 World 事件的时间当作选择时间，延迟预算/回执事件可带着更早时间。历史同一来源共14次失败复现为 `selection_clock_unavailable`。修复在该原先失败的分支读取原始 pin 以内的真实 World/Clock 时间；已有成功记录的 origin 字节不变。原失败现在可从原审计恢复，不需要重新作者调用。
2. **模型看不到部分本地约束。** DeepSeek strict 适配会去掉 `allOf`，旧话题更新的约束因此消失；模型反复带上只属于创建的 `thread_kind`。新世界刺激工具5把已有权限分支完整展开再压缩，同一选择仍由角色决定。新工具支持内部本已允许的32条注意来源，旧8条载体保持冻结。
3. **大量费用用于传输内部 ID。** 新引用表示把请求内的长标识符变成短句柄，完整映射放在宿主调用身份中。文本、数字、状态、权限、顺序均保留；表格的引用列也参与编码，正文列保持原文。原请求与字典共同绑定，跨请求换字典和未知别名失败关闭；API实际输入、宿主字典和原始响应分别记录。改变传输不改变语义作者身份，也不应让已付费的相同语义回合缓存失效。
4. **重复 schema 与审计证明。** 新主动联系工具仅做无损本地 schema 引用合并；World工具4只发送一次原生 schema，在用户载体中保留原生模式不能表达的数量/长度等限制。新增 NPC/地点的 `narrative:*` 语法进入原生工具，与既有本地检查一致。背景 inventory 仅移出宿主哈希及重复证明边，保留每一行的来源、作用域、修订、隐私与过期信息。
5. **合法的已付费活动选择被无关审计写入废弃。** 活动目录7把全局 deliberation cursor 和整个 projection hash 放进令牌；它们会因无关审计变化。新目录8改绑 World 修订、精确时钟、角色和 eligible Plan 权威哈希。worker 仅在世界/时钟、执行租约、完整可选目录都未变化时，以同一角色草稿编译当前追加位置；世界或租约变化仍拒绝，效果继续走正常 CAS。旧目录7及更早版本保持原规则。
6. **审核与短引用的请求身份统一。** 主动消息审核复用实际请求准备结果，先校验不可变请求与宿主字典，再展开原引用；只有原有来源目录内的别名可被当作引用。没有绕过审核。
7. **加速驱动计时不一致。** 调度和回执使用现成 `JourneyClock`，provider 超时仍使用真实计时。日志中的 `not_due` 不能再被误当成角色不说话。

短引用当前由 `WORLD_V2_REFERENCE_WIRE_ENABLED` 控制，默认关闭；本次实验显式打开，生产 daemon 没有重启。World工具版本4、角色工具版本5与可见来源审核v24/v25是不同维度；模型与可见审核 profile 没有为降低费用而换档。

## 验证范围与仍未通过的部分

同一份内容的离线对照：对最新轮40个带引用编码的真实请求，用官方tokenizer分别测编码前后用户材料（均为相同JSON序列化格式），从1,160,333降到552,624 tokens，减少52.37%。每份材料均经宿主映射完整还原。该数字只衡量这些请求的用户材料，不含系统/工具/输出、供应商包装及缓存，不能当作整日费用同比降幅。原始明细在 `rebase-qualified-day/identical-payload-tokens.json`。

- 引用回环、原始响应哈希、同角色纠正、宿主映射防篡改、冻结工具身份和 source view 冷恢复有回归覆盖。
- 新目录的无关审计漂移、World变化、租约变化分别测；只有无关审计漂移可以复用同一付费选择。
- `virtual-qualified-day`、`final-compact-day` 与 `rebase-qualified-day` 的独立冷回放哈希一致，ReplayEvaluator 没有发现问题。
- 曾有一轮原负载低于¥1.5，但不能把这轮较少的新事件和较低费用当作完整质量等价。增加6条新聊天后，已记录的轮次尚未稳定过线，且出现过 provider 计费未知与首次延后。最新轮的未知调用为 inbound caller_cancelled（2175ms），预留 ¥0.248546 只是容量占用，不是实际账单；无法将它计为零。全不命中缓存的闲时敏感性估计 ¥1.849744，也高于目标。
- 最新首轮拒绝原因为 `expression_plan_acceptance.event_share_claim_invalid`：通过不可变 Acceptance 事件ID及原 proposal/status/world 的身份哈希精确匹配失败码。原答案引用了多个已结算事件，但 compact 路径没有提供普通回复所需的完整 reviewed-inbound authority。后续重新生成后发出。不能通过删除 settled evidence 或放宽 acceptance 把这类失败算作解决；本轮尚未修复这处已有路径不匹配。
- 抽查对话发现具体生活叙述的来源仍有问题。例如 `final-day-with-chat` 的 `chat-02` 作者输入里，图书馆只出现在例行日程中，没有“梧桐”的来源，回复却说上午在图书馆看树叶。发送成功不是事实正确。这条是当前 compact 路径的质量缺口，降本改动没有通过放松检查掩盖它。
- 最新6轮反复谈照片，仍未证明长期自然性和多样性。
- 本轮核心回归438项通过；活动/生活链101项、传输审计40项为分组检查，与核心覆盖有重叠，不合计成独立用例数。交付汇总反例测试通过。主动消息来源审核与原始请求绑定完整回归118项通过（`proactive-final.log`）。Ruff与 `git diff --check` 通过。
- 完整自然日生产账单、长期人格/记忆等价、真实 QQ 回执及媒体费用均未由这些克隆测试证明。加速缓存命中可能不同于真实跨日命中；报告保留全未命中的费用敏感性估算。
