# 自主生活再考虑与 NPC 生活链验证

状态：本轮功能已实现并完成局部链路验证；不等于整周真人感或发布资格通过。未主动重启、部署生产，也没有真实 QQ 外发。

## 修复了什么

1. **“现在不安排”和“以后再考虑”分开。** 日初/活动结束的角色决策新增 `reconsider`，由角色给出60～86400秒的延后时间。到期使用当时的最新上下文，再次选择计划、不安排或继续延后。等待期间没有模型轮询，不生成活动/经历/外部 Action。
2. **复用原有持久化与调度。** 时间请求绑定原始角色结果哈希，保存在现有 DayOpen journal。重启从同一 CharacterInterior 结果恢复，不能改写期限或把旧失败重新解释成角色沉默。每个请求只创建一个子考虑机会；技术重试和角色选择的再考虑时间分别读取，再交给已有 Life scheduler。期间新增其他活动不会抹掉这次思考机会；它仍只能产生未来计划，实际启动走正常生命周期。
3. **去掉默认背景的摄影日程偏置。** 真实请求中，旧日常模板每天安排图书馆看书、摄影整理、晚间再次整理照片，又叠加每周摄影讨论和作品集。新增 V2 专用 `character_routine_background`，呈现休息、日常事务、学习和自主时间，不把爱好编成反复出现的固定预约。爱好、人设和已发生的历史不删；旧可执行模板保持原样。新背景仍是习惯提示，不是今日计划或完成事实，并继续随 snapshot 固定。
4. **补齐 NPC 已有硬边界的输入。** NPC 曾把地点/计划 ID 当作事件来源；随后又在 `timing=now` 填未来计划字段。现在在实际请求 schema 中列出合法事件来源及 now/later 的完整字段关系，校验逻辑不放宽。
5. **让 NPC 知道计划归谁、时间是否已过。** 原来只给计划 ID，实际模型说成“我开的计划”；时间过了又重复“窗口还开着”。现提供原始 owner/status/window 及按时钟计算的 upcoming/open/elapsed，明确 elapsed 不等于完成；旧内心状态带原形成时间，不冒充新的观察。
6. **NPC 隐私约束提前检查。** 真模型确实提出过行动，但 visibility 低于参与 NPC 的隐私等级，直到写入 World 才抛异常。现在角色看得到合法 visibility，世界模型也看得到结果隐私范围；不合法时在原模型的有界重选阶段处理，不把错误拖到事实提交。不会由代码偷偷改高可见性。已保存的不合规旧决定也不会被重新作者调用或静默升级，会返回明确技术失败；这不是旧 pending 数据的自动修复迁移。

这些都是能力、时间、状态或来源边界；没有加入“必须出门”“每天换主题”“禁止谈书/照片”或随机替角色决定行动。

## 兼容与边界

新请求使用 activity capability `.5` / choice `.3`；新 Plan origin 和 journal 显式版本化。旧载体仍按旧规则解释，已保存的 `no_op` 不会追溯变成预约。新的 source/event 权限、CAS、effect-once 和执行验收继续保留。

计时设计参考 [Temporal 的持久化 Timer](https://docs.temporal.io/workflow-execution/timers-delays)：保存期限，重启恢复，到期继续执行。本项目复用自己的 SQLite journal 和已有调度器，没有安装 Temporal，也没有另起定时服务。这里的重启证明覆盖完整 SQLite（含 CharacterInterior 与 journal）的保存恢复；单独导出 World 事件不包含全部协调状态。World 账本回放另外核对。

## 实际验证

- 最终相关组合回归：**324 passed**，覆盖旧载体、延后一小时、跨天、重启、重复 Clock、再次延后、中途新增计划、篡改预约时间、非法输出与有界纠正、NPC 计划/结果/恢复、习惯与事实边界。
- NPC 到期计划→启动→世界结果→结算→完成与重启恢复的完整路径由受控 HTTP 决策覆盖；模型语义固定，不能拿它宣称真实模型自然性。
- 修正了两个旧夹具的读取方式：按已有 shared-string 协议解包 current_activities；检查实际发送的来源词表，不再解析已删除的提示词示例。原来的无权来源拒绝、计划状态和回放断言保留。
- 真实 API 小场景：同样的夜间/早晨初始场景，旧背景均选照片；新背景选择了课程笔记，并进入正常计划/生命周期。只有两组，不能据此估计长期多样性或因果效应大小。计划的 completed 状态也不等于证明“笔记已经整理完”。
- 真模型接受了新的三分支工具协议，但这几个主角样本选择的是未来计划，没有选择 `reconsider`。再考虑分支的端到端证明来自可控决策测试，不伪称为已观察到的自主使用率。
- NPC 新鲜模型调用：修正来源与格式后可首稿通过；三次后续机会选择了 no_op，正确记录为角色选择，不能算技术失败，更不能强迫它为了指标行动。
- NPC 原失败样本回放：把 `live-npc-time-fixed` 的真实失败原稿作为已记录输入重放（不是新增 API 调用），同一模型在明确隐私错误后真实重选，World 模型真实生成后果，完成一次 **occurrence_committed → settled → Experience**。下一次机会中又产生一个新候选 occurrence；后者未结算，不计作第二件已完成经历。
- 上述结算的实际结果是厨房已有他人，林调整到一个角落准备；该正文进入了下一次 NPC 作者的 `shared_experience_summaries`。这个 NPC 单独经历没有自动触发主角的私有 Appraisal。各已导出的真实小场景账本 replay hash 一致、无 evaluator findings。
