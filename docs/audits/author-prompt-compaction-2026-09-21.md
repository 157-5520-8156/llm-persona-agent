# 聊天作者提示词精简与对照

当前 atomic v3 聊天作者已改成一份独立的语义提示词。最终实际身份材料下，system 从
29,919 字符降为 **8,334 字符（减少72.1%）**，其中原有身份、性格、风格及来源说明
4,735 字符完整保留。真实对照版减少约12%的整次输入 token，但没有证明速度或事实质量
改善。发布状态仍为 `manual_only / qualification_incomplete`，没有部署或真实 QQ 发信。

## 改动与边界

`character_interior/inbound_prompt.py` 集中解释角色自主性、生活事实、往事记忆、引用、
情绪与互动字段的含义。去掉完整 Appraisal/Expression 提示词的层层拼接，以及“顶层是
AppraisalDraft”“顶层是两份草稿”“再套工具 result”等相互覆盖的格式说明；本次工具
schema 是输出结构，提示词保留 schema 无法表达的跨字段约束。Recall 后也使用同一工具
封装，不再追加裸两字段对象的要求。

习惯、计划、尝试、生命周期结束与已结算结果分别保留原来的权限。当前感受不创造既往
经历；程序启动前认可且可访问的记忆仍是合法来源；没检索到不等于没发生。原身份全文、
user 数据、工具定义、来源审核、接受与回执机制均未为了缩短提示而删减。当前私密认知
协议的原文按原协议选择，旧 v1/v2、stream 和非工具路径保持原有编译字节。旧已保存的
v3 请求从原始载体验证，不用新提示词重编历史。

新模块直接用于新调用的请求哈希计算之前。初稿与纠正保留同一 system；精确失败原因
和原稿继续走原有反馈通道。没有关键词删句、固定回复、角色静默兜底或新增审核模型。

## 六次真实调用的结果

证据在 `output/private-audits/author-prompt-20260921-01/`。原始输入分别来自配色问题和
“你这一会儿过得怎么样”问题；每组 user、生活材料、模型、温度和工具保持一致。

第一阶段 `9ed02fa1`，两组各旧/新一次，system 29,919→8,205字符：

| 输入 | 旧输入 token | 精简输入 token | 旧调用耗时 | 精简调用耗时 |
| --- | ---: | ---: | ---: | ---: |
| 配色 | 38,021 | 33,437 | 4.589秒 | 4.910秒 |
| 近况 | 38,521 | 33,937 | 4.662秒 | 5.747秒 |

每组减少4,584个输入 token。耗时包含本次作者调用包装，不是用户首条消息延迟。
旧请求缓存几乎全命中，新请求有大量未命中；输出长度也不同，不能据四次调用推断稳态
单价或速度。四次均 HTTP200/native schema通过，其中三次 canonical typed shape通过。

精简配色稿的 `appraise=true` 却填 `severity=null`，被原有本地约束拒绝。精简版确实
漏显式说明此条件，但单次输出不能证明删文案是唯一原因。`952cb6f1` 补回
appraise=true时 meanings/attribution/severity 非空的接口说明，再对两份原材料各调用一次。
二次阶段输入33,468/33,968 token，耗时4.724/7.038秒；两份 severity 均完整，配色 typed
通过。近况选择了 interaction_act，却把 subject 和 counterparty 填成同一人，本地校验
拒绝。最终又补明互动对象不得包含主体自身；该最后一句仅离线检查，没有第三次付费试验。

所有结果均是作者草稿，没有执行独立来源审核、完整业务物化、Action或消息交付。第一
阶段近况稿虽 typed shape通过，affect episode_id 仍抄错了字符；“字符串合法”不代表选中
真实情绪记录。不能把这里的模型返回成功算成生产聊天成功。

## 事实与自然度的观察

配色草稿仍有自然的偏好和打趣，没有复述系统规则；不据此声称长期真人感已合格。
第一阶段精简近况稿说“路边那几张画桌还摆着”，但其声明只引散步计划，当前可见材料
不支持画桌仍存在。第二阶段改为“去看看……还在不在”，却又把当天旧对话说成“昨天”，
且仍叫已经画完、想继续聊天的用户“接着画”。事实范围与对话理解仍然有问题。

另查明生活材料的表示问题：01:48已结算环境原文379字符仍完整保存在 sidecar，作者
看到的却只有38字符。`LifeContentBudget` 为480字符/项、1440总额；四个较新条目先耗
1402字符，最旧环境被 `LifeContentReading.bounded` 截为半句话，两层均标记truncated。
这是共享预算策略，不是来源丢失。重复环境占位和半句截断值得后续处理；恢复全文也只能
证明01:48环境，不能直接证明04:30仍在，不应为“画桌”单独增加对话规则。
