# 第 13 批：角色读到未来计划，回复仍被传输格式阻断

固定版本 `a4ecc9df79d3c6d64e1af0b14c7c94ccf525205f`，独立数据库、真实供应商和本地
投递捕获。**0 条交付，0 次全文审核**；不构成多轮对话、完整生活链或录制候选验收。
此后没有重启本批或追加真实调用。

## 实际结果

先推进 5 分钟，角色选择下午整理近期摄影作品、挑选作品集照片的计划，时间窗
14:05–15:05。活动开始在场景起点之后 245 分钟，超出已固定的 180 分钟观察上限；
没有为测试改变角色选择或延长场景。当前只有 `ActivityPlanned`，没有活动开始或结束。

首个真实聊天请求确实包含 `planned_activities` 的已接受意图全文、`planned` 状态、
未来计划权限和时间窗。首作者约 6.2 秒返回完整 3435 字节响应，候选包含三条未交付文本：

> 刚忙完就来找我，还挺积极嘛
> 我今天下午打算整理下最近拍的照片，挑几张看看能不能收进作品集
> 你呢，忙完这一阵想干点什么

“下午打算”保留了未来态，这是计划读取接入实际模型的单样本证据；其中其他表述是否
来源充分还未经过完整审核，不能据此标为语义正确或自然度通过。

直接阻断是 strict v2 的 `$.result` 漏写 `private_turn_state` 和 `recall_request` 两个
未使用分支的 null 字段。原系统提示末尾已明确列出这两个字段；继续追加相同提醒没有
得到稳定效果。一次同角色纠正使用原 11 秒总作者截止，响应被取消且 body 为 0 字节。
终态 `primary_timeout / main_timeout` 后立即停止，未到 30 分钟的同进程 host 重建。

实际耗时 193.20 秒，其中包括操作者观察和输入间隔，不能当作单轮响应延迟。仅推进
5 分钟虚拟时间；4 次调用为 day-open、首作者、纠正作者、事实提取。前三项中的纠正
作者用量未知，其余三次完整。没有世界作者调用、来源 reviewer、真实 QQ 或生产库写入。
