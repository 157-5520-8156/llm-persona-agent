## 零值需要分别解释

- 独立目标、位置、资源、注意力状态、动态世界地点、生平坐标、生活线、愿望记录确为0。
  它们不是54项计划或70个世界事件的同义计数。缺少独立资源状态不能解释为身体状态正常；
  位置状态为0也不能解释为没有场景。没有为了填数恢复已暂弃用的小屋。
- 启动前人生档案/历史片段为0：这个生产世界尚无对应导入记录。
- 周期记忆复核为0：运行进程早于上一轮新增 worker；代码已实现不等于生产已装载。
- 外部感知请求/结果/外部信号记录为0：该 pin 未看到对应链路记录；不能称该能力已验收。
- `interaction_fact_decisions=0` 不等于事实提取从未运行：133条提取流程、10次
  FactCommittedV2以及30条事实都存在。该计数只覆盖特定的新结构。
- `pending_actions=0` 表示当前无待处理行动；`failed_actions=0` 是当前状态计数，
  历史失败回执仍有11条。
- `life_ecology` 类流程为0不证明生活调度未运行：调度的空转、等待、租约还会保存在
  独立运行侧记录，表格只统计账本中的该类流程，不假装覆盖所有调度调用。

## 修复

1. **表达正文漏接**：原卡片只渲染 ExpressionPlan 状态和固定标题，没有读取已有正文。
   现在按同一接受记录、计划、payload引用/hash和原文匹配读取**已送达的纯文本**；显示
   总段数/送达段数/可展示段数与接受时间。部分送达明确标注；withhold、未发送、独立
   载荷/非文本或来源不匹配时不给正文。多 Beat 是正常设计，未合并为一次新角色表达。
2. **经历正文固定未读取**：从 Experience 精确 settlement binding 关联对应世界事件，
   对展示的最新经历补读其实际来源，即使不是最新世界事件；沿用已有事件、hash、权限和
   内容完整性检查。不拿附近的事件或角色私人解释补写事实。保留shareable可见范围。
3. **所有无detail都用同一句占位**：区分结构化字段、未送达、来源未接入、不可用和受限。
   标题已有情境评估含义时，不再暗示“文字没提取出来”。
4. **零值没有口径**：给关键零计数增加解释；加入15个类别的持久流程统计，区分open、
   claimed、terminal与受理尝试。旧服务没提供新统计时显示“未提供”，不伪装成0。
5. **期待永远open**：对应精确源的fulfilled/superseded评估及原时间窗口决定展示状态；
   回访安排也反映scheduled/expired。已满足/已过期的期待保留在历史中，但不再充当
   未完成的等待。没有推断角色情绪或更改角色行为。
6. **读取挂起时无限等待**：客户端10秒中止请求，沿用最近已验证快照并显示过期/不可用。
   未从health、另一个世界或历史归档拼接数据，也没有将读取失败转成零值。
