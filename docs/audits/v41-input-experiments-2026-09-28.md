# V4.1 输入对照与可落地的机械修复

## 结论

只用 DeepSeek V4.1（正式API名`deepseek-flash`）完成输入对照。有限历史方案没有赢得新题验证，**未接入默认生产链路**。已应用的是费用准入、检索过滤集合和审核引用解码的机械修复；不宣称编造、总体发出率或5秒目标已解决。

用户要求停止V4 Flash/Pro比较后，已中止最初的模型矩阵并禁止原脚本再运行。中止时有8次完成、1次中断，约¥0.4336已知估算和1笔未知账单，全部排除出结论。随后没有继续Pro调用。官方说明[正式名称与V4.1发布](https://api-docs.deepseek.com/zh-cn/news/news260910/)、[旧名称映射](https://api-docs.deepseek.com/zh-cn/)；现场`/models`也返回`deepseek-flash`。旧`deepseek-v4-flash`名称不是当前独立的旧Flash模型，不把别名变化算成模型升级收益。

## 实验设计

第一阶段冻结8个原始初次作者请求，统一使用当前系统提示词、同一V4.1模型、相同工具/温度、关闭thinking；完整与有限历史输入交替顺序，各8次。没有纠错或来源审核，Recall请求不算完成回答。

有限历史输入保留全部对方报告、当前情绪组件、关系、事实、未完成事项、选中的检索结果和能力；只展示最近2条稳定旧自述、最近4条稳定Appraisal，省去Affect中的冗长证明引用，明确这不是全部历史。没有删除账本记录。原文及有效来源不被改写。该策略现在只由实验工具显式安装，不存在生产配置开关。

第二阶段采用6个未用于筛选的新问题，分别从相同账本独立分支，执行作者→现有来源审核→本地捕获发送。问题包含完成小事、照片计划状态、养猫往事、周五取耳机时间及周三取消、书店共同经历、当前是否想聊天。两组均没有后台唤醒、媒体发送或真实QQ。

## 已确认并应用的修复

### 1. 正式模型名称被费用准入错误拒绝

`resolve_model_price()`已经支持V4.1价格，`estimate_provider_request_reserve_cny()`的精确模型白名单却遗漏`deepseek-flash`。真实链路在HTTP请求之前报`ProviderRequestPricingUnavailable`。已补正式名称，未知模型仍拒绝。新旧别名使用同一费率；保守预留额可能因模型名字节数略有不同。

最初6题零调用结果属于这个基础设施缺陷，费用0、未向模型发请求，已排除，不记作模型失败。修复后才运行上表中的有效验证。

### 2. 检索集合排序引起无意义失败

`memory_kinds`和`link_refs`语义上是集合。新atomic slim解码器只对已写出的字符串成员排序去重，不增删种类含义，不改查询、时间范围、数量或历史开关。未知种类、错类型和后续引用权限仍拒绝；旧非slim解析器和持久Trace仍使用严格规范格式。

16个原始首稿中有2个仅因集合顺序失败；离线重放同一原始返回字节后，两个均恢复结构解析。这里没有新增模型调用，也不把结构通过当作语义或引用权限已通过。

### 3. 正确回答被审核传输格式拒绝

取耳机时间题的正确候选是“周五下午三点”“周三那个作废了”。原审核选择了真实Fact原文和正确主体，却同时在普通引用列表与完整Fact值选择中重复同一reading ID；说明文字还提到了`@r:`编号，通用引用解码器把它当作整个字符串必须是一个ID而失败。

新`grounded-review-ordered-wire.4`：

- 只在`reading_ids`、`reading_id`、`subject_ref`这些身份字段解码编号；正文、命题、理由和`quoted_value`原样保留。
- 如果普通引用列表重复了同一条完整Fact值选择的ID，只去掉那份冗余普通ID；保留完整选择并继续验证原文、主体与scope。
- 不合并重复/矛盾的完整Fact值选择，不补quote，不把普通ID升级成Fact值，不放行未知引用。
- v1/v2/v3继续使用旧规则，原请求和旧回执不被新协议重解释。

离线将原始失败响应交给新解码器，两个Beat均`closed`；问题、候选、来源、审核指令和工具参数schema不变，仅传输版本和工具名更新。历史v3请求重建仍与捕获字节相等。此离线检查不伪造一次新的供应商调用或发送回执。

真实V4.1单题复测使用新wire4：作者一次、审核一次，2调用、¥0.0514，原样发出“周五下午三点 青禾维修”“周三那个作废了 别白跑”；首条7.29s。没有重写角色答案或再问模型。该新wire4账本冷重放的semantic hash一致。仍未达到5秒，也不能推广为全部场景一次通过。

## 验证与边界

相关测试分组399项及81项通过，覆盖排序不改成员、非法值拒绝、模型计价准入、原文/主体校验、引用字典、旧协议重放与HTTP接受链路。`git diff --check`通过；实验工具和新窗口模块Ruff通过。

生产进程、生产账本与开关未改，测试均使用调试账户。输入裁剪只在实验工具中可选；后续付费实验固定V4.1，不再使用Pro比较。
