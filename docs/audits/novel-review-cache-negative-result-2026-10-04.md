# 生活来源检查的缓存对照：候选已撤回

目标仍是原范围：保持质量和频率，常规首条回复 <5 秒、约 1.5 元/天。本轮没有发布或修改生产配置。

## 已完成的对照

从已完成的全天副本中提取 22 次真实 novel-origin 检查，14 次 supported、8 次 unsupported。找到对应的 World Author 原始响应，重建并完整校验 Manifest（包含展示用 manifest_hash、位置 capability_ref 与重建值的逐项一致性），使用原解析器重建 28 份草稿。选取最先匹配的 supported/unsupported 各三份，实验前固定六份输入。

尝试仅重排当前源证明协议的 JSON 字段：静态输出约束、完整 pinned authority 前置，已有证据的 source slices 位于变动 Context 身份之前。所有值、来源、隐私、数组顺序、候选和 evidence packet hash 不变；旧协议保持原请求。13/9 个同 SYSTEM 请求组的共同 USER 前缀从 132 增至 15704 字符。公共实际 HTTP、原始来源、历史版本、冷重放 29 项通过。

六组旧/新交替真实 V4.1 Flash 调用共 12 次，使用独立 debug key/usage 库，不发送 QQ。全部返回均通过原始草稿上的完整原解析器；三份原 supported 在两种表示下仍 supported。三份原 unsupported 中，两份两侧仍拒绝；一份旧表示拒绝、新表示通过。

这不是纯粹的措辞差异：该候选把“续读只推进了原定页数中的一部分”等角色行动放进 environment_text，该字段仅拥有外部环境权威；另一分支还依赖服务台登记领取安排。原解析器能验证拒绝坐标/片段，却不能代替模型识别被漏掉的语义主张。新表示漏掉这些边界，因此不能以结构测试绿灯、全文未删除或缓存前缀增加宣称保质优化。

## 费用不能作节省证据

本轮已记录旧表示 6 次约 0.01938 元，新表示 6 次约 0.17111 元。二者输入 tokens 均为 246441；旧表示 cache_hit=245120，新表示=89088。旧请求重用了此前真实试验的完整请求字节，几乎全缓存命中，新格式是第一次请求。

这是已暖旧请求与新表示的污染对照；它不能证明新排序稳定更贵，也不能证明新排序便宜。实际 12 次费用均保留，没有删除不利样本，没有把未知费用算零，也没有用理论前缀长度替代付费结果。由于出现了明确语义漏放，**没有继续付费暖缓存重复验证这项候选**。

生产候选 helper 和新增测试已全部撤回。原有缓存、来源闭包、协议与事实权限保持。

## 同轮本地性能候选也未保留

Context 剖析显示多次两位作者 Experience 读取，尝试对精确 JSON 字节的 binding schema 解析做 128 项有界 LRU；每次仍重查当前事件、参与者、结算、隐私和原角色审计。暖缓存后撤去当前来源/角色审计的拒绝测试及原记忆检查 27 项通过。

同一冻结副本 32 份 binding、每轮 3 遍完整来源检查，交替基线/候选两对为 0.1230/0.1098 秒、0.1134/0.1207 秒；没有稳定收益，已经有不少纯解析缓存，剩余成本主要是当前状态和来源闭包。**该代码与测试增量也已撤回**。不将几十毫秒波动宣传为 <5 秒回复优化。

## 下一步的具体依据

1. 以后涉及 prompt cache 的 A/B，要用相同新鲜度：隔离诊断缓存命名空间，或对两侧明确一致预热，同时保留不同真实 Context/来源的连续变化。完整旧请求重放适合验证行为，不适合直接对比新格式的缓存费用。
2. 优先剖析当前状态地址查找和重复上下文读取；纯 JSON 解析已经不是上述 Experience 读取的主要成本。索引只能加速当前投影的查找，不能缓存一次“权限通过”结果，也不能跳过失效来源/撤回/隐私变化。
