# 生活丰富度：从生成、执行到表达的分层排查

状态：局部机制修复已实现；长期丰富度尚未合格。没有重启生产或发送真实 QQ 消息。

## 已确认的问题

1. **不是单纯检索漏掉了丰富经历。** 对成本实验 `rebase-qualified-day` 的真实账本核查，新增4次世界结算主要是照片尝试结束、宿舍变安静、安静继续、公共设施通知；5份角色经历又反复回到照片及“先前答得太淡”。这些是语义重复，不能用事件ID不同或句子不同判作多样。
2. **环境变化偏弱。** 已结算文本多次强调“没有新的推动或阻碍”，角色没有多少新的具体事情可回应。schema 已允许新人物、地点与持久外部后果，但能力存在不等于模型有效使用。不能用随机主题表、禁止提照片或强制轮换活动替她决定。
3. **规划机会与语义不清。** 日初/活动结束各提供一次规划机会；深夜 `no_op` 会结束该机会，没有安排下次考虑时间。模型其实能用 `start_after_seconds` 安排未来24小时内的私有计划，但此前说明不够清楚。一次“不想现在做”容易变成白天没有计划。此次明确告知时间范围与 no_op 后果；没有新加定时强迫规划，角色自己指定再次考虑时间的能力仍是缺口。
4. **加速测试真的跳过了活动窗口。** 第一轮修改后的真实模型选择在14:01～15:01整理照片；驱动从13:23直接通过下一条聊天跳到15:21，完全跨过窗口。不能把没启动归因于角色不想生活。生产有 `scheduler_wake_snapshot` / `select_clock_wake`，旧固定24时钟驱动没有沿用这套边界。
5. **NPC 到期工作可能被环境生成长期挤占。** Life Ecology 每次先跑普通 World Author；若生成 occurrence，该轮 NPC 就不运行，即使 NPC 已有模型写出的待结算决定/到期计划，或刚收到可观察的新刺激。新增失败用例复现，再修复优先级；不是要求每次都发生社交。
6. **表达与内心重复需要单独验收。** 某轮世界新事件增加，不代表角色不再念叨照片。此轮没有更换 BGE-M3 或降低检索阈值，也没有禁止她提旧事；还没有证据能把当前语义重复定位成向量检索故障。

## 本次修改

- 当前 World Consequence 使用独立的外部世界上下文 profile，保留人物背景、当前执行条件、事实和客观生活结果，不再附带主角的 Affect、关系片段、未完私有线程及主观经历列表。角色自身的完整连续性 profile 和旧 World 作者 profile 不变。这样分开作者职责，不把世界塑造成她当前心事的重复回声；不增加调用。

- 当前 World 作者的近期历史提供简洁的结果视图，去掉把人物背景当近期事件的重复条目，清楚呈现原事件时间、隐私、原始后果、尝试结果与原本存在的角色响应。完整 pinned source 仍保留，旧协议不改写；索引没有新增事实，也不宣称过去环境仍然持续。
- 试验过额外的 World 多样性说明；完整一天仍然单一，**已从最终代码撤回这段追加说明**，不继续靠堆提示词。原始权威边界与新历史索引保留。试验请求与代码快照保留，不改写成当前结果。
- 日初/活动结束的同一次角色调用明确展示未来时间范围和 no_op 的后果；用现有计划及执行链，不增加一个规划模型层。
- 已到期 NPC 工作或尚未处理的新可观察刺激先于普通环境生成；角色当前尝试/完成的精确后果仍优先，原有单轮不重复生成 occurrence 的限制保留。
- 加速驱动新增 `advance_with_runtime_dues`，每一步重读生产调度器公开的 due 集合并使用同一选择函数，先处理途中到期任务，再推进到脚本目标时间；使用生产 owner registry 区分生活与纯 Action 到期，避免每个消息到期都额外启动生活生成。测试步数/费用保护触发必须报告失败，不能当作降频。成本脚本用显式 `--follow-runtime-dues` 开启，旧实验保持可追溯。
- 新增只读 `scripts/audit_life_richness.py`：分开输出已结算世界事实、角色回应、活动状态及规划机会；校验正文哈希；标记跨过未启动计划完整窗口的时钟跳跃。候选、私有响应和聊天文本不升级成已执行事实。它没有用关键词给丰富度打分。
