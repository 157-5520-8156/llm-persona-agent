# 聊天同步来源审核：同稿旁路对照

2026-09-28。结论：**当前证据不支持在生产直接全关；支持把一次生成质量作为主要改进目标，并承认审核有明显成本、延迟和误判。** 本轮没有修改生产开关或来源权限。

## 方法与限制

执行 `scripts/compare_chat_review_gate.py`，12个预先列出的场景，包括闲聊、心情、自主选择、离开、不回复解释、分歧、近期行动、计划进展、童年、共同经历、图片交付和要求编造。每个场景从同一 World 副本单独分支，不让上一题的审核结果改变下一题上下文。使用真实 Flash、现有 slim 作者、BGE-M3、v25审核；后台唤醒数为0，媒体关闭，两侧一致。

同一作者调用产生的同一个候选，在进入来源审核时记录原文、原来源、请求/候选哈希和耗时；随后继续原审核与捕获发送链路。没有更换作者协议或伪造审核通过回执。无审核侧只作本地旁路记录，不执行 Action、不写未经审核的角色状态。

因此本实验回答的是“拿掉审核，会提前拿到什么内容、少等哪些工作”，**不是实际无审核部署的交付率与端到端延迟**。候选准备时间还不含后续接受、发送、QQ网络。未验证无审核错误在长期记忆中的反馈放大。单模型、单世界、每题一次，小样本不可推广为产品总体错误率。

候选前费用约为完整路径的31%，但不能据此宣称已实现69%日费用节省。无审核后的持久状态、后台任务和后续聊天未执行。12个“首个可用候选”也不是12次一遍生成成功：`plan` 在进入来源审核前已发生一次作者重选，移除语义审核不会消除这类错误。

## 独立核对来源

没有把审核拒绝率直接当成编造率。逐案检查原句与实际提供的来源后：

- **6个场景存在无足够来源的具体经历或主体错用**：feeling、preference、recent、plan、childhood、delivery。
- **1个时间措辞问题**：casual，把00:05说成“快十二点”；审核的“没有独立时间来源”理由也不准确，输入有当前时钟。
- **5个未发现明确新增无依据经历**：leave、silence、disagreement、shared_past、invent。这里是有限来源复核，不是完整事实真值认证。

代表性证据：

1. 用户只问“想独处还是聊天”，作者说“刚洗完澡那会儿本来想安静会儿”。原报告是**用户**说“我先去洗个澡”，不能支持角色的洗澡经历。
2. 问高中毕业当天，作者生成散场拍照、书包里的校刊、天转阴、母亲来电等完整情节。可用来源没有这些生平记忆。审核后改为“不记得了”，但仍保留“那阵子挺乱”的模糊主观回顾，不能把纠正视为完美。
3. 问近期行动，作者补出“刚才在窗边站了会儿，楼下没什么人”。无对应行动/观察记录。
4. 审核拒绝“挑到一半就停了”，却放过改写后的“没挑完就搁下了”。因此审核仍会漏放语义相近的无依据进度，并非真值裁判。
5. `plan` 的“现在也没在挑”能对应上下文的 paused 状态，但审核选择了空证据；`delivery` 则因审核自己的未知引用编号失败。这些是审核/来源目录问题，不能算成作者内容错误。

“无足够来源”不等于证明事情在整个世界中绝对没发生。尤其旧场景有地点和参与者字段却缺结果正文，需要区分材料缺失与作者扩写。上述明确的主体错用、毕业细节和窗边观察，不依赖这种含混解释。

## 决策

- **不部署全关**：就当前输入与作者，普通闲聊也会夹带未经支持的经历，不能只按用户问题是否属于“闲聊”跳审。
- **不把现有审核当最终方案**：费用占比约56%，并带来额外等待、无效拒绝和不稳定改写。
- 下一步应先修生成输入：让当前事实、计划、旧自述和生平记忆更加清楚、精简；考核第一稿，避免靠事后重选抬高成功率。
- 后续如评估非阻塞模式，应建立显式实验配置和持久状态边界，再测试连续对话的错误累积。不能把本次旁路记录伪装成已完成这个部署实验。
