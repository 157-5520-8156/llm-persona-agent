状态：代码修复中，`manual_only / qualification_incomplete`。未重启生产，未向真实 QQ 发送测试消息；8792 是明确标注的历史快照预览，8787 仍是原进程。

## 已定位并修改

- **看板事项没有说明**：Thread 投影确实没有正文。新增窄读取器，沿 Thread mutation → AcceptanceRecorded → typed ProposalRecorded → 原角色 ProposalRecorded 回溯 `reason_summary`；核对世界/pin、接受状态、变更哈希、实体版本、审计事件哈希。隐私 withhold 或链条缺失不显示正文。生产副本的两条“还没说完”已读到原说明。不是用近邻日志猜正文。
- **被动生活反应过重**：旧协议在 no_change 时也要求行为倾向、立场、表达策略，且给了明显偏温暖的样例。当前 WorldStimulus v6 增加由角色选择的 brief/elaborated，brief 可把这三个解释置 null；没有按事件类别硬判重要程度。新增内部 Decision 子类型，外部行为提案仍保留原强约束；中心解析、审计和接受路径均支持新类型。历史协议继续使用原字段。
- **回执与未回应缺少可核验来源**：Life .20/.21 加入与原 capability 和 snapshot 绑定的运输回执、未回应时间线读取。回执只证明发送状态，不证明用户看过、理解、在乎或回复；时间线在结算处从同一 pin 重新核对。当前 .21 压缩展示坐标，原始授权材料保留在回执中。
- **人格连续性被技术错误截断**：保留同一情绪 episode 的精确更新，未知坐标不能被本地悄悄改为新情绪或 no_change。brief 的负面情绪经过真实本地接受链存入 Affect；重复处理不重新创作。此为接线证明，不是自然生气概率或长期人格质量证明。
- **错函数名被当作供应商宕机**：运输层保留原参数和精确函数名错误，交还同一角色的一次受约束纠正；不本地改名放行。HTTP→Core→Action→回执→重放测试通过。
- **审核弱化原句**：真实样本曾把“我做过”改成“我曾说过”，再用话语记录放行。新请求要求保持完整命题，不把对方的问题当回答依据，也不把主观的“没做正事”加强成完全无活动。格式与语义拒绝继续分开。提示改进不等于可消灭误判。

## 性能证据与修改

1. 同一录制成功响应的离线 cProfile：本地重复 restore/catalog/receipt 验证累计，整体 10.418 秒 → 3.090 秒；编码引用版本 3.165 秒。是带 profiler 的本地计算对照，不能当真实用户延迟。
2. 完全相同生产投影与新增审计事件：旧 reducer 0.1299 秒 → 0.01875 秒，输出状态相等。避免每次写入把全部历史模型审计重复 Pydantic 解析及交叉匹配，原身份碰撞与物理调用谱系检查仍保留。
3. 编译与不可变证据验证使用最多 8 项的有界缓存，键覆盖完整候选、原来源、协议和原始响应；不同候选/来源/调用不复用判断，冷缓存重放验证继续执行。
4. 当前 slim 作者和 v25 审核采用请求绑定的短引用字典；未知编号、重复键不能越过原权限。部分真实调用输入从作者约 40k→28k tokens、审核约 48k→34k tokens，但不同回复样本不可当严格费用对照。
5. 审核材料实测 103847 字符，其中大量为主观历史的技术坐标。新增 `subjective-proof-elision.1` 仅去掉该类型的证明坐标，保留文字、时间、状态、owner、权限；每个可读字段在原/展示视图逐个比对，受影响就保留原卡。此包缩至 84876 字符（约18%）；原 catalog/source table 留在不可变回执，旧回执按原展示协议恢复。
6. v25 第6次探测的第一轮 8.44 秒中，前台 provider 6.57 秒、context 0.186 秒、coalescing 0.1 秒、acceptance 0.142 秒；部分埋点重叠，不能机械相加。发送/捕获回执自身不到1毫秒。瓶颈仍主要在生成与来源审核，未证明5秒达标。
