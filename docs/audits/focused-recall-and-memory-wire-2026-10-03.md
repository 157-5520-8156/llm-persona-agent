# 首轮检索与记忆传输续修

基线 813255f3。复用固定生产副本，实际 V4.1 与 BGE-M3，CaptureDelivery；未切换生产或发测试 QQ。持续 goal 保持 active：<5 秒、CNY1.5/天与完整发布资格尚未通过。

## 检索归因与修改

先前生日轮得到厨房计时器等材料，却没有生日故事。现有自动检索把当前问题与较长的旧对话/处境混成一个向量。使用冻结的 71 条前史、原 40 题及新增一题，混合上下文源召回约 83.8%，当前问题与情境向量等权组合约 94.6%。37 道有标准来源的题目参与这个均值，其余无标准来源的题目不进入分母。这是来源召回诊断，不是编造率、聊天质量或保留集成绩。单一家庭前文、纯前史索引不代表完整生产索引。

当前代码：自动语义预取在同一 embedding 请求中保留当前原话和情境两通道；先各自归一化再组合，仅改变候选可达性。角色主动 Recall 不改变。新向量版本带 `balanced-attention.1`，原 query/lexical 输入与所有来源、状态、权限、排序边界保留。查询向量与文档向量分开，避免两者文本恰好相同导致覆盖。

实际语义任务约 0.8–1.8 秒，开始于 Context 编译期间。450 ms 首轮 join 经常先释放词法候选；仅入站 Faculty 的 join 上限改为原端口允许的 1 秒，任务已就绪立即返回，不强制停顿或禁止角色再 Recall。

自动情境查询另限 256 字符，按已提供分面分配字符，防止长原话/旧对话吞掉感受、解读与关系。完整原话仍有独立通道，角色上下文及主动 Recall 的 1024 字符能力不删减。长情境 512/256 的原始前缀实验保持该组等权源召回，但不能当作最终分面版本的完整质量资格；最终分面版仍须扩大承接与短句验收。

无模型比较：415 个实际向量归一化原约 150 ms，新冷缓存相同、热缓存约 3.7 ms，逐项完全一致。只缓存纯数值运算，当前文档、来源与权限检查继续执行。

## 后台记忆传输

直接删除 source-token enum 的试验没有改善实测费用，还让模型引用一般注意目录 s12/s13，最终没有采用。保留精确的 m/k 来源枚举和本地引用、引文、遗忘、主体与前身检查。

当前新 reference transport 的 tool v4：模型选择 retain/release 与明确的前身列表。零/一/多个前身分别对应原 retain/revise/merge；release 仍须一个前身。这个机械解码完整覆盖原合法操作，不修改角色选择的前身、摘要、置信度或引文；避免独立 operation 与前身数量矛盾。旧非 reference 和 choice-only 格式保留。

主记忆候选用无损 JSON-pointer 列表格共享嵌套字段名，保留所有值、缺失/null、数组、原文与可复制引用；前身模型继续用原对象展示。实际八条记忆块从 13,972 降至 9,277 字符；整次请求输入降低约一成，不能把这一块的降幅当成整个请求。来源不合法和同批忘掉又引用的失败原因现在带条目位置/具体 token，仍由同一角色模型重选。

最后三批均 reviewed，三次模型调用、24 个候选完成处理，最终三个 active 理解；首次 [] 是角色选择，没有强迫写理解。约 CNY0.0381。动态基线三次约 CNY0.0323，首次已有 98.5% 输入缓存命中，新格式初次较冷；因此**实际费用未证明下降**。不以少一次纠错或更少输出当作保质降本资格。中间 v3/v4 失败和费用保留在私有目录。

## 实际聊天与剩余工作

只增加等权检索仍有生日第二次作者调用，约 9.57 秒。增加入站 join 的另一组三轮为 5.51/6.07/6.28 秒；生日回答转成询问哪一次，不能称为同质量提速。

之后明确事件和对话承接的四轮为 6.91/5.17/6.83/8.88 秒，四轮都捕获成功。后两轮因为 payload_json 字符串漏掉 meaning_of_this/my_state 重选，费用和等待均增加。现有外层 strict schema 只约束字符串，不约束内部必填字段，这是下一项根因。此前完整 native schema 要求大量 nullable 可选字段，约 27k schema 字符；不恢复它。下一步验证只把必要的语义核心变为 native 字段、可选能力继续保持紧凑表示，所有角色选择和权限边界保留。

一次整轮 cProfile 用于归因，约 13 秒，不能计入正常速度比较。它确认重复向量归一化与本地解析成本，也含网络等待和 profiler 扰动。

验证：专项测试、Ruff、diff check；实际记忆和聊天副本冷回放见 cold-replay.json。不是全套发布或每日成本验收。参考 [DeepSeek 缓存机制](https://api-docs.deepseek.com/guides/kv_cache/)与[原始长上下文研究](https://arxiv.org/abs/2307.03172)，本项目指标只来自本地证据，不借用论文指标。
